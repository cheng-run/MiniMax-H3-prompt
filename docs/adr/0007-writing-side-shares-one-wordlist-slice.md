# 电影语言词表接进落笔侧：三条路径共用同一份切片

2026-09-27（issue #32；父票 #30，前置 #31）。

## 背景

ADR 0006 把词表接进了**选词侧**那两个角色（分镜师、摄影指导），并写明落笔侧
（整片提示词工程师与两条写段路径）由后续票接同一读取口。此前**落笔侧一处都没提写作纪律**
——真源自己的「写作纪律」一节就是这么写的，它列的两条（运镜写成自然句、切点整秒）
在提示词层只有两个选词角色各说了半句，没有一处把它当成落笔时的纪律。

## 裁定一：三条落笔路径共用**同一份**切片

`VIDEO_SLICES` 里两个键指向同一个元组：`prompt_engineer`（整片提示词工程师，走角色提示词
加载口）与 `segment_writer`（长视频两条写段路径，走 `segment_prompts` 的请求模板；它们
不是角色，请求是拼出来的字符串）。

**为什么不按路径各取所需**（分段写手不需要风格表、整片不需要七格骨架之类）：三条路径写的
是**同一件事**——最终 H3 正文。一份词表两档写法，就会「一套有、一套没有」；而两条写段路径
里回退式那条**只在规划失败时才走**，它的缺口要等到规划真的失败才现形。本仓已经犯过同型
的错：issue #26 的帧锚定与累积修订都只改了主路径，回退路径的缺陷原样复发。
测试直接钉住两个键相等——将来真要分家，那是个显式动作。

## 裁定二：落笔侧取**全部九节**（因此它的切片就等于整份真源）

选词侧只定「用哪个词」，各取所需即可；落笔侧要把词**落成句子**——景别、机位角度、构图、
光线、风格它都现写，运镜白名单与写作纪律是落笔纪律，每镜六要素与七格骨架则定义了它要写的
那个镜头块必须确立什么、按什么排序。真源自己点名留给落笔侧的两节（「词表：风格」此前无人取、
「写作纪律」明说落笔侧没提）都在其中。

「切片 == 整份」是**当前的事实，不是缺陷**：声明仍然显式（收窄改一处，两个键共用同一元组），
「不声明即拿不到」的机制不变。给落笔侧另抄一份精简词表才是本仓明确放弃过的做法（N 份硬拷贝）。

## 裁定三：切片附在文末、逐字搬运

与 ADR 0006 同一纪律：不改写、不插值；真源里不许出现花括号（有测试钉）。角色提示词按
`load_role_prompt` 的既有形态附在文末，两条写段路径插在各自指令模板的末尾。

## 实测（生成侧那半是掷骰，不是判据）

用 GEN004 的 plan 与 stage_state 瘦身 fixture 驱动**段 2** 的写段请求，改前/改后各 3 份
（`output/issue32-evidence/`，模型 `deepseek-v4-flash`，未钉 seed、**不是受控实验**）：

- **确定性**：改后请求与改前请求逐字节只差**一处插入**——5179 字，内容逐字等于
  `video_slice("segment_writer")`；6 份重跑产物 validator 全零 issue。
- **掷骰**：改后三份一致出现更明确的景别层级（两档 + 过渡）与光线维度；after-3 逐字用上
  真源里三处措辞（`35mm lens with shallow depth of field` / `flat diffused light` /
  `slightly desaturated color palette`），改前三份一次都没出现。**但改前臂本就不是零电影
  语言**——分镜表本身带景别/机位/光线措辞，改前三份都继承了它。故增量是「更明确、更成体系」，
  不是「从无到有」。
- 「词表：构图与焦点」7 份样本命中 **0 次**：切片到了、措辞没被采用。只记录，不主张。

## 考虑过并放弃

- **按路径各取所需**：见裁定一（漂移 + 回退路径最晚暴露）。
- **把词表抄进模板正文 / 另抄一份精简版**：N 份硬拷贝，改动要改 N 处、漏一处不报红。
- **顺手把「切点整秒」收紧成 validator 闸门**：本仓纪律是闸门收紧先有实测样本（ADR 0003
  的对称纪律）。何况真源那句是官方 `base-en.txt:86` 的**切点**规则（`[Shot N]` 的切点整秒），
  段内节拍不受它管——实测 6 份重跑产物的段内节拍仍是 0.1s 精度，没有一份退化成全 `.000`。
- **把真源措辞改得更「贴落笔侧」**（例如把「切点必须是整秒」写死成「所有时间戳」）：切片只做
  搬运；要动措辞就是动真源，得单独议。
- **给分段规划师也加**：票面明列不进——它的 `end_hook` 是锚帧语义校验的可判定对照物，
  掺审美词会让人判不了。

## 后果与边界

- 每段写段请求体量 +5177 字（实测 3760 → 8939 字）；这是三条路径共用的全部代价。
- 到达性由测试钉住（角色加载口 + 两条写段路径的真实请求字符串各一条），**产出质量仍由人读**，
  本票不新增任何校验闸门。
