# 帧级地点校验改为覆盖式：#37 不再要求每张关键帧都含全部地点词

## 背景

2026-09-27，issue #37。主题地点守卫（`tools/theme_guard.py` 的词表 ＋ `generation.validate_fl2va_bundle` 的判决）此前按**词表命中组数**分流：命中 1 组时「逐帧严格」——每一张关键帧的正向提示词**与** `scene_anchor` 都必须含该组的地点词；命中 ≥2 组才切「覆盖式」（锚点或任一帧覆盖即可）。

这个分流的前提是「词表命中几组 = 主题有几个地点」，**不成立**：词表是从**整条**主题里做子串匹配抽出来的，而一张关键帧只画主题里的**一个**时刻。实测该次运行的主题是「云上天宫的女子 → 人间高楼室内练琵琶的女孩」，`室内` 由**后半句**命中、只有 1 组，而 I2VA / FL2VA 的**首帧画的是天宫**——画面里写不出「室内」。

后果不是「模型不听话」，而是**结构上不可满足**：模型两轮回复（原始回复已落盘）首帧实文都是「云层之上的天宫高台临空围栏处……」，一个室内词都没有；它甚至把「室内」写进了自己**顺手多生成的 `last` 帧**里，而 I2VA 只校验 `first`。阶段 1 跑满 **4 分 37 秒**、十几次 LLM 调用后整条抛错。默认变体 FL2VA 同样中招（首帧天宫 ＋ 尾帧室内 → 首帧那一关过不去）。

## 裁定一：帧级地点校验一律覆盖式

每组地点词被 `scene_anchor` **或任一帧**覆盖即可，不再按组数分流。锚点是**全片**共享的环境锚点（改写重试里模型自己就把锚点写成「两个明确地点对位：①天宫……②人间高楼室内……」），帧才是具体画面；覆盖式正对上这个分工。判据代码（`validate_fl2va_bundle`）从「帧循环里分支」移到「帧循环之后按组判」。

「任一帧」指**该变体自己的帧**（`variant_frame_names`）：I2VA 下模型多返回的 `last` 不计入——它不是这个变体的产物（见「后果与边界」）。

## 裁定二：把词表点名给模型（同票补的接线）

帧节点从前**从不把词表告诉模型**——主请求、转 JSON 重试、改写重试三条都只有一句「主题地点是硬约束」，而校验器做的是**字面子串**判定，所以改写重试那句「使其通过主题地点校验」在信息上**不可赢**。整片路径早有这条接线（`pipeline._theme_repair_injection` → `theme_requirements_text`），帧路径缺的正是它。

现在三条请求共用同一份【场景词】块（`nodes._scene_terms_block`，**恒为非空**：无命中时说明「本片无地点硬约束」，否则角色提示词的指针会悬空——同 #33 的【画布】块）。`theme_requirements_text` 新增 `target` 关键字参数（默认「正文」，整片路径逐字不变）以指明词该落在哪儿。角色提示词里那条硬编码「如果主题明确说『酒馆』或『室内』，必须直接写」改成指向该块并声明落点。

## 考虑过并放弃

- **只补接线、判据不动**：模型知道词表后只能把「室内」塞进天宫首帧的生图提示词——守卫不再误报，但产物开始**撒谎**，误报换成了画面污染。校验要求的位置必须与画面的实际情况一致。
- **两条降级为 warning、判据一字不动**（#11/#22 的先例）：判据本身是有牙齿的（首帧真画室内、锚点只写天宫时，旧口径连**锚点**都卡——那半是过硬不是过软）。误报出在「每帧」这个**位置**，位置修对了不必降级。
- **按地点在主题里的位置把词分派到对应帧**（前半句的词给首帧、后半句给尾帧）：方向看着最贴切，但「哪一帧画哪个地点」没有可靠的确定性判据，等于把启发式塞进一条 error 级闸门。
- **每帧至少覆盖「某一组」词**（不要求覆盖全部组）：看着能在不放宽「不许两帧换地点」的前提下修掉本案，但它会把天宫那一帧重新判死——天宫不在词表里，那一帧**一个**词表词都没有。

## 后果与边界

- **「帧间换地点」这条不再有兜底——实测如此，不是想定。** 复审当天实跑「首帧酒馆 ＋ 尾帧『among tall trees in a forest』」：本判据放行，整片正文守卫（`theme_fidelity_issues`）也放行（它只管「该地点在整片正文里出现过」，而这段话在开场就出现过）。`_CONFLICTING_OUTDOOR_TERMS` 只认 `forest clearing` / `open field` / `wilderness` / `outdoor camp` 四个词组，**不含光秃的 `forest`**。旧口径在这一例上确实拦得住，代价是本案那种结构性误报——两害相权取了覆盖式，但**别把「还有别处兜着」当成事实**。
- **重议条件**：出现真实坏例——有人交出一份「首帧在 A 地点、尾帧无理由换到 B 地点」而本判据放行、且另两道也没拦下的产物。届时按该例的形态定判据（或补一条真能判「两帧同空间」的检查），而不是凭想定收紧。
- **已知未修、另开票** → **已由 #38 修（2026-09-27，`docs/adr/0010`）**：I2VA 运行里模型多返回的 `last` 帧（L2VA 则多一张 `first`）原先没有被任何地方剥离（`fl2va_bundle_from_dict` 原样保留，`render_generation` 又无条件渲染 `last-frame-prompt.md`）。现在在解析处按变体剥离并在帧节点告警。它同时意味着「模型想靠补一张 `last` 来满足地点词」这条路在本判据下不计分（`variant_frame_names` 只认该变体自己的帧）——**这一点没有变**，剥离只是让产出口径跟上判据口径。
