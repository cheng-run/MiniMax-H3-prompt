# 路线决定产物集，不复制管线图

2026-10-23 回滚之后，仍有一个反复被提出的选项：既然首尾帧路线不该产出「资产图提示词」、多参路线必须有它们，为什么不**复制一份管线图**（base 图 / ref 图），让每条路线各走一张？本记录写下否决「两套图」的三条证据，以及取而代之的决定：**路线（`Brief.mode`）决定产物集**，两条路线继续共用同一张管线图、同一套设计节点。父票为 issue #77。

## 决定

1. 产物集的**唯一判据**是 `Brief.mode`（`base` / `ref`），判定点收在**产物出口**（结果构造、渲染、参考素材登记、旧会话读回），不散落在各调用点。
2. 管线图**不复制、不冻结**：两条路线共用 `_STAGE1_CHAIN` / `_PARALLEL_GROUPS`；资产图提示词节点在非多参路线只做早退（返回空更新），不改拓扑。
3. 「是不是 FL2VA」「有没有首尾帧 bundle」**不能**代替路线判据——多参的变体恰是 T2VA 且没有 bundle，这两条支路正好也是多参的产物出口。

术语边界见 `CONTEXT.md` 的**设计正文**、**资产图提示词**、**素材库图**。

## 被否决的方案：两套管线图

**证据一：两分支的图拓扑零差异。** 回滚点 `43a2c06`（main）与多参线存档 `2714503`（`archive/ref2va-full`）的图定义——`_STAGE1_CHAIN`、`_STAGE2_CHAIN`、`_PARALLEL_GROUPS` 及其注释——**逐字节相同**（`sed -n '/^_STAGE1_CHAIN/,/^_FOLDED_NODES/p'` 两侧 sha256 均为 `82192a43…`）。两条分支的差异全在节点内部行为、状态键与产物出口，不在节点与边的集合。拓扑既然从未分叉，复制图就等于人为制造一份当前不存在的差异。

**证据二：回滚点本身已是多模式图，没有纯首尾帧图可冻结。** `43a2c06` 的 `Brief.mode` 已是 `base | ref` 双值，`build_pipeline_graph` 已按 `brief.mode` 装配 agent；阶段 1 链里也早已挂着三个资产图提示词节点（issue #36 引入，`parallel_image_prompts`）。要冻出一张「纯首尾帧的图」，得回到资产节点进链之前——那是比回滚点更早的另一个版本。冻结 `43a2c06` 冻下来的仍然是一张多模式图，问题原样留着。

**证据三：冻结等于包级复制，并留下共享依赖的泄漏路径。** 节点不是自足的：`graph/nodes.py` 依赖 `agents`、`generation`、`segment_prompts`、`user_revisions` 等共享模块，图定义还依赖 `PipelineState`。冻结图只能连包一起冻结；只要共享模块仍被两条路线引用，多参路径的行为就能从这些依赖里漏回首尾帧路线——这次事故正是这个形态（资产节点进了共享链、出站口落在共用函数上且没有路线守卫）。共享图 ＋ 单一产物出口才能把「哪条路线产出什么」收在一处，可复审、可做变异检验。

## 后果

- 首尾帧阶段 1 的模型调用回到资产节点进链之前的水平；多参路线行为**逐字节不变**（父票的验收口径）。
- 资产图提示词节点在非多参路线会空转一次：不发请求、不花钱、不产生进度行。这是保留共享拓扑的**已知代价**。
- 新增产物出口时**必须**走同一个路线入口；绕过它就是在重新长出一条泄漏路径。
- 路线判据只有一处来源，删掉任一守卫都应让测试变红——守卫要能被变异检验咬住，不能只是摆设。
