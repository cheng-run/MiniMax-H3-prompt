# 长片分段陪跑

> **状态（2026-11-12 复核）**：已接受；随 D6（#243）落地，三条裁定在 #244–#251 实现，真实验收由 D6-AC14 收口。

D4 把 `base` 的短视频闭环做通了，但 `duration` 被硬限在 4–10 秒。D6 把同一条链延伸到 60 秒：阶段 2 之后多出一条「分段规划 → 逐段写词 → 逐段回交视频 → 校验 → 拼接」的段循环。系统仍然**不生成视频**——每段视频由用户拿提示词去 ComfyUI 跑完再传回工作台，这是既有内核的边界（`main.py`「项目不会自动运行 ComfyUI」），D6 沿用。这里记三件会被后来者反复追问的裁定。

## 决定

1. **长片在阶段 2 之后追加段循环，不替代阶段 2。** 阶段 2 照旧产出完整提示词与中文摘要；阶段 2 成功时若时长 > 10 秒，收尾不落 `completed`，而是在**同一次落盘**里接上分段规划任务（`api/jobs.py::_finish_stage2`）。之后每一步由「已落盘的段状态」决定：当前段是第一条非 `passed` 的段，`pending` 跑写词、`validating` 跑校验，全部通过才拼接。
   - 为什么不是「长片跳过阶段 2」：阶段 2 的完整提示词是逐段写词的共同上下文（风格、人物、运镜都从那里来）；跳过它等于让每段各自重写一遍全局约束。
   - 为什么分段步骤不记账：15 段 × 2 条会把 `JOB_HISTORY_LIMIT` 挤爆，而段状态本来就是步骤判据；失败重试因此不需要另记「跑到了哪」。
   - 写词必须**逐段增量**：第 N+1 段要拿第 N 段视频的尾帧当首帧锚（`wizard.py` 的同一做法），不能一次写完所有段。

2. **段视频做成第三个人工待办 `segment_video`，不复用 `frame_submission`。** 每段一个待办，载荷带段号（`segment_index`）；resolve 只收 `video_asset_id`（必须是本会话已上传的 mp4 素材）。kind 与载荷强校验：错配、段号不符、外会话素材、非 mp4、技术档不合格一律 422 `segment_video_invalid`，会话留 `awaiting_human` 可重传。
   - 两个待办的生命周期完全不同：帧提交一次收两张图（首/尾），段视频收 N 次、每次一段、按段推进；复用一个 kind 会让「当前该交哪一段」只能靠载荷猜。
   - 语义闸门拒绝时**不落 `passed`**、重建同一段待办并发既有 `action_item.created`——用户的素材不合格不是系统故障，不记 `failed`（与 CLI `wizard.py` 的同一口径）；技术异常才落 `failed`，重试重跑同一次校验、不要求重交素材。
   - 事件类型仍是**十种闭合**：段待办复用 `action_item.created` / `action_item.resolved`，不新增事件。

3. **段视频有两道闸门：同步技术档 + 异步语义读图，且不提供 opt-out。** 同步闸门在 resolve 时判帧数档/时长/尺寸（复用 `tools/preflight.check_segment_video`），异步闸门在 job 内剥尾帧、视觉模型读图、与本段 `end_hook` 对照。两道都不能关、不能批量放行；被拒的段不落状态，否则恢复会跳过它。7–10 秒档不在 H3 实测帧数表内，技术档只报 `warning`（`segment_video_duration_unknown_tier`）——测不出事实就不许阻断，攒到样本再固化。

## 考虑过的备选

- **把段视频并进 `frame_submission`**：一次交 N 段视频看起来省待办，但「第几段」只能塞进载荷，错配校验会变成一团 if；也表达不了「交一段、写一段、再交下一段」的节奏。
- **一次把 N 段提示词全写完再收视频**：省去等待，但第 N+1 段没有第 N 段尾帧锚，段与段之间的连续性只能靠模型猜——这正是分段陪跑要避免的。
- **段状态只放 job 记录、不落快照**：job 历史被截断后恢复就不知道跑到第几段；快照是恢复的唯一事实源，每次段通过立刻落盘。
- **允许用户跳过语义闸门**：成片段落接不上时无从解释；与 ADR 0002 同向，不提供强制放行。
- **读 CLI 的段产出账 `segments/shot-ledger.jsonl`**：两套风格互不续接（#215 裁定）；工作台只认自己的段状态，CLI 账本不读也不写。

## 后果

- 会话状态仍是既有七态，新增的只是阶段标签 `segmenting`；「等用户交视频」就是 `awaiting_human`。
- 段列表进会话详情（`SessionDetail.segments`），段提示词是登记表里的模式产物 `segments/shot-NN.md`（kind `segment_prompt`）；规划结果只读，不要求确认。
- 最后一段通过后**自动拼接** `final.mp4` 并转 `completed`（没有交付确认闸门，同 ADR 0034）；缺段则 `failed` 并把 `assemble_film` 点名的段号原样带出，补齐后可续拼、已通过段不重收。
- 重启恢复只读 `session-state.json`：已通过段不重跑、不重收视频，`validating` 重跑校验，`pending` 重起写词。
- 真实验收由 `scripts/accept_d6.py` 手动跑（真实 LLM + 用户 ComfyUI 生成的真视频，报告落 `output/accept-d6/`，不进 CI）；CI 用桩管线覆盖三段闭环与拼接。
