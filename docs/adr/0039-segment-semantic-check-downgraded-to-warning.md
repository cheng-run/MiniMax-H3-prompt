# 段尾语义检查降级为提示

> **状态（2026-11-14 复核）**：已接受；随 #269 / #270 落地，取代 ADR 0036 第 3 点「语义闸门无 opt-out」与第 2 点「被拒不落 `passed`」的表述。

D6 的真实验收（#243 / #251，2026-11-14 FL2V 18 秒）暴露了一个结构性卡死：第 1 段视频画面与计划完全一致（右手在胸前、包在左肩），但读图模型把人物自身左右说反，判「尾帧未达到本段末态」；末态里还要求「双脚收成一前一后」，而那一帧是中景、脚根本没入画，视觉模型无论如何核不了。结果是换成什么视频都过不了，第 2、3 段和拼接全做不了。这里记四条被推翻的判断与新的口径。

## 决定

1. **计划意图不是成片判据。** `end_hook`（段尾钩子）是规划期写下的**意图**，不是成片的验收标准。计划与成片有偏差是质量问题，应该让人看见并选择，不该结构性地阻断流程。`end_hook` 的原用途不变：规划段边界 + 注入本段写词请求作为收尾约束。
   - 为什么不能继续当闸门：判据是一次不可靠的单帧读图。读图模型在「人物自身左右」「具体哪只手」「视线朝向」和「未入画部位」上系统性地说不准，把它的结论当硬闸门等于让不可靠的观察者决定整条长片能不能继续。
   - 判据提示词因此改「关键事实冲突」口径：只核场景/地点、主体是否在场、本段大动作是否发生、关键道具落在哪；其余细节与未入画部位不参与判定；描述没覆盖某条要求不算不符。

2. **实际尾帧是段间衔接的唯一事实源。** 真正保证段与段接得上的是剥出来的**实际尾帧图片**（下一段就拿它当 Picture 1 起跑），不是文字里的末态声明。文字锚（`bridge_frame_descriptions`）只作为写段请求的补充说明，缺了不阻断——图还在。
   - 剥尾帧失败仍是系统故障（下一段没有首帧锚），维持 `failed` 可重试；但那是「系统没做成」，不是「用户素材不合格」。

3. **技术档仍是硬闸门。** mp4 容器、段号、本会话素材、时长、尺寸、帧数这些确定性判据不变：不合格仍在 resolve 时 422 `segment_video_invalid`，会话留 `awaiting_human` 可重交。可确定的坏素材不该进拼接；只有「算不出来的语义」才降级。

4. **无 opt-out 改为无阻断。** ADR 0036 第 3 点把语义闸门做成「不能关、不能批量放行」；新裁定是**没有闸门可关**：语义检查只产出提示（`semantic_warning`），段直接 `passed` 并进入下一段。读图或判据不可用时段照常通过，附「语义检查未完成：原因」。这样既不需要给用户一个绕过闸门的开关，也不会出现「服务波动 → 白等」。
   - 模型调用入口因此只返回「差异说明」字符串（空串＝无提示），**不再返回布尔**：调用方没有任何分支能因它把段判为不合格（#270 口径）。

## 考虑过的备选

- **给语义闸门加 opt-out 开关**：等于承认闸门不可靠却还留着它；用户要在每个被拒的段上先学会绕过，体验与直接给提示没有区别，还多一个状态位。
- **放宽判据提示词、保留闸门**：治标——读图模型仍会在某一帧上说不准，只是概率低一点；一旦说错，长片照样卡死。
- **只在读图置信度低时放行**：读图服务不返回可靠置信度，判据本身也没有可校准的刻度；引入一个假置信度只会把问题藏起来。

## 后果

- 段记录字段 `rejection_reason` 更名 `semantic_warning`，进会话快照与 `SegmentOut`；交新视频、重开段、重新规划时清空，段通过后保留，段卡片上仍可见，由人决定要不要自己重生成这一段。
- 收尾不再重建 `segment_video` 待办、不发新的 `action_item.created`；通过分支照常推进下一段写词，末段接拼接。
- 事件类型仍是十种闭合集合，不新增错误码、端点或事件类型。
- 旧快照里的 `rejection_reason` 载入时读成 `semantic_warning`，不写回旧键；已有会话不会因为字段更名打不开。
- CLI（`ui/wizard.py` 的人判 + 五档出路）与导演台 `judge_video_evidence` 判据不受影响——本裁定只改工作台的语义检查去向。
