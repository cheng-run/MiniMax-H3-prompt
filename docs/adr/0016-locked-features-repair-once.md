# 锁死清单违约：先修一次，修不好仍停

issue #53 把「条目必须是 `positive_prompt` 的原文片段」钉成节点侧闸门，并裁定「模型交不出就整条阶段 1 停住报错（宁可停，不要静默回落到不收窄）」。2026-10-21 的一次真实运行撞上了它：场景资产「同一公寓卧室床头」交的条目是「同一间当代中国普通都市公寓卧室」——把设计资料里的「当代中国普通都市」和场景标题缝起来的**转述**，不是它自己正文里的原句。阶段 1 停在生图提示词节点，此前 11 次调用的结果全部作废。

不变式本身是对的：条目转述时，读图校对的 `_locked_hit` 是双向字面子串（`asset_proofread.py:145-154`），必然不命中，于是每条偏差都被静默归入 `exempted`、偏差清单清空、报告仍算「干净」（`asset_proofread.py:201-206`）——正是闸门要防的静默失效。问题在**违约后的处置**与**触发概率**不匹配：场景／道具的「身份特征」在设计资料里本就是抽象空间描述，模型从资料概括出条目、而不是从自己刚写的正文里摘，是这类资产的常见失败形态；一次违约就让整条阶段 1 停住、重跑还要重付已成功的那几路调用，代价远高于再问一次。

**决定**：清单层违约时先做**一次**补丁式修复重试；仍不合规才停。

- **补丁式**：修复请求只要 `[{"name": …, "locked_features": [...]}]`，按 `name` 合并回原条目。正文**按构造冻结**——不是靠提示词里叮嘱一句；否则模型可以靠改写正文来「满足」原文片段不变式，产物已经变了却审不出来。
- **只修清单层**：缺席／非数组／空表／非原文四类。结构性坏法（顶层不是数组、项不是对象、`name` 缺失、`positive_prompt` 为空）不进修复——补丁无处落，重交只会再撞同一道闸。
- **修复只一次**：与仓里既有的同形先例一致（关键帧 bundle 外层在任意 `ValueError` 时回灌重写一次，`graph/nodes.py:410-441`）。修复调用走 `run_agent`，成本自动记账。
- **修不好仍停**：错误信息带「已修复尝试 1 次」与逐条明细，便于人工分清是模型固执还是可修。
- **全路线统一**：base／帧路线不消费清单，但清单也是产物（各路线都渲染 `### 锁死清单` 段），不按 `brief.mode` 分叉出两套口径。

## 考虑过的备选

- **维持一次违约即停**：守住原裁定，但这次实测的代价（停在中段、重跑重付）与场景资产的常见失败形态不匹配，且无法区分「模型固执」与「顺手概括了一下」。
- **放宽校验、允许转述**：下游会把整条偏差静默降级成「理想描述出入」，偏差清单悄悄清空、记录照写 DONE——否决。
- **降级为空清单／不收窄**：等于回到 #53 之前「8 张图 39 条偏差、38 条按图改文案」的人裁灾难——否决。
- **修复到过为止（多轮）**：模型持续违约时应当停，多轮只把「停」推迟，成本不可控。
- **进向导让人补清单**：把「那条到底想锁什么」交回人是对的，但会新增一条交互路径与一批测试；先靠修复与错误明细观察触发率，有数据再决定是否升级到交互。

## 后果

- 违约时多一次 LLM 调用（仅在违约时发生），进成本表。
- 修复失败的错误仍是 `ValueError`，但外层多了「修复 1 次后仍不合规」的包装；想看原始病因（例如结构坏）时注意剥这一层。
- 角色提示词同步追加了一条场景／道具的示例（`prompts/image_prompt_engineer.md` 末尾），降低触发率；该文件被 docs 按行号引用，新规则只能追加、不许中间插行。
