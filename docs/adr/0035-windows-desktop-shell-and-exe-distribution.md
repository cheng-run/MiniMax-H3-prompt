# Windows 桌面外壳与 EXE 分发

> **状态（2026-11-12 复核）**：已接受；随 D5（#235）落地，四处裁定在 #236–#241 实现，验收由 D5-AC 收口。

D2–D4 把工作台做成了「浏览器 + 本地 Headless Service」（ADR 0031），但目标用户拿到手的必须是一个**双击就能用的 Windows 程序**，而不是「先装 Python、再开终端」。D5 只加一层很薄的外壳与一条打包流水线，产品逻辑一行不改。这里记四件会被后来者反复追问的裁定，以及一条实测 spike 门。

## 决定

1. **外壳用 pywebview（系统 WebView2），不用 Tauri / Electron。** 前端本来就是浏览器应用，本地服务已经是唯一的业务入口，外壳只做「等就绪 → 建窗 → 关窗退出」三件事；pywebview 让 Python 进程直接持有窗口，不需要第二套运行时。Windows 11 预装 WebView2 Evergreen，等于零安装成本的浏览器引擎；pywebview 的官方冻结文档又正是 PyInstaller，打包路径没有额外赌注。外壳**不传 `js_api`、不建原生桥**：`GET /api/v1/auth/token` 不设防且同响应下发 `wb_session` Cookie，窗口地址与系统浏览器完全相同、不带令牌。

2. **交付形态是 onedir 便携目录 + zip，不做安装器，也不做 onefile。** 解压即用、删除即卸载，不需要管理员权限、注册表与卸载项，也不需要为安装器付代码签名与更新通道的成本。目录内是稳定的运行时（`MiniMax-H3-prompt.exe` + `_internal/`）与可写数据 `data/`，排障时用户能直接把整个目录拷走。构建输出目录叫 `build-exe/` 而不是 `dist/`——Vite 的前端产物就在 `frontend/dist`，同名会互相覆盖。**不签名**：首次运行会被 SmartScreen 拦一次，`README.txt` 写明「更多信息 → 仍要运行」。

3. **路径一刀切：只读资源走 EXE 内部 `_MEIPASS`，可写数据走 EXE 同级 `data/`。** 冻结后包安装位置变成临时解包目录，原先散在各处的 `Path(__file__).parents[N]` 全部失效，因此路径推导收口到一个解析模块：只读资源（前端 `dist`、内置配置模板、`prompts` / `knowledge`）冻结态在 `sys._MEIPASS`、开发态在仓库根；可写数据（`config` / `sessions` / `output` / `logs`）冻结态在 EXE 同级 `data/`、开发态仍是仓库根。**数据根可被 `--data-root` 覆盖**（验收与调试用），且必须在任何业务 import 之前生效——配置是 import 期单例，迟到的覆盖不会回头改已算好的路径。外部路径（素材库、ComfyUI 输出根）仍是外部依赖，不打包，缺失时给可操作提示。

4. **不做设置页，密钥继续文件化**（`%APPDATA%\MiniMax-H3-prompt\.env`）。非敏感配置住 `data/config/*.yaml`，首次启动从内置模板只补缺、不覆盖用户改动；改配置需重启生效，界面文案与之一致，不承诺热重载。**密钥刻意不落 `data/`**：作品目录会被用户整个拷走或分享，密钥跟着走等于随作品泄露；密钥也不受 `--data-root` 影响——数据根挪的是作品与配置，密钥属于这台机器的人。缺 key 时概览页给「文件绝对路径 + 格式示例 + 复制路径按钮」的可操作提示，而不是配置向导——浏览器与 WebView 都不能直接打开本地目录，为此新增一个动作端点不值得，让用户把路径复制走即可。日志与错误响应在写入前就完成脱敏，不靠事后过滤。

5. **spike 门：pywebview 未声明支持 Python 3.14，这条依赖要按实测而不是 classifier 走。** 本项目跑 Python 3.14，而 pywebview 6.2.1 的 `Requires-Python` 只声明到 3.13；实测能建出 WebView2 窗口的直接原因是 pythonnet 3.2.1 声明 `<3.16`。2026-11-12 的 spike 三条全部成立（源码形态与冻结形态都建出窗口、onedir EXE 在无本机 Python 的环境里可跑、Playwright 能经 CDP 连上真实窗口），结论与复现步骤在 `docs/research/2026-11-12-exe-packaging-spike.md`。因此继续按「桌面外壳」推进，**不降级**成「无外壳 + 系统浏览器」。升级 pywebview / pythonnet 必须重跑该 spike；若将来失效，降级路径就是回到「本地服务 + 系统浏览器」，产品能力不减，只失去双击体验。同一 spike 还钉死一条实现约束：要开 CDP 调试端口必须设 `webview.settings['REMOTE_DEBUGGING_PORT']`，环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 那条路不通——pywebview 自己给 `AdditionalBrowserArguments` 赋值，把环境变量读到的值覆盖掉了。

## 考虑过的备选

- **Tauri**：产物小、原生感强，但要引入 Rust 工具链与它自己的一套打包/升级流程，而业务进程仍然是 Python；换来的只是「少 30 MB」。
- **Electron**：自带 Chromium 意味着 100 MB 级的重复引擎，还要 Node 工具链、独立的签名与更新通道；本机已有 WebView2，没有理由再带一个浏览器。
- **onefile**：单文件好看，但每次启动都要把整包解到临时目录，启动变慢、杀软扫描变重、临时目录堆积；`_MEIPASS` 每次都是新路径，排障时连「它在哪」都要问进程。
- **安装器（Inno Setup / MSI）**：要签名、要管理员权限、要维护卸载与升级；这是个人便携工具，压缩包比安装器更符合「拿到就能用」。
- **设置页 / 配置向导**：需要持久化接口、校验、密钥输入与遮罩，等于在文件配置之上再造一层；配置本来就该由用户用编辑器改，缺的是「文件在哪」这类提示，不是表单。
- **把 `.env` 放进 `data/`**：省一处路径，但作品目录一旦被拷贝，密钥就跟着走了。
- **留一个「原生桥」给窗口直调业务**：多一套凭据通道与 IPC 契约，而 HTTP 端点已经覆盖了全部能力。
- **用环境变量开 WebView2 调试端口**：实测不生效（见决定 5），依赖它会让自动化验收出现「窗口开了但 CDP 连不上」的假阴性。

## 后果

- 打包流水线必须显式收齐两类内容：只读资源（前端 `dist`、内置配置模板、提示词与知识库、`ffmpeg` 二进制）与运行时元数据。漏了前者是**空白窗口**，漏了后者是版本号读不到——两者都不报错，只静默少东西。
- 冻结态与开发态**故意保留两套数据根口径**：冻结态会话在 `data/sessions`，开发态是仓库的 `output/sessions`。统一它们会动用户机器上已有的会话目录，属于「看着整洁、实际迁移」。
- 根路径推导只许有一处：新增任何「项目根在哪」的推导都要走解析模块，由结构守卫咬住第二处。
- 日志落点是契约（`data/logs/app-YYYYMMDD.log`，按日滚动、保留天数进配置），诊断包按固定清单组装，且不得包含密钥与媒体。
- WebView2 是运行前提：启动前检测，缺失或过旧时拦下并给安装指引，版本读不懂时按「不可判定」放行并记警告（宁可警告不硬阻断）。
- 未签名与「不装 Python 的全新机器」这两条只能靠实机验收，不因为构建成功就算通过；验收报告要写明机器形态。
- 配置改动需重启，不能把「改完没生效」当成 bug 去加热重载。
