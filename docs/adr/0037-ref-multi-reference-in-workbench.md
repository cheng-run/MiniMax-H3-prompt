# ref 多参进工作台

> **状态（2026-11-13 复核）**：已接受；随 D7（#252）落地，裁定在 #254–#259 实现，真实验收（#260）按 2026-11-13 用户裁定延后到 Program Overview 全部子 spec 完成之后。

D7 把 CLI 里已经跑通的 `ref` 多参路线搬进工作台：会话、任务、人工待办、产物四类边界与 `base` 共用，页面不长出第二套状态机。系统仍然**不生成视频**——段视频由用户回交、系统校验、系统拼接，与 D6（ADR 0036）同构。这里记三件会被后来者反复追问的裁定，以及两处在实现时由用户当场裁掉的 spec 自相矛盾。

## 决定

1. **素材循环是逐件串行的人工待办，不是批量收齐。** 阶段 1 通过后不直接进阶段 2：先按台账编号升序逐件写资产图词（`assets/picture-NN.md`，一件一份），挂 `asset_image` 待办，用户拿词去生成、把图传回，系统读图校对，通过才推下一件。
   - 为什么串行：校对要用「前几件已定稿的样子」当一致性参照；先出后面几件的词，等于在没看过前面的图的情况下写词，与素材循环存在的理由相反。
   - 为什么一件一份而不是合并：词与「这件词的图」天然成对；合并后「第 3 件当时给的是哪一版词」就脱钩。改词重出覆盖同一份文件，历史靠台账轮次与待办决议表达。
   - 两个 job（出词、校对）都记 `kind = asset_loop`，中间是**持久化**的人工等待，不是阻塞线程；进程重启后待办仍在，恢复只读台账推当前件（最大连续通过编号 + 1），不靠 job 历史。
   - 阶段标签新增 `asset_loop`；**注入卡不单独占 step**，它是进阶段 2 前的最后一件产物。会话状态仍是既有七态。

2. **素材校对没有放行开关，降级只能靠改词。** 校对不通过时在同一件号重开待办并附差异清单（「你的词说 A，图里是 B」），系统把差异作为反馈重写词、覆盖同一份产物。
   - 为什么不给「就这样吧」：素材图是后续所有段视频的参考正本，接错一次会在整片里放大；与 ADR 0002 同向，不提供强制放行。
   - 工作台没有编辑产物正文的入口，所以「改词」的落法是系统按差异重写，而不是让用户手改文件——两处都做会让「这一版词是谁改的」说不清。

3. **段内参考素材子集由系统算、界面只读；换段只换视频，不改子集。** 子集从分镜表的 `<Subject>/<Picture>` 标签算种子 → 定义闭包 → 撤一致性锚 → 从 1 连续重编号（复用 `segment_refs` 的既有算法），结果只读回显在段上。
   - 不做「逐段手填参考素材」：那等于把闭包算法搬到前端，两套口径必然分家。
   - ref 已通过段允许「换一段」（`passed → waiting_video`，重过双闸门），但只换视频；base 不开这条边——中间段换掉会断掉第 N+1 段的帧锚（ADR 0023），属结构性禁止而非产品选择。

4. **带语义名上传 = 登记参考素材；不带 = 普通素材。** 同一个上传端点也收素材图与段视频回交，那时会话早已离开 `created`。所以「起跑后不许再增删素材」只锁**台账登记**（带 `name`），不锁普通上传；容量 9/3/3/12 也只数台账条目。
   - 否则素材循环与段循环的回交通道会被起跑锁一起锁死，而它们正是 D7 的主流程。

5. **ref 一律进段循环，`≤ MAX_SEG_S` 是「1 段」直出形态。** base 的长片门槛（> 10 秒）与分段形态一字不动；ref 的分段门槛是路线属性（`is_single_segment_route`，从 `MAX_SEG_S` 派生、不写字面 15）。10–15 秒的 ref 页面显示「1 段」，不是「长片但只有一段」。
   - ref 段不建桥接帧、不剥尾帧判 `end_hook`（ADR 0011：多参分段不套单图开场锚）；段尾判据走段内注记的 `validate_ref_segment`，提交时不再读图。
   - 段词落 `segments/segment-NN.md`，与 base 的 `segments/shot-NN.md` **并列**两条产物模式，不是改名。

6. **两处 spec 自相矛盾由用户当场裁定，各新增一个端点**（覆盖 spec §12「不新增端点」的字面）：
   - `DELETE /sessions/{id}/assets/{asset_id:path}`：只撤销**台账登记**，只允许 ref、循环开始前；台账外的普通素材 → 404 `asset_not_found`。
   - `POST /sessions/{id}/segments/{index}/reopen`：ref 已通过段换一段；base → 409 `segment_resubmit_unsupported`。
   - 理由：§4.2 要求「循环开始前可删素材」、§5.5 要求「ref 已通过段能换一段」，而这两个动作无法用既有端点表达；让功能残缺比多一个受契约与 drift 检查覆盖的端点更贵。

## 考虑过的备选

- **一次收齐所有素材再进阶段 2**：交互更短，但校对失去「前几件已定稿」的参照，且第一件不通过时后面几件的词全部作废。
- **素材校对给一个人工放行键**：用户可能一时看不出差异而想先推进；但接错的素材是整片参考正本，放行之后没有任何环节能补，与 ADR 0002 同向。
- **段内子集由用户逐段手填**：把闭包算法搬到前端，判据两处口径；改一处漏一处时界面显示与实喂素材会静默分家。
- **新增事件类型（如 `asset.updated`）**：十种闭集是本仓的稳定契约；素材循环的进度由台账与 `action_item.created` 的载荷（件号、差异）表达即可。
- **让工作台读 CLI 的 `asset-ledger.json`**：两套路径语义互不续接（#215 裁定）；工作台的素材台账住会话状态，CLI 的账本不读也不写。
- **把起跑锁做成「状态离开 created 就锁全部上传」**：实现简单，但会把素材图与段视频的回交一起锁死——这正是本裁定 4 要避免的。

## 后果

- 会话状态仍是既有七态；新增的阶段标签只有 `asset_loop`，SSE、状态徽章与列表页不长新分支。
- 产物登记表新增：`assets/picture-NN.md`（`asset_prompt`）、`segments/segment-NN.md`（`segment_prompt`）、`injection-card.md`（`injection_card`）、`segments/injection-card-NN.md`（`segment_injection_card`）、`segments/order-card.md`（`concat_order_card`）、`segments/ref-shot-table.md`（`ref_shot_table`）。`segments/plan.json` 与素材台账不入产物：前者由段快照表达，后者住会话状态。
- 注入卡是**只读文本**，给人照抄进 ComfyUI，绝不进任何一段的模型载荷；卡面只显示用量、不做容量拒绝（整片卡是库存清单，不是一次请求）。
- 容量有两处闸门：上传/删除时的同步 422 `ref_capacity_exceeded`（点名超了哪一档，注意 12 是独立上限）与规划期的硬失败（段内闭包超 9 或单请求超 12 时点名超限素材）。
- 读图校对是真实视觉模型调用，CI 由桩管线伪造并覆盖「通过」与「不通过重开」两条路（#259）；真实多参验收的证据落 `output/accept-d7/`，按 2026-11-13 用户裁定延后（#260）。
