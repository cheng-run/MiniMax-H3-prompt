# 桥接帧链式锚定保留，失败用分层闸门拦（不改由关键帧另行生成）

第 N+1 段的首帧取自第 N 段输出视频的尾帧，所以**任何一段的失败都会被当成下一段的事实喂回去**（GEN003：段 2 的尾帧整段漂到另一场景——木框棕门、猫在地砖上，而 `shot-03.md` 声明收银台＋手——段 3 的伪影重叠与之吻合；重跑无效，因为输入一字未变，重掷不是独立实验）。官方 `base-en.txt:92-96` 明确认可这条链（edge-stability 句就是为「抽出的尾帧留给下一段当首帧」而设），故决定**保留链式**，改为在剥尾帧的当轮加分层闸门，不合格显式拦下而不是静默喂下去。

闸门分两层，**判定者不同**：**可证层**（`preflight.check_input_frame`：图与上一段视频尾窗的像素差超阈）报 `error`、硬阻断；**语义层**把人判交给流程——把上一段的 `end_hook` 与尾帧读图结果并排打出来，人判画面是否达到该末态。语义判定是启发式的，故只劝阻、允许显式覆盖；每次闸门遭遇都记进 `segments/gate-log.jsonl`。剥帧因此**前置于**「本段满意」的确认，进度落盘也后移到闸门通过之后（否则被拦下的段会被记成已完成，续跑直接跳过它）。

**考虑过并放弃**：

- **不抽尾帧、改由关键帧图另行生成**：唯一能真正切断累积的方向，但作为常规路径否掉——剥尾帧是免费且白送画面连续性的一步，另起要多一次生图与多一次人工失配机会，而官方明确认可这条链。保留为兜底：连续拦下同一段两次时，提示可改用关键帧图另起。
- **先造自动判据**（尾帧与本段 Picture 1 的场景身份相似度／LLM 裁判 `end_hook` 与读图结果是否一致）：本项目定阈值一律取在**实测分离边界**上（`MAD_MAYBE` 5.0、flicker 稳 0.09–0.17／坏 3.6–4.9、#11 多拍阈值 ≥3），而「场景漂移」目前只有 GEN003 一例，先上自动判据等于凭感觉定阈值。人判层会顺手产出校准所需的样本（图＋末态声明＋人的判定）。
- **自动重掷本段**：输入一字未变，重掷不是独立实验，只是烧十分钟换同一个结果。
- **给「不用上一段尾帧」留 opt-out**：那等于闸门可被静默绕过，且下一段会带 #9 定死的单图锚定行去声明一张并不存在的 Picture 1。

**范围**：闸门只管**段间**。末段（无下一段）的尾帧一致性是这条链的另一端、不是累积问题，另开票处理。
