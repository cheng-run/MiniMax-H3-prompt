# 变体之外的关键帧在解析处剥离（不判为校验失败重试）

2026-09-27（issue #38）。

## 背景

关键帧 bundle 只该装**该变体自己的**帧：I2VA 只有 `first`、L2VA 只有 `last`、FL2VA 两帧。
这条在**校验**侧早已写定（ADR 0009 裁定一：`variant_frame_names` 只认该变体自己的帧），
但在**产物**侧缺一条：模型偶尔会多写一张不属于它的帧（#37 那次运行**两轮**都自己多写了
`last`，当时是在试图满足地点词校验），而没有任何地方剥它。

链条是这样的：

1. `FL2VAPromptBundle.from_dict` 用 `_infer_frame_variant` **从帧的存在性反推变体**——
   I2VA 的回复里多一张 `last`，整份 bundle 就被读成 FL2VA，连 profile 默认值都变成 FL2VA
   那个 `h3_fl2va_v2`（实测：旧臂 I2VA/L2VA 的 `profile_id` 都是 `h3_fl2va_v2`，新臂都是
   空串——剥在**解析前**，默认值才按该变体推）；
2. `validate_fl2va_bundle` 按 `brief.variant` 只校验该变体自己的帧，所以多出来的那张
   **不被校验**，一路放行；
3. 于是它落成产物：`render_generation` 无条件渲染 `last-frame`，`last-frame-prompt.md`
   里装着那张用户根本不会生成的图（L2VA 是镜像：多一张 `first`）；
4. 还有三处**别的读者**（都不进票面的影响清单，是把 bundle 的消费者读全才看到的）：
   `_fl2va_frame_context` 对 I2VA **照样读 `last`**，把它当「视频最后一帧计划画面」写进
   整片正文的锚定块；`render_baseline_block` 同样两帧都读，于是人机修改循环的下一轮会把它
   当「上一版产物里用户没提过的部分」原样保住；`frame_common_sense_issues`（阶段 1 有界
   常识质检的判官）也照样把两帧拼进待审内容，多出来那张会以 `[last 帧] …` 的身份参与判分。

实测（两臂对照，`output/issue38-evidence/`）：旧臂 I2VA 的 `last-frame-prompt.md`、
`fl2va-prompt.json`、`generation.json` 三份产物含多返回的帧；正文锚定块、修订基线块与
质检判官读到的内容也含它（L2VA 同形）。

## 裁定：在解析处按变体剥离，并在帧节点告警

- **帧的归属由变体决定，不由「模型交了几张」推断**。变体是用户的选择
  （`resolve_effective_variant`：请求优先，多给了帧也不静默升级）——同一条口径现在覆盖
  模型多交的帧。
- 「哪个变体有哪些帧」只有一份表（`_FRAME_NAMES_BY_VARIANT`，读取口
  `generation.variant_frame_names`）：裁定用它、帧节点那句「必须保留 first、last」的改写
  清单也用它现拼——复审实测过，同一份知识在节点里另抄一张表正是本仓「规则在、接线不在」的温床。
- 剥离口是 `generation.strip_foreign_frames(raw, variant)`，**剥在原始 dict 上**再解析：
  这样 `from_dict` 才会据实推出该变体自己的 profile 默认值，而不是顶着 FL2VA 的
  `h3_fl2va_v2`。
- 三个入口各接一次，各有用处：`fl2va_bundle_from_dict`（「模型 JSON → 项目协议」的**不变量**，
  任何调用方都绕不过）、`result_from_state` 的非 FL2VA 支路（它为了读旧 state 特意宽松、
  不走上面那个函数，票面复现走的正是这条）、帧节点（**报告**：拿到被剥的帧名才说得出话）。
- **告警由帧节点打**（`[警告] I2VA 变体不含 last 帧，模型多返回的它已剥离，不会进入产物。`）：
  真实运行都经过它，所以「绝不静默失败」落地成可见，而不必在纯转换函数里打印。
- 非帧变体（T2VA／未知）**原样返回**：帧节点对它们直接返回 `{}`，本来就不存在帧 bundle。

## 考虑过并放弃

- **判为校验失败 → 走节点已有的改写重试**：最严格，但 #37 的物证显示模型**两轮**都多写了
  `last`，等于每次多烧一次 LLM 调用，最坏两轮全挂、把跑满 4 分钟的阶段 1 炸掉——那正是
  #37 刚修掉的那类脆弱（结构性满足不了的 error 闸门）。而且这不是「内容不达标」而是
  「多交了一张」，有确定性手段可用，没有理由占用模型轮次。
- **把被剥的内容留档**（写进 `fl2va-prompt.json` 的 `ignored` 字段或另落一份文件）：为一件
  事后几乎不会看的东西动 bundle 的落盘 schema；本仓连**被打回**的模型原始回复都不落盘
  （#37 要靠 tee 现抓），单独给这张帧开一份留档与全仓口径不一致。
- **顺手去掉 I2VA 交付目录里那个「（I2VA 变体未生成尾帧提示词）」占位文件**：它是 `8c527dc`
  有意的体验取舍（明说未生成，用户不会照着它去生一张用不到的图），且要去动 `main.py` 的
  文件清单打印。本票不碰——修完剥离之后，那个文件里已经没有可被误用的正文了。

## 后果与边界

- **自己的帧一张都不剩时仍按原样报错**（如 I2VA 的 bundle 里只有 `last`）：剥完为空 → 交给
  `FL2VAPromptBundle.from_dict` 抛「FL2VA 必须同时包含首帧和尾帧提示词」（该文案是既有的，
  改前给一份空帧 payload 就走它）。「该变体连自己的帧都没有」与「多了一张」不是一回事，
  没有被这次改动抹平。
- **告警只到控制台**：被剥的内容不进任何产物，事后从产物里看不出模型多写过什么。重议条件：
  有人真要复盘「模型多写了什么」。
- **旧会话不追改**：#38 之前存下的 session-state 里那份 bundle 仍是未剥的。CLI 路径
  （`result_from_state`）会剥；向导的提示词展示直接读旧 bundle、不重写它（同「旧 plan.json
  不自动修正」的先例）。
- `last-frame-prompt.md`／`first-frame-prompt.md` **占位文件照旧落盘**（内容只有一句
  「未生成」）：本票只清正文，不清占位。
- 校验侧「只认该变体自己的帧」仍是 ADR 0009 裁定一，本次没动它。

## 物证

`output/issue38-evidence/`（gitignore，不进库）：

- `probe.py`：确定性探针（无 LLM、无网络），两臂跑同一份脚本。
- `old-arm.txt` / `new-arm.txt`：旧臂是 `b473a58` 的干净 worktree（脚本里写死 `FIXED_POINT`，
  不是 `HEAD`——本票一提交 HEAD 就变），两臂的 `CONFIG_PATH` 与 `nodes.__file__` 都实测指向
  各自的树。旧臂：I2VA bundle `last=1`、三份产物含多返回帧、锚定块与修订基线块都含它、
  无告警；L2VA 同形（`first=1`）。新臂：两个变体的 bundle 都只留自己的帧、产物无多返回内容、
  锚定块/基线块/质检判官输入三处都干净、各打一条告警；FL2VA 两帧照旧保留（回归）。
