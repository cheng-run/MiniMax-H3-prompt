# base 与多参的段边界规则相反

> **状态（2026-11-19 复核）**：已接受；随 spec #342 落地（规划器判据见 #343，写段兜底纪律见 #344），本文裁定「两条规则方向相反」及其理由，不裁定「0.6 秒」的具体取值。

同一个 `segment_planner.parse_segment_plan` 里，base 要求内部段边界**不得**落在镜头切点上，多参要求**必须**落在切点上。看起来像其中一条写反了——两个相反的判据住在同一个函数里，谁先说「这里不对」都不会被立刻反驳。本文把两条规则为何都对记下来，免得下一轮把它们「修」成同一个方向。

问题出在 base 长片验收（2026-11-19，FL2VA / 18 秒，spec #342）：分段计划的内部边界 8s 与 14s 恰好都落在镜头切点上。桥接链路本身正常（段 1 尾帧与 `shot-01-start.png` 逐像素相同，差量 0.0），但段 2 的出场画面与桥接帧差量 50.8，贴着输入图起笔的段 1 只有 7.4；肉眼是中景全身 → 中近景胸上的硬切。更早的同类会话段 2 / 段 3 差量为 37.3 / 49.1，说明不是偶发，而是**边界落在切点上**这个结构位置的问题。

## 决定

1. **base 的内部段边界不得落在镜头切点上，落在某个镜头的内部。** 边界一旦避开切点，每段的开场画面就是上一段末帧那一镜的延续，桥接帧作为 `first_frame` 输入与段词指向同一套机位，两者不再互相抵消。
   - 判据住在 `segment_planner.parse_segment_plan` 的 base 分支：给定切点表时，内部段边界命中任一镜头切点即判不合格。
   - 切点从分镜表 `[Shot N]` 的时间戳抽取，起点由 `segment_planner.shot_cut_starts` 一处提供（复用 `segment_prompts._shot_blocks`），**不新写一份**；base 的切点表 `segment_planner.shot_cuts_from_table` 与多参 `ref_segments.prepare_ref_segmentation` 的机械窗口都从这份起点派生，多参再经 `segment_planner.plan_segments` 的 `shot_cuts` 传入，base 走同一入口、同一参数。
2. **多参的内部段边界必须落在镜头切点上，这条不变。** 多参没有桥接帧，段间靠参考素材与起止状态声明衔接；边界落切点保证「一个执行段＝整数个镜头」，镜内切会把一个镜头劈进两个执行段，两段都只看到半个镜头。
   - 既有唯一例外保留：单个镜头本身超过执行窗口（> `segment_planner.MAX_SEG_S`）时允许镜内切——长镜头拆段本来就没有切点可用。
3. **两条判据各住各的模式。** 都由 `segment_planner.parse_segment_plan` 的 `mode` 分派，各自的守卫都验证「同一条回复在另一模式下结论相反」，防止串线。
4. **抽不出切点＝该约束不生效，不是「全部不合格」。** 分镜表没有 `[Shot N]` 时间戳、只规划出单镜、或时间戳取整后彼此重合时传 `None`、跳过该约束，与多参「抽不出切点只靠指令约束」同一条降级口径；约束不满足时与既有「回复不合格」同路——返回空，调用方回退机械拆分。
5. **写段纪律只作兜底，不是主修。** 无条件注入 base 写段请求一条纪律：「本段 0.00 秒的开场必须沿用 Picture 1 的机位与景别，切镜最早放到本段 0.6 秒之后」（文本真源在 `writing_disciplines`）。它管的是「规划器避不开切点」与「切点抽不出」两种残余情形；主修仍是规划器把边界挪进镜头内部。

为什么方向必须相反：两条路线用不同的东西保证跨段连续。base 用**图片**——上一段末帧即本段第一帧输入，画面本身在说「继续」，边界落切点等于让图片说继续、段词说换镜，模型只能二选一，实测选了换镜。多参用**素材与声明**——没有一张「上一段末帧」图可以承接，它需要的是每段镜头单元的完整。**base 治接缝的画面连续性，多参治素材与叙事单元的完整性，两件事各有一把尺。**

## 考虑过的备选

- **允许 base 段首切镜**（边界仍落切点，靠写段纪律在 0.00 秒承接机位）：这就是 2026-11-19 验收时的现状，实测不成立。请求里 Picture 1 锚定 0.00 秒沿用上一帧，分镜块又在 0.00 秒换机位，两条指令互相抵消，模型按分镜块走。矛盾压在写段端，等于让每一段都去赢一次赢不了的冲突。
- **双轨「0.6 秒后切」**（边界仍落切点，同时要求段首同机位、0.6 秒后才切）：只是把硬切从 0.00 秒挪到 0.6 秒，接缝没有消失；而且一个执行段里因此出现两个机位，与 `shots_in_segment` 的记录对不上，验收时说不清这段的开头到底属哪一镜。规则还只有措辞、没有能拒绝坏规划的判据——「规则在、接线不在」的同款风险。`0.6 秒` 本身也只是首版取值，拿一个未校准的数当结构方案的地基更不成立。
- **只加写段纪律、不动规划器**：即上面两条的合体，治不了「模型按分镜块换镜」这个主要形态；纪律留着，但位置是兜底。

## 后果

- 规划器守卫成对：base「边界落切点 → 拒绝」、多参「边界离切点 → 拒绝」，同一条回复在两边结论相反；删掉任一侧判据、或把切点抽取改成恒空，守卫都要变红（「没有变异的守卫不算守卫」）。
- 抽不出切点时 base 不加边界约束，画面连续性退到写段纪律兜底；这不是静默降级——与多参同口径，且会记录在规划路径上。
- 已落盘的旧 `plan.json` 走既有兼容读口，不因解析变严而读不出来；新规则只作用于新写的规划。
- 多参与导演台的边界规则、写段词、包结构一律不动。导演台的切镜段语义（切镜就是硬切、不承接上一段）是它自己的显式建模，与本文无关，两条路线各管各的。
- `0.6 秒` 是首版取值、按实拍校准；本文只裁定「方向相反」，改这个数不需要重开本文。
