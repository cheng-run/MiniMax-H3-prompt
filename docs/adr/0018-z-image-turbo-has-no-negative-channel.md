# Z-Image Turbo 没有负向通路：生图提示词按正向纪律写

2026-10-22 的实测里，一条生图提示词的四处细节没被画出来（靠墙的数级低台阶、屏幕朝下的手机、咬了一口的三角形三明治、正在收拢的灯架），读图校对判出 4 处偏差。把现象归到模型侧后，查证到三条事实：

1. **Turbo 是蒸馏模型，CFG=1，负面提示词完全无效**。官方讨论区原话「this model does not use negative prompts at all」；diffusers 的 `do_classifier_free_guidance` 在 guidance=0 时返回 False，ComfyUI `samplers.py` 在 `cond_scale≈1` 时把无条件分支置空。写「不要 X」「没有 X」不但是空动作，还会被当正向词读。
2. **空间关系是它最弱项**。官方 GenEval Position 0.62（base）/ 0.65（Turbo），社区复现只有 39.5%；数量 0.77、属性绑定 0.68 也弱。属性绑定 Turbo 比 base 低 0.09。
3. **ComfyUI 链路不截断，但也不认权重语法**：文本编码器 `max_length=99999999`（`comfy/text_encoders/z_image.py`），而 `disable_weights=True`——`(词:1.2)` 不生效、括号原样进提示词。官方 PE 模板还明令禁止 masterpiece/8K 等元标签。

## 决定

生图提示词纪律写进 `prompts/image_prompt_engineer.md`（AI 改词复用同一套）：

- 只写镜头里**看得见**的事实；状态要翻译成可见证据（「屏幕朝下」→「背面朝上，方形摄像头模组可见，屏幕贴着桌面」）。
- 空间关系三件套：**锚点 + 方位 + 距离/比例**，一物一句；不写「靠墙的」这种无参照修饰。
- 数量写成可数实体并给逐个特征；一句只放一个数量。
- **一律正向陈述**，不写否定；要排除的用占位描述替代。
- 关键细节前置（前 30 字内），结尾复述一次。
- 单句短（约 40 字内），一物一句。
- 长度控制在约 600 字内（ComfyUI 不截断，但长文稀释注意力）。
- 禁 `(词:1.2)` 权重语法、禁 masterpiece/8K 等套话。

出词后加一道**警告级**确定性检查（负向表述、权重语法、套话、长度、方位缺锚点），不做 error 闸门。

**AI 改词的方向是强化原意，不是迁就成图**：只改偏差涉及的那几处，把被忽略的细节显式化；锁死清单与其余正文逐字保留。迁就成图等于让一张画歪的图反过来改设计，且与「按图改文案」重复。

## 考虑过的备选

- **靠负面提示词 / 负向词表**：Turbo 无 CFG 通路，空动作。
- **换 Z-Image base**：官方数据只换来负向通路与属性绑定（+0.09），Position 反而更低（0.62 vs 0.65），代价是 28–50 步。
- **只改 AI 改词、不动源头角色提示词**：源头仍会持续产出违反纪律的提示词，AI 改词只是补丁。
- **把检查做成 error 闸门**：判据容易被合法写法误伤，先以警告观察触发率。

## 后果

- 既有产物不自动改写；旧提示词照旧存在，重跑才吃到新纪律。
- 锁死清单的判据不变（仍是身份特征、仍是偏差的唯一依据）。
- 角色提示词被 docs 按行号引用，新规则**追加到末尾**，不中间插行（同 #36 的教训）。
- 「英文比中文更服从」没有官方依据，不作为规则。
