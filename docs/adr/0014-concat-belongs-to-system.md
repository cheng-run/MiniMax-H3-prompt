# 拼接归系统——全段验收通过后自动接成成片（反转 #39 ID13）

issue #39 的 ID13 写着「**拼接归用户**，系统只出段清单+拼接顺序卡」，US 24 的用意同此（「我自己剪辑拼接时有据可依」）。2026-10-20 的 `/grill-with-docs`（父 spec issue #54）把它反转：多参分段收尾改为**逐段陪跑 + 回传验收 + 系统拼接**——系统一次只出当前一段的提示词，用户交回该段输出视频、过两道闸，**全部段通过后由系统接成成片**（`<generation_dir>/final.mp4`）。

反转的理据是**交付主体换位**（#54 spec 的 Problem Statement）：收尾原先只交一份整片 `video-prompt.md`——那是一坨不可执行的文本（H3 单次只能生成 4–15 秒），等于让用户拿一个跑不起来的产物去干活。逐段产物其实早就落盘了，问题在**指错了交付物**。交付主体既然换成「逐段回传 + 验收」，拼接就没有理由再留在用户手上：段序（`plan.json`/拼接顺序卡）、每段是否通过（段产出账）**都已在系统手里**，让用户开剪辑软件按卡拼，等于把一条已经可自动化的收尾推回给人。

更要紧的是**纪律**：spec #54 定「**未通过即不拼**」——缺一段的成片时长对不上总时长，是伪产物，比没有更坏。这条纪律只有在系统拼接时才可执行；拼接留在用户手上时，系统无从保证成片里没有未验收的段（用户手工拼一条缺段的片子，系统连知道都不知道）。

落法（issue #57）：

- **自动拼接**：全部段通过后自动接成成片，段间**硬切**、用**各段自身帧**；段序取 `plan.json`（拼接顺序卡的机器可读面）。**复用既有的 ffmpeg concat 件**（`tools/seam_audit.merge_videos`：先 stream copy、失败转重编码），不新写 ffmpeg 调用。
- **段数=1 退化为拷贝改名**：≤15 秒直出的片子**收尾不分叉**（触发口径仍按总时长分流：≤15 秒直出、>15 秒拆段），整片六段式即本片唯一执行段，拼接退化为一次拷贝。
- **缺一段就不产出成片**，并点名卡在哪一段。这条规矩住在 `ref_segments.assemble_final_film` 里（不是调用方的 `if`）：规矩住在被拼接的那一处，才不会成为可以被绕过的调用方约定。
- **手动命令**：`uv run launch.py ref-concat <生成目录>`，重跑某段后不必从头走完整流程；`--replace N <路径>` 换掉重跑的那一段（该份**未经系统验收**，当面说破）。
- **可证核对**：段表必须无缝覆盖 `[0, 起步总时长]`（判据是「末段 end **≥** 总时长」，**不是**「各段之和 ＝ 总时长」——规划器允许末段留余量）；账上记的视频读不到（改名/搬走）、SHA256 对不上（换版/被覆盖）都拒绝拼接——「记 SHA256」本来就是为了对抗**文件名可变引用**，成片是它第一个真正的读者。

**被否决的方案**：

1. **全线保持「拼接归用户」**（#39 ID13 原裁定）：验收判定与段序都在系统手上，「未通过即不拼」无处落地；用户拿到的仍是「一坨文本 ＋ 一张卡」，短片与长片的体验继续分叉。
2. **只自动拼、不留手动命令**：重跑某段之后必须从头走完整流程（素材循环 ＋ 阶段 2 组装，可能十几分钟）才能拿到成片。
3. **逐段裁到计划时长，让实测时长严格等于总时长**：H3 产出**从不是整数秒**（4s 档恒 4.458s，见 `preflight.H3_TIER_FRAMES`），要裁就得新写 ffmpeg 调用（本票明令复用既有件）并承担关键帧对齐误差。「成片时长等于起步输入的总时长」的可证形态因此是**结构**的——段表无缝覆盖 `[0, 起步总时长]`，而**末段允许留余量**（规划器契约：`parse_segment_plan`「最后一段 end 可以略超 total（留余量）但不许欠」），所以成片比起步总时长长一点是设计使然；实测时长只做**只报短**的核对（短了说明有段没接上或交回了别的时长档）。这一条在实现时踩过一次：第一版把判据写成「各段计划时长之和 ＝ 总时长」，末段一留余量就会把**全段通过**的片子拒绝掉、理由还说是「段表不是一套」——同一份契约两处口径（issue #56 的假 `SEGMENT_TIMELINE_MISSING` 是同一个形态），复审实测可达后改成覆盖式判据。
4. **段数=1 时也走一遍 ffmpeg concat**：单段拼接就是拷贝，多跑一趟 ffmpeg 只多一个失败面。
5. **把段产出账与首尾帧链的闸门遭遇记录（gate-log）合并成一本**：两本记的是不同的判定物（那本记桥接链的锚帧人裁，这本记多参段自己的交接物），混在一起将来给自动判据取阈值时分不开（#55/#56 已裁定分家）。

## #39 相关条目的现状（票面点名的一簇，逐条照实标注）

票面把 #39 的 **US 15–19 / 24** 与 **ID 11–14** 整体点名为「已被取代」。逐条核对后，真正被**推翻**的是 US 24 的「我自己剪辑拼接」与 ID 13 的「拼接归用户」；其余条目的**机制**照旧，被取代的是它们作为「流程终点」的地位（收尾不再止于「出段提示词＋出卡」）。照实标注，不把没变的说成变了：

| #39 条目 | 原文要点 | 现状 |
| --- | --- | --- |
| US 15 | CLI 输入目标总时长，系统按它路由与拆段 | 部分取代（#54）：时长输入与路由不变；路由不再是流程终点 |
| US 16 | ≤15 秒直出一段、>15 秒按镜头边界拆 4–15 秒执行段 | 部分取代（#54）：拆段口径不变；≤15 秒直出改为**走同一套收尾**（段数=1） |
| US 17 | 每段提示词是完整独立的六段式 | 部分取代（#54）：段文本形态不变；段提示词不再是交付终点（交付物是成片） |
| US 18 | 每段带时间轴注记（段序+起止秒） | 部分取代（#54）：注记照旧；服务对象从「用户手工拼接」变成「系统拼接的段序对位」 |
| US 19 | 每段带起止状态声明 | 部分取代（#54）：声明照旧；对照物改由系统并排摆给人判（语义层，issue #56） |
| US 24 | 系统出段清单+拼接顺序卡，**so that 我自己剪辑拼接时有据可依** | **完全取代**（#54/#57）：卡照出，但**拼接归系统**；卡的作用变成段序的出站真源 |
| ID 11 | 总时长与路由 | 部分取代（#54）：同 US 15/16 |
| ID 12 | 多参分段（六段式/注记/状态声明/禁指代前文） | 部分取代（#54）：分段机制照旧，收尾另立（#55/#56/#57） |
| ID 13 | 连续性机制：共享素材 ＋ 文本状态；**拼接归用户，系统只出段清单+拼接顺序卡** | **完全取代**（本 ADR 的正题）：拼接归系统 |
| ID 14 | 时长校验扩档 4–15 | 实质不变（#54 未动它）：另加收尾侧的**可证层**交接闸门（#55） |

#39 的原文不改（已关票的票面是历史记录），本 ADR 是这一簇条目的**现状标注**。相关先例：ADR 0011（多参分段不套单图开场锚）、ADR 0012（时长档分路线）。
