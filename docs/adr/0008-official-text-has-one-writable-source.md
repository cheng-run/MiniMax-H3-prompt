# 官方原文只有一处可写来源：references 是给人读的对照物，原文由加载处注入

2026-09-27（issue #35）。

## 背景

同一句官方原文在仓库里有**四处**各自独立的副本，谁也不知道别的几份是不是还一样：

| 位置 | 是什么 |
|---|---|
| `references/base-en.txt` / `ref-en.txt` | vendor 进来的官方原文本体 |
| `tools/h3_validator.py` 的常量 | 代码侧写死的两份（`EDGE_STABILITY_SENTENCE`、`ALIGN_TEMPLATES`） |
| `prompts/prompt_engineer.md` | 人工文本里又抄的一份（三行对齐指令 + edge-stability 句） |
| `tests/test_h3_validator.py` / 正样本 fixture | 测试里抄的又一份 |

而「官方如此」这句话，链条上原先只有一个地方会去核对（#8 留下的那一条断言，只钉了 edge-stability
句）；`ref-en.txt` **一份代码都没读过**，#30 因此把它记成「先例性的空接线」。这是本仓的
高发病「规则在、接线不在」的一个变体：**声明在，判据不在**。

## 裁定一：references 是给人读的对照物，不做运行时的解析源

被否掉的那条路是「让 references 真被读到」：在 import 时从 `base-en.txt` 的 ```text 围栏里
把对齐指令与 edge-stability 句**解析**出来，让官方文件成为代码的取值来源。不这么做的理由：

1. **要解析的是一份给人读的散文**。取值得靠「第 2.1 节第几个围栏」「这句话后面那个围栏」这类位置
   依赖，官方文件换个排版就崩——而崩的地点是 `h3_validator` 的 **import 期**，它被 agents / graph /
   segment_prompts 全体导入，爆炸半径是整个程序。本仓的既定纪律是加载链上不做模板与解析
   （ADR 0006 裁定一、裁定二）。
2. **上游换版本时，代码应当有一次有意的确认**，而不是悄悄跟着漂。这些常量进的是**模型请求**
   （写段模板逐字符插值），官方措辞一变，产出就跟着变——这种改动值得一次人工签字，而不是
   「重新 vendor 一下，测过了，绿」。
3. 反过来，**常量也不该被当成官方文件的替代品**：它们必须被钉回原文。

所以：references 的定位是**给人读的官方原文 ＋ 守卫测试的对照物**，写进 `references/README.md`
（就在文件旁边，谁也绕不过去）；`h3_validator` 的模块 docstring 原先自称「以官方规范为唯一依据」，
那句话把「人读的参考」说成了「机器读的真源」，一并改掉。

## 裁定二：代码里只留一处可写来源，其余全部改成**派生**或**被钉住**

- **角色提示词**：`prompts/*.md` 里的手抄**删掉**，只留指针（「原文见文末【官方逐字符原文】」）；
  原文由 `agents.load_role_prompt` 从 `h3_validator` 常量注入到文末。这是本仓已有的形态——
  电影语言词表就是在加载处附上的（ADR 0006 裁定二），理由同一条：抄进 N 份人工文本就是 N 份硬拷贝。
  列表 `OFFICIAL_VERBATIM_ROLES` 是显式的：**不声明即拿不到**（当前只有整片提示词工程师要）。
- **测试**：用例里的字面量改成取常量，不再另抄（测试里那份同样会漂，且返回值里两份都在场，
  看不出哪份是旧的）。「常量 == 官方原文」的断言集中到 `tests/test_official_references.py`。
- **注入块只做搬运**：块里的每个字都逐字取自常量，函数不改写（同 ADR 0006 对切片的纪律）。
- **块标题只有一处定义**（`OFFICIAL_VERBATIM_MARKER`）：块、角色 .md 的指针句、测试都按它认，
  否则「块标题」自己又成一个三处各写一遍的字面量——正是本 ADR 要消的东西。
- **「唯一」的口径**：指**出站文本的来源**，不含文档引文与样本（正样本 fixture、各条用例里
  内联的同句）——为什么不做全树扫描，见下面「考虑过并放弃」。

**代价（写明白）**：模型看到的四段原文**位置变了**（从「产出」小节与「铁律」列表里，挪到文末的块）。
这是出站文本的改动，不是纯重构。缓解：内容逐字不变（改前 .md 的四段与注入块逐字节相同，见
`output/issue35-evidence/two_arm_check.log` 第 2、3 节），且指针句仍留在原位、仍带「逐字符照抄、
不改写不译文」的要求——要求留在原地，只有字面量挪走。

## 裁定三：守卫测试要能报红（变异检验）

`tests/test_official_references.py` 把常量逐字钉回两份官方文件（`ref-en.txt` 由此拿到它的
第一个消费者），反向钉住「被判自创结构的标记在官方原文里确实找不到」——把注释里的断言变成
可执行的判据。`tests/test_role_prompts.py` 另外钉住两端：白名单里每个角色**都要**留指针
（漏写指针 = 原文送出去了但模型不知道文末那块干嘛用），且 .md 的指针必须与块标题逐字一致。

守卫测试若永不为红就等于没有，故附**变异检验**：11 处扰动（常量改一字 / 对齐指令多一空格 /
base 与 ref 各混进一个假字段名 / 混进假 retention 标记 / 自创结构标记里塞进官方真有的短语 /
白名单清空 / 白名单全线放开 / 白名单加角色而它的 .md 无指针 / 改块标题使指针失配 / .md 恢复
一份手抄）**11 处全被抓到**（`output/issue35-evidence/mutation_check.log`）。
端到端另有一道：用**记录型桩模型**建真 agent，抓模型实际收到的 system 消息——官方原文 4/4 段
在里面，且没越权送去 qa（`output/issue35-evidence/system_prompt_check.log`）。

## 考虑过并放弃

- **import 期解析官方文件**：见裁定一。
- **保留 .md 手抄、只加一条「.md 必须含常量」的守卫测试**：那只是让第 2 处可写来源**报红**，
  不是**消失**；「改一处生效」这个性质仍然不成立，而票面的要求是「只剩一处可写来源」。
- **回归测试里连源码一起扫，证「只有 h3_validator 写死原文」**：Python 侧的常量是**跨行拼接**的
  字符串（`"…edges " "crisp and…"`），整树子串扫描扫不到它，会给出**假绿**——不可靠的守卫比没有更糟。
  Python 侧改由「唯一来源被插值到出站文本」＋「常量钉回官方原文」两条一起守住；.md 侧才能扫（散文是字面量）。
- **顺手把 `segment_prompts.py` 里同样写错的引用（edge-stability 句标成「官方 base-en.txt 2.1」，
  它其实在 §4.2）一起改**：那是出站文本的另一条路径，属另一件事；本票只改了 `prompt_engineer.md`
  里同一句的引用（本就顺手重写那一行），其余留作记录不冒充已修。
- **给更多角色注入原文块**：除整片提示词工程师外没人需要——两条写段路径是代码拼的请求
  （`segment_prompts` 直接插值常量），审查/质检角色是拿校验器工具去判，不自己逐字符写。

## 后果与边界

- 官方原文要改（比如上游换了措辞）：改 `h3_validator` 一处 → 注入块、两条写段模板、校验器
  一起跟着动；守卫测试报红提示你去核对 `references/` 里的官方原文。
- 反向地，重新 vendor 官方文件而不动常量：守卫测试报红。**这不是要你删掉那条用例**，
  是让你做一次有意的确认。
- 本票不动产出质量，也不新增校验闸门（本仓纪律：闸门收紧要先有实测样本）。
- 正样本 fixture（`tests/fixtures/official_shot01_i2va.md`、`flicker_arms/*`）里的原文是**样本**，
  不是来源：样本本来就得长得像真实产出，所以它们保留原文；它们是检验物，与来源分叉时由
  上面的钉合用例报红。

## 票面归属

#35（父票 #30 的 Out of Scope 第二件）。#30 的 ADR 0006 裁定三说「要逐字符照抄的官方原文只留指针」，
那条只落实在真源里；本 ADR 把同一条纪律落实到角色提示词与测试上，并给出 references 的正式定位。

**对 #35 票面前提的一处更正**：「两份 references 从不被任何代码打开」只对 `ref-en.txt` 成立——
`base-en.txt` 自 issue #8 起就被 `tests/test_h3_validator.py` 读过一条断言
（`git log -S BASE_EN_REF` → `b70e421`）。本票没有推翻这个前提就动手，先跑了实测再写证据。
