# 人的修订累积、机器的质检问题替换：两条同形重出循环的语义分叉

阶段 1 有两条长得几乎一样的重出循环：**自动常识质检循环**（判出 error → 注入问题 → 重出一轮，上限 `max_qa_iterations`）与**人机修改循环**（展示提示词 → 用户提意见 → 重出）。2026-09-25 裁定：**人的修订按轮累积**（说了就不忘，可按编号回收），**机器的质检问题每轮重算**（替换语义，问题消失即失效）。两者不统一。

| | 用户修订 | 质检问题 |
|---|---|---|
| 提出者 | 人 | 系统（常识判官） |
| 语义 | **累积**：说出口就对后续所有轮次成立 | **替换**：每轮对**当前产物**重新判一遍 |
| 失效条件 | 人显式回收（按编号删任意一条） | 产物变化后重算不再报 |
| 载体 | `state["user_revisions"]` | `state["frame_prompt_issues"]`（每轮 `pop`） |

**为什么分叉**：人提的意见是一次性说出口的**断言**，静默丢掉是**信息丢失，而且用户看不见**；机检问题是**对当前状态的判断**，产物改了判断就该重算——把它累积下来，等于让一个已经修复的问题永远压在下游头上。**两者的「有效性来源」不同**（人的意志 vs 当前状态），故不该共用一套语义。

**物证**：用户实测同一主题连提两次意见。第 2 轮产物含「中国古代**秋日**庭院」「几片**秋日枫叶**落在青石与水缸边，院中或墙侧有**红枫**与树影」；第 3 轮产物里**秋日／枫叶／红枫 一个都没有**——第 1 条意见被第 2 条整体顶掉。用户的原话是「正常的流程应该是每次都会记住意见，而不是每次都从来」。

## 触发本裁定的五处根因（均有可复现证据）

| # | 根因 | 证据 |
|---|---|---|
| 1 | 意见只经 `brief.plot` 走私，没有独立通道 | 重出时把意见拼进 plot 字符串 |
| 2 | 重出只跑首帧提示词**一个节点**，而人物／背景／道具／美术统筹／分镜／镜头评审／身份锁定／画面细化**全部在它之前定稿** | 阶段 1 链序；该节点只返回 frame bundle |
| 3 | **长视频分段路径断链**：写段请求收了一个**从未被引用的** `brief` 参数，分段规划函数**根本没有**这个参数 | 分段请求函数的函数体不引用该参数；四个既有测试调用点全给它传 `None` 而照过 |
| 4 | 意见不累积：第 N 轮用**循环外**的原始 brief 重建 | 用户实测三轮产物（见上） |
| 5 | `frame_feedback` 字段**写了从没人读**，且不在会话持久化白名单 | 全仓库仅一处赋值、零处读取 |

第 2 条导致用户的判断成立且必须记下来：**在首帧环节提「汉服改成现代审美」在架构上没有任何落点**——它既改不了人物设计，也改不了身份锁定。用户称之为「形式主义」，这是准确的结构描述，不是感受。

## 配套裁定

- **层次＝重跑起点**：修订分四档（只改画面／人物设定／美术场景道具／剧情分镜），每档**一一对应阶段 1 链上的一个起点节点**，不另造映射。设定级重跑**复用既有的 `run_stage1(resume_from_node=...)` 截断链机制**（续接路径已在用），不新建机器。层次由**用户自己声明**——只有人知道这条是画面口味还是设定变更；让机器猜是不可证启发式。
- **意见不再经 `plot` 走私**：`plot` 同时喂给主题地点守卫（**按子串**提取地点硬约束）与生图常识判官（「不得新增主题中不存在的主体、地点或道具」的判据）。把散文意见塞进去等于让意见文字**随机改写两条闸门的判据**，且有**否定句反噬**——用户说「不要森林，改到庭院」会让守卫反而开始要求正文出现「森林」。
- **注入优先序：首帧图 > 用户修订 > 分镜表**。理由沿用既有教条：图是用户提交的**产物**，分镜表是**计划**，成片必须与图连续。「提了修订却没重出图」这种冲突**不做自动判定**（语义对比不可证），改为写段前把「累积修订」与「首帧读图结果」**并排展示**交人判。
- **续接路径补上同一个修改循环**：它原本只展示提示词、不提供修改入口，这一处不对称随本次一并修。

## 考虑过并放弃

- **统一为累积**（质检问题也累积）：已修复的问题会永久压在下游，且它与「每轮对当前产物重判」的实现直接矛盾。
- **统一为替换**（意见也每轮替换）：就是今天的行为，用户已实测其害。
- **继续把意见塞进 `plot`**：污染两条闸门判据（见上）；且 `plot` 是「主题」的宿主，名字与内容说反话。
- **自动裁决互相矛盾的意见**（如先「改成秋天」后「改回春天」）：需要不可证的语义判断。改为**展示带编号的清单 + 允许删任意一条**，把判断交回人。
- **设定级意见只注入、不重跑**（当注记用）：下游会同时看到「汉服朴素」（来自人物设计产物）与「改成现代审美」（来自注记）**两条打架的指令**，谁赢取决于模型临场判断，不可证。
- **自动判定「修订与首帧图冲突」**：同上不可证；只并排展示。
- **给那个死参数 `brief` 找一个用途**：修订本来就住在 state 里，写段请求本来就在读 state 取关键帧锚定——**从 state 读并删掉死参数**比给它派活更干净。

## 后果：接线纪律

本次五处根因里**两处**是「写了没人读」形态（死字段 + 死参数），故加一条验收口径：**每个新增字段／入参必须有一条断言它在产出物里可见的测试**（请求文本、落盘状态或展示块）。

另：**「已落地」标记只在重跑成功后写**——重跑失败或用户中断时不得写，否则清单会谎报。
