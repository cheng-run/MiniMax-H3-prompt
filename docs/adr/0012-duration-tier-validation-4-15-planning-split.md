# 时长校验档扩到 4–15，规划档分路线（首尾帧链保守 4–10）

2026-10-16 读 59- 工作流自定义节点源码实测契约 min=4/max=15，旧「ComfyUI 时长下拉只有 4-10」对该节点已过时（issue #46 AC6 据此把**执行段/交接校验**的时长校验从 4–10 扩到 4–15 整数档：`preflight.check_shot_duration`/`check_segment_video` 与 `warn_out_of_range_durations` 跟节点真实能力走，不再误杀 11–15s 的合法产出）。但 59- 是多参专用工作流，**工作流 62（首尾帧链）的时长节点没有复核过**——「旧说法过时」的证据只覆盖前者。故**规划档分路线**：首尾帧链仍按 4–10 保守档出段，且 `segment_planner.parse_segment_plan` 的验收闸**分模式**（base 硬闸 4–10，与 #46 前行为逐字一致；ref 4–15）——校验层只负责不误杀，规划闸不替未复核的工作流做激进假设。多参规划按镜头边界在 4–15 取整（`segment_planner_ref.md`）。

被否决的方案：全线放开到 4–15（若工作流 62 的节点真是 4-10，不听话的 base LLM 会规划出 ComfyUI 里选不出时长的段并静默通过——共享验收闸就是开这个口子）；校验也锁 4–10（多参 11–15s 段全被误杀，AC6 不成立）。收尾信号：哪天实测工作流 62 的节点也是 4–15，把 base 规划措辞与 `BASE_MAX_SEG_S` 同步放宽即可，校验层无需再动。
