# 工作台审查面与帧提交

> **状态（2026-11-11 复核）**：已接受；随 D4（#227）落地，三处裁定在 #232 / #233 / #234 实现并验收。

D2 把 `base` 的生命周期搬到了服务端，D3 补上了素材、媒体与本地鉴权。D4 要让「人在环里」的两步真正可操作：先审阶段 1 的中间产物，再把用户生成的图片作为首/尾帧喂回管线。规格在 #227 里当场裁定了三件会被后来者反复追问的事，这里记决定与为什么。

## 决定

1. **中间产物落盘为「产物」，不新增 state 端点**（Q5 / Q11）。阶段 1 完成时把 `script.md`、`shot-table.md` 与帧链的首/尾帧词写进会话目录，登记进既有产物白名单，前端经 `GET /api/v1/artifacts/{id}/content` 读正文。`stage_state` 仍只住在服务端。
   - 复用已经存在的三件事：白名单、文本 1 MiB 上限、Content 端点的鉴权与形态分支。多开一个 state 端点等于把内部中间键做成对外契约。
   - revise 重跑后文件原地更新，审查面看到的永远是当前稿；正文不进快照，避免「快照里的旧稿」成为第二份事实。
   - T2VA 只有剧本与分镜表，帧链才有两帧词——**产物清单本身**就是「该显示哪些文件」的事实，前端不再按变体判一遍。

2. **帧提交做成第二个人工待办，不并入 approve**（Q6）。`stage1_review` approve 后，仅帧链会话创建一个 `frame_submission` 待办；会话仍停在 `awaiting_human`，发既有 `action_item.created`。resolve 端点扩展 `frames: {first?, last?}`，按 kind 分型；**不加新事件类型**（十种闭合）。
   - 两个动作在真实流程里隔着一段时间：用户先看帧提示词、拿它去生图，图片就绪后才回来交帧。并入 approve 会把「批准文本」与「图片已生成」绑成一次原子提交，逼用户在没图时二选一。
   - 双空提交是**显式跳过**（UI 确认框点明会降级为纯文字），不是禁止；降级按 `resolve_effective_variant` 记录，不静默。
   - 帧直接引用素材文件、不复制第二份；读图审计在 job 内完成（慢速视觉调用不占请求）。

3. **不做交付确认闸门**（Q7，收口 #214 §9 的推延）。阶段 2 成功即 `completed`（`TERMINAL_STATUSES`），没有第二道人工确认。
   - `base` 的交付物就是可复制的 `video-prompt.md`，它本身已经是产物；再加一次「确认交付」没有下游动作可触发。
   - 昂贵的那一步（阶段 2）之前已经有过人工闸门；把确认放在花钱之后，只是让用户多点一次。
   - 将来若某条路线需要「交付审批」（例如付费渲染），应新增一种 `action_item` kind，而不是把 `completed` 改成又一个中间态。

## 考虑过的备选

- **把 `stage_state` 直接暴露给前端**：省一次落盘，但内部键变成 ABI，revise 与续跑随时会改它们；也让 1 MiB 上限与产物白名单这两条边界失效。
- **把帧槽并入 approve 的请求体**：批准被图片就绪状态阻塞，且同一条待办要接受两种完全不同的决议载荷，错配校验会变成一团 if。
- **自动从会话素材里挑首/尾帧**：看起来省一步，实际会在用户没点名的情况下把错图送进读图与阶段 2，而且「跳过」不再可表达。
- **新增 `frame_submitted` 之类事件**：事件类型是十种闭合集合，`action_item.created` 已足够表达「多了一个人工待办」。
- **在 `completed` 之后加 `delivering` / `delivered` 两态**：为一次没有下游动作的确认扩状态机，所有消费终态的地方都要跟着改。

## 后果

- 产物登记表（`workbench_store.py`）是「哪些文件能看」的唯一来源；新增产物必须同时进登记表与写盘点，前端不抄第二份白名单。
- 帧链的闭环是「审查 → 帧提交 → 阶段 2」两停一跑；T2VA 是「审查 → 阶段 2」一停一跑（既有语义不变）。
- 完成态没有后续动作：`completed` 即终点；中断的阶段 2 续跑按 `stage1_review` 的决议事实回到阶段 2，不回人工闸门。
- 真实浏览器 + 真实 LLM 的闭环由 `scripts/accept_d4.py` 手动验收（不进 CI）；CI 用桩管线跑两条路径到 `completed` 并复制产物。
