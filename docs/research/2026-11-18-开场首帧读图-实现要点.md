# 开场首帧读图（spec #317）——实现要点与代码地图

给 #321–#326 的实现代理用：把要碰的面都点一遍，省得各自重新摸索。
**本文件只写「住在哪」与「接缝是什么」；票面与 spec 才是需求的真源。**

票面：#317（spec）、子票 #318–#326。

## 一、读图这一半（#318 已抽、#321 要用）

- 共享读出点：新模块 `director.still_description`（#318 落地）。全片尾帧原有的
  `director.film_end.get_film_end_description` 会成为它的一个薄包装。
- sidecar 契约住在 `director.frame_meta`：`write_frame_meta`（整份重置）/
  `merge_frame_meta`（累积合并）/ `read_frame_meta`（坏文件返回 `None`）/
  `sha256_file`。sidecar 路径＝被描述文件同名换 `.meta.json`。
- 缓存命中三条判据：`kind` 相符 ＋ `description` 非空 ＋ `image_sha256` 与当前图一致。
- **读图失败必须抛错且不落盘**；坏 sidecar 反过来要宽容（当没有，重读）。
- 视觉调用在用例里一律桩掉（`minimax_h3_prompt.tools.reference_auditor.describe_image`
  是唯一入口；延迟 import，桩要打在 import 之后生效的位置）。

## 二、开场首帧图的落点与判据（#321 要用）

- 路径：`director.pack.start_still(session_dir, position=1)` →
  `director/assets/01/start.<ext>`；扩展名偏好是 `pack._ASSET_EXTS`。
  **别另写一份扩展名列表**。
- 模式闸：`director.pack.opening_start_still_missing(session_dir, mode)` 里写着
  「哪些模式需要这张图」（i2v / fl2v）。
- 段槽位判据：`director.frames.needs_first_frame_image(segment_type, mode)`
  ＝ `IMAGE_FIRST in give_images_for(...)`。**注入判据必须问它，不许写模式字面量、
  不许硬编码段类型清单**——r2v 的开场段没有首帧槽，问它会自动排除。
- 开场段的段类型常量：`director.frames.FIRST_SEGMENT_TYPE`（＝ `opening`）。

## 三、写段请求的接缝（#322 要用）

- 组装点：`director.prompts.build_segment_request`，入参全显式。
- 块顺序的唯一真源：`director.prompts._SEGMENT_REQUEST_BLOCKS`（provider 元组）。
  **新块只在这张表里插一行**，不要改相邻 provider 的拼接现场。
- 现有序（节选）：
  `instruction → header → give_images → start → revision → film_end → story → …`
  spec §5 要求新块插在 **`start` 之后、`revision` 之前**（「本段起点是哪」之后紧跟
  「起点画面是什么」）。spec 同时写明「位置可改，若希望与终点块相邻，实现时提请裁定」。
- 每个 provider 收同一个 `_SegmentRequestContext`（dataclass，字段全显式）；
  新增入参要同时加进这个 dataclass 与 `build_segment_request` 的形参。
- 空值不产生块、也不产生空行——统一走 `_context_block()`。
- 全片尾帧的块长什么样：`director.film_end.render_film_end_block(description,
  for_planning=...)`。开场首帧的渲染器要**同形**（`for_planning` 只改「拿它来做什么」
  那半句）。

## 四、规划期注入（#322 要用）

- `director.planning.plan_director_segments(...)` 形参里已有
  `film_end_description`；注入现场在函数体内按 `mode == "fl2v"` 再守一道。
- 调用方（CLI / 工作台）先按**盘面**判一次（`film_end_still(...) is not None`），
  函数内再按模式守一道——开场首帧照抄这个两层判据。

## 五、纪律句真源（#319 已落地、#321 要用）

- `writing_disciplines` 模块（#312 建立）只放**文本、不放逻辑**。
- 首尾帧链的双向一致性纪律句原本是 `segment_prompts._FRAME_CONSISTENCY_DISCIPLINE`，
  #319 提到真源模块成为公开常量。**导演台新块必须从真源取，不许写第三份**。

## 六、调用点：CLI（#323）

`ui/wizard.py` 里与全片尾帧一一对应的三处：

1. 收图之后：`_collect_director_stills`（`store_director_still` 落图之后的
   `prepare_film_end_description` 附近）。
2. 规划前：`_run_director_flow` 里 `prepare_film_end_description` 那一段。
3. 写段前／改词：`_run_director_segment_handoff` 里的改词分支。

统一出口：`ui/wizard_director.prepare_film_end_description(session_dir) -> (ok, description)`
——**新票要在它旁边加 `prepare_opening_still_description`，同形状**，两处失败文案由它
统一说。它内部先判盘上有没有图、再调读图口、捕获 `RuntimeError/OSError` 打印并返回
`(False, "")`。

## 七、调用点：工作台（#324）

`api/jobs.py`：

- 规划：`JobRunner._plan_director_project` 的真实分支（`prepare_film_end_description`
  在 `from ..director.pack import film_end_still` 那一块）。
- 写段上下文两个构造点：
  - 当轮规划返回的 `_DirectorWriteContext(...)`（同一个函数里）；
  - `JobRunner._director_resume_context(...)`（续跑重建）。
- **`_DirectorWriteContext` 是 dataclass、显式传参**。票面明令：**绝不能挂到 runner
  实例属性上**——runner 是进程级单实例、多会话并行，实例属性会把 A 会话的描述串给
  B 会话。已有事故。
- 桩模式分支（`fake_pipeline.director_plan` 那条）也要显式填槽位，与真实分支同形。

## 八、离线导出（#325）

- `scripts/director_request_dump.py`：
  - `_film_end_description(image)` 只读 sidecar、**绝不现场读图**；缓存缺失就抛
    `DumpError` 并说清「真实写段会当场重读（付费、改会话目录）」。
  - 它在内部直接调用 `film_end_module._cached_description(image, sha256_file(image))`
    ——**这是个私有名**，#318 重构时若改名要同步这里。
  - `dump_session(...)` 里按 `film_end_still` 现算 `film_end` / `film_end_description`，
    再逐段调 `build_segment_request`。开场首帧照抄这条路径。

## 九、测试与守卫的既有先例

- 读图与缓存：`tests/test_director_film_end.py`（桩 `describe_image` 的写法在文件头上）。
- 请求块：`tests/test_director_prompts.py`（`_plan()` / `_SUBJECT_DEFS` 是现成的段表
  样本，多个用例文件都 import 它们）。
- 跨路线纪律守卫：`tests/test_writing_disciplines_guard.py`（记录型桩模型 + 出站文本
  断言；**先断言真源非空再 `in`**，否则清空真源的变异会被 `"" in text` 恒真骗过）。
- 变异清单：`scripts/mutation_check.py` 的 `MUTATIONS`，每条要 `old` 在文件里**恰好
  出现一次**，并声明 `tests` 与 `why`。
- 离线导出：`tests/test_director_request_dump.py`。
