### 4. 帧网格与「保完整」

#### 4.1 对齐函数

【源码确证，`director/frame_align.py:8-13`】

```python
def minimax_align_frame_count(frame_count: int) -> int:
    n = max(5, int(frame_count))
    while n % 17 != 5:
        n += 1
    return n
```

即 `17k+5`（5, 22, 39, 56, 73, 90, 107, 124, 141, 158 …），**只向上取整、不报错**。
潜在网格由 `FRAME_PER_TOKEN = (1, 4, 4, 4, 4)` 决定：5 个潜步 = 17 像素帧（`h3_motion_context.py:27`）。

#### 4.2 声明帧 → 导出帧

【源码确证】

| 步骤 | 代码 |
|---|---|
| 上下文枚举 | `CONTEXT_FRAME_CHOICES = (5, 22, 39, 56)`、`DEFAULT_CONTEXT_FRAMES = 22`、`DEFAULT_AUDIO_CONTEXT_FRAMES = 24`（`h3_motion_context.py:30-39`） |
| 采样长度 | `generation_frame_budget(visible, ctx)`：`visible = align(声明)`；`sample = align(visible + ctx)`；`trim = ctx`（`:747-774`） |
| 导出长度 | `continuity_export_len(...)`：`trim<=0 → target_len`（即声明帧）；`keep_tail → sample − trim`；否则 `visible`（`:777-794`） |
| 实裁到导出 | `_trim_decoded_to_export`（`executor_core.py:159-184`） |
| 「保完整」默认开 | `resolve_continuity_keep_tail`（`segment_continuity.py:167-181`），缺省 `True` |

**算术（ADR 0024 核对）**【算术推导】：

- 有引导：`align(声明)` ≡ 5 (mod 17)，`ctx ∈ {5,22,39,56}` 全 ≡ 5 → 和 ≡ 10 → `align` 补 12。
  `sample = align(声明) + ctx + 12`，`export = sample − ctx = align(声明) + 12` → **恒 ≡ 0 (mod 17)**。✅ ADR 成立。
- 无引导：`trim = 0` → `export = 声明帧`（`target_len` 原值，**不对齐**）。✅ ADR「无引导段导出 = 声明帧」成立。

#### 4.3 相位对齐会裁上一段尾部几帧

【源码确证】

- 选窗函数 `_phase_aligned_tail_start(total_steps, n_steps, end_frame)`（`h3_motion_context.py:202-251`）：在**上一段的采样网格**上找 `5` 步对齐的起点，使 `pin_end_px ≤ 上一段导出末端`，返回 `gap = end_limit − pin_end_px`。
- 应用位置：`executor_core.py:948-1048`——`trim_export_tail` 裁掉 `prev_export_trim` 帧（`:972-977`），把新长度写回 `handoff["phase_align_trim"]` 并**重存缓存**（`:1035-1048`，`replace_audio=False`）。
- 每段交界最多差 16 帧（步长 17）。

**关键推论**【算术推导】：

| 上一段类型 | `end_limit` | 网格边界 | `gap` |
|---|---|---|---|
| 有引导 | `trim + export = ctx + 17k`（ctx≡5） | `17m + ctx` 恰好等于它 | **0** |
| 无引导、声明帧在 `17k+5` 上 | `声明 = 17k+5` | `17m + 22 = 17(k−1)+22 = 17k+5` | **0** |
| 无引导、声明帧**不在**网格 | `声明` | 上一个边界 | `(声明 − 5) mod 17 ∈ [1,16]` |

→ **只要每段声明帧都落在 `17k+5` 上，相位对齐就一帧都不裁**；ADR 0024 示例里的「段1 声明 108」（`108 mod 17 = 6`）会被裁 1 帧 → 实际 107，成片合计 719 而非 720。
（该结论为源码公式推导，**未实跑验证**。）

#### 4.4 UI 侧的强制吸附（比插件后端更凶）

> **2026-10-29 协调会话复核更正（以本节为准）**：下面这条结论只对「**UI 新建/编辑**的段」与 **image_batch 模式**成立，**不适用于导演包导入的 gen 段**。
>
> 证据（源码确证）：导入走 `applyImportedTimeline` → `ensureGenTimeline()` → `normalizeGenSegments()`；后者取 `seg.frameCount ?? seg.length` **原样保留**，只夹到 `[minFc, MAX_GEN_FRAMES]`，**不按 `durationSec` 重算**（`web/js/minimax_timeline.js:4813-4858`）。按秒重算发生在 `newBatchSegment`（`web/js/minimax_gen_timeline.js:437-466`）与 image_batch 的 `normalizeImageBatchSegments`。
>
> 因此：**包内每段必须同时写 `frameCount`/`length` 与一致的 `durationSec`**；只要 `frameCount` 存在，30 秒五段 720 帧的规划（段1 声明 108、其余 141）在导入后保持原值。风险只剩「用户手动改秒数」那一步——那时 UI 会吸附到 `17k+5`，属执行期行为，项目侧不承诺。

【源码确证】这是本次勘察最影响规划口径的一条：

- `newBatchSegment` 注释直言「**durationSec is the user-facing source of truth; frameCount is derived by formula**」（`web/js/minimax_gen_timeline.js:427`），返回对象里 `length`/`frameCount` 被**强制重算**（`:460-463`）。
- `normalizeImageBatchSegments` 对每个段：`fc = durationToClampedMiniMaxFrames(durationSec)` → `seg.length = seg.frameCount = fc`（`web/js/minimax_image_batch.js:893-908`）。
- `durationToMiniMaxFrames(sec, fps) = max(5, round(sec×fps))` 再吸附到 `17k+5`（`web/js/minimax_gen_timeline.js:93-107`）。
- UI 存的秒数**只有 1 位小数**（`roundDurationSec`，`:108-113`）。
- 归一化在**工作流恢复**时就会跑：`normalizeSegments()`（`web/js/minimax_timeline.js:4578`）。
- 段帧上限 `MAX_GEN_FRAMES = 512`（`:239`）。

**后果**：项目若声明 108 → UI 取 `preferredDurationSecFromFrames(108)` → 找不到能反演出 108 的秒（因为反演公式只会返回 17k+5）→ 回落 `round(108/24)=4.5` → `align(4.5×24=108) = 124`。**108 变成 124**。
（`preferredDurationSecFromFrames`：`web/js/minimax_gen_timeline.js:126-143`。）

#### 5.4 怎么数出实际帧数（#105 的核心）

**【源码确证】没有任何「读帧数」的缓存 API**。插件侧只有：
- `_frames_exist`（存在性，`:473-477`）
- `_load_frames`（**整段解码**成 float32 张量，`:480-503`）——代价大，不建议
- `lib/video_io.py:150-179` `_ffprobe_count_frames`，`:204-272` `probe_video_file`——但这些跑在 ComfyUI 进程里，项目侧**不能 import**

**结论：帧数只能由项目侧从帧文件自己数。** 三条可行路径：

1. **`ffprobe`（首选，若本机有）**
   ```
   ffprobe -v error -select_streams v:0 -count_frames -show_entries stream=nb_read_frames -of csv=p=0 seg_0000.frames.mkv
   ```
   （matroska 里 FFV1 通常没有 `nb_frames`，必须 `-count_frames`，会真解码一遍。）
2. **只用 `ffmpeg`（`imageio-ffmpeg` 是项目依赖，但**不**随附 `ffprobe`）**
   ```
   ffmpeg -v error -i seg_0000.frames.mkv -map 0:v:0 -f rawvideo -pix_fmt rgb24 - | wc -c
   ```
   再除以 `W×H×3`。宽高用 `ffmpeg -i` 的 stderr 解析（`WxH`），或从 `handoff.json`/计划拿。
3. **`handoff.json` 的 `export_frames`（快、不解码，但是「写盘时记的数」）**

`handoff.json` 内容【源码确证，`executor_core.py:1569-1575`】：
```json
{ "trim_frames": 22, "export_frames": 153, "sample_frames": 175, "official_mc_length": false }
```
相位对齐后还会多一个 `phase_align_trim`，并**与帧文件一起原子重写**（`:1035-1048`）。因此正常情况下它与帧文件一致；但缓存写是 best-effort，任一步失败会留下不一致——所以**判据应落在路径 1/2，`handoff.json` 只作交叉核对**。

**代价提醒**：默认 `cache_frames_codec="raw"` → 磁盘上是 `seg_XXXX.pt`（torch），项目侧**没有 torch 依赖**，读不了。要么让用户在导演台把「缓存编码」切成 `ffv1`，要么把校验改走 `handoff.json`。

### 8. 最终包（UI 导出）与初始包的结构差异

【源码确证 + 推断】

### 打包（#104）

1. **包内所有路径必须 ASCII**：`^[A-Za-z0-9_./]+$`，禁 `..`、禁绝对路径、禁反斜杠。中文素材名必须在包内改写为 ASCII（`_ascii_extra_name` 那套逻辑可参照：`[^A-Za-z0-9_]+ → _` + sha1 前 8 位）。
2. **媒体路径要写成相对包根、带 `PACK_PREFIX` 前缀**（`asset_groups/NN/…`、`shared_params/…`、`source_video/…`、`extra/…`），否则导入时不会被改写成 `input` 相对路径，运行时找不到文件（会被静默清空）。
3. **每个媒体字段必须写 `imageFile`/`audioFile`/`videoFile`**（不是只写 `fileName`）。
4. **同一段不要同时给 `genImage` 和内容不同的 `startImage`**：导出时两者都落到 `asset_groups/NN/start.<ext>`，`_copy_file` 命中已存在就跳过 → **后一张图静默消失**（`pack.py:237-242`、`:454-467`）。i2v 用 `genImage`+`imageFile`；fl2v 用 `startImage`+`endImage`。
5. **`commonEnabled` 必须为 `false`**（`shared_params.json` 与 `timeline.global` 两处）：为真时全局词会以 `"{common}\n\n{segment}"` 拼到每段词前（`plan.py:202-212`），参考图还会按槽位合并（`merge_indexed_refs`）。
6. **画布宽高必须 32 的倍数**（后端会抛错，但报错发生在执行时，不在打包时）；`output.mode` 对生成类必须 `"fixed"`。
7. **`output` 必含**：`continuityEnabled: true`、`continuityOverlapFrames: 22`、`continuityKeepTail: true`、`continuityMode: "guide"`、`exportMode: "all"`。
   **且这些只能挂在 `output` 下**——timeline 根级的同名键会被 UI 的 `stripTimelineContinuityRootFields` 删掉（`web/js/minimax_timeline.js:271-277`），最终包里就没有了。
   - **媒体一律用文件引用，不用 `imageB64`**：`sanitizeSegmentForPayload` 会把 `imageB64` / `previewB64` / `previewFrames` 从导出载荷里删掉（`web/js/minimax_timeline.js:322-330`）。
8. **`mixed` 段类型必须逐段校验在 `{t2v,i2v,fl2v,r2v}` 内**——插件会把非法值**静默**改成 `t2v`。
9. **`refs[].index` 必须从 0 连续**，且每段 ≤ 9 张；`refAudios`/`refVideos` 各 ≤ 3。
10. **每段声明帧必须落在 `17k+5` 上**。理由有三：(a) 有引导段导出 = `align(声明)+12`，只有声明在网格上时 `align` 才是恒等；(b) 无引导段导出 = 声明，只有声明在网格上时相位对齐才不裁尾；(c) **UI 归一会把不在网格上的声明重算到网格**（108 → 124）。ADR 0024 的「段1 声明 108」是反例，必须改（例如 107，或把 12 帧余量分配到别处）。
11. **不要写 `durationSec`，或必须与声明帧严格自洽**：后端 `_segment_frame_count` **优先读 `durationSec`**（`gen_timeline.py:89-99`）并用 `align(round(sec×24))` 覆盖 `frameCount`；fl2v 的 UI 更是**只认 `durationSec`**。
12. **fl2v 要同时写 `shots` 与 `segments`**，段级用 `genImage`（首帧）+ `endImage`（尾帧），没有 `startImage`；负面词默认 `"bad video"`。
13. **`timelineMode` 必须显式写**（`prompt_batch`/`fl2v`/`video`），`editMode` 随之（`segment`/`global`）。不写会按任务类型猜，`v2v`/`rv2v` 猜错就走成生成类并因缺源视频报错。
14. **`pack.json.widgets.task_type` 与 `timeline.global.taskType` 必须一致**——前者优先级更高。

### 段规划（#102 相关，但由本勘察反向约束）

15. **段边界由 `frameCount` 顺序累加得出，`start` 被忽略**（生成类，`gen_timeline.py:102-123`）。所以数组顺序 = 时间顺序，不能靠 `start` 排。
16. **总时长校验不能用 `Σ 声明帧` 去对 `总时长×24`**：有引导段每段多 12 帧，`Σ 导出帧 = Σ 声明帧 + 12×(有引导段数)`。ADR 0024 的「720 = 108 + 4×153」核对了这一条。

### 可证层（#105）

17. **默认配置下磁盘上没有 `frames.mkv`**，只有 `seg_XXXX.pt`（torch）。要么要求用户把 `cache_frames_codec` 切成 `ffv1`，要么改用 `handoff.json`。这是 #105 最先要定的一件事。
18. **`meta.json` 不能当产出凭据**：它只有输入指纹，没有帧数、时长、尺寸。
19. **判据按「段类型」分档**：有引导段 = 17 的倍数（且可能被下一段相位对齐裁掉至多 16 帧，见第 4.3 节；**若声明帧在网格上则为 0**）；无引导段 = 声明帧（同样可能被裁）。
20. **`mixed` 下「段有没有引导」不能只看总开关**：还要看该段 `continuityFromPrev`（缺省 `true`，段 0 恒 `false`）、该段 `taskType`（`i2v` 带首图 → 引导失效）、以及上一段缓存是否存在（缺失则**静默降级硬切**，只留一行 info 日志）。
21. **缓存目录名 = `<缓存名>_<节点id>`**，缓存名会做字符替换（Windows 非法字符、空白、点 → `_`，截 64 字）；项目存的用户输入名不能直接拼路径，要复刻 `normalize_cache_name` 的规则，否则找不到目录。
22. **缓存指纹不含父段身份**——级联重跑必须由项目删下游缓存目录里的 `seg_*.{frames.mkv,pt,av.pt,audio.pt,meta.json,handoff.json}`，插件不会自己失效。

### 陪同执行（#107）

23. **执行期提示词会被插件改写**（补 `<Picture N>`/`<Video 1>`/`<Audio J>`、删无效 `<Audio N>`、空词兜底）。若项目要「送进模型的词 = 账本里的词」，必须自己写全标签且关键词非空。
24. **「全片模式全部命中缓存 → 不再采样」不成立**：选中的段一律重采样。要「只跑第 N 段」必须用 `runSelection`（`runSelectEnabled: true` + `runSelection: [索引…]`），否则整条重跑。

### 最终包比对（#108）

25. **比对路径固定为 `timeline.json` → `segments[i].prompt`**（fl2v 加比 `shots[i].prompt`），join 键用 `segments[i].id`；`group.json` 只在 `timeline.json` 的该段词为空时才被采用，不能作为比对源。
26. **最终包的 `frameCount` 可能被 UI 归一化改过**（见第 4.4 节），所以「最终包 vs 初始包」的段帧数差异不一定代表用户手改——比对口径应只针对**提示词**与**挂图**，帧数若要一并比，必须先复现 `durationToMiniMaxFrames`。
