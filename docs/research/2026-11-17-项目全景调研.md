## 1. 一句话定位与产物链

输入一句创意 → 双语设计与分镜（阶段 1）→ 英文 H3 提示词（阶段 2）→ 长视频按执行段拆开逐段跑 → 成片。
项目**不生成图、不生成视频**，只生成提示词与导演包，执行在 ComfyUI 侧由用户完成。

```
创意 → 澄清 → 阶段1(剧本/设计/分镜/关键帧词) → 阶段2(整片提示词)
     → 分叉：base 首尾帧链｜ref 多参｜director 导演台 → 逐段陪跑 → 成片归档
```

三条路线**并存**（不是替代关系），共用同一条阶段 1 主管线，在阶段 2、拆段与逐段验收处分叉。

## 2. 三条路线 · 四条入口

| 维度 | base（首尾帧链） | ref（多参 ref2va） | director（导演台） |
|---|---|---|---|
| 提示词格式 | base 三段式 | ref 六段式 | 段词（三字段或六节）＋导演包 |
| 画面锚定 | 关键帧图（首/尾） | 参考素材 | 开场首帧 / 参考素材 / 纯文本 |
| 跨段连续 | 剥上一段末帧作下一段首帧 | 段内参考素材＋起止状态声明 | 段间引导（AV latent 尾部，默认 22 帧） |
| 时间轴 | 相对本段起点，整秒段 | 相对本段起点，整秒段 | 帧网格 `17k+5`，段词写相对、组装器换成成片坐标 |
| 逐段证据 | 用户贴段视频 → 剥末帧 | 用户贴段视频 → 剥首末帧读图 | 用户贴段视频 → 数帧 |

| 成片 | 系统拼接 | 系统拼接 | 导演台合并导出，项目只归档 |

桌面壳（`desktop.py`）。**四条入口走同一套业务函数**，分叉点只在「谁调用、进度怎么出站」。

## 4. 提示词生产线

### 4.1 阶段 1（三条路线共用同一节点链）

`制片 → 导演 → 创意圆桌（制片‖导演‖编剧）→ 编剧 → 设计三并行（人物‖背景‖道具）→ 美术统筹
→ 资产图提示词三并行（仅产资产图的路线）→ 分镜 → [镜头评审会 ‖ 身份一致性会]
→ [摄影指导 ‖ 参考一致性] → 关键帧生图提示词（仅要关键帧的路线）
→ [声音设计 ‖ 配乐] → 生图常识 QA（有界）`

- **节点在链上 ≠ 产物一定有**：走不走由 `brief_parser.route_emits_asset_prompts` /
  `route_emits_frame_prompts` / `director_frame_variant` 三个判据决定，这三处是唯一真源。
- 阶段 1 的 state 键（`script` / `character_design` / `background_design` / `prop_design` /
  `art_design` / `shot_table` / `shot_review_lock` / `visual_design` / `identity_lock` /
  `creative_lock` / `subject_defs` / `fl2va_frame_descriptions` / `user_revisions`）后面被不同消费者取用，
  **取用方各不相同**。
- **不是 state 键的东西别去 state 里找**：锁死清单住在 `character/prop/scene_image_prompts`
  每条条目的 `locked_features` 字段里（`nodes._normalize_locked_features` 校验）；
  `director_mode`、`frame_revision_baseline`、`setting_revision` 被持久化白名单**故意排除**。
- 持久化白名单唯一真源是 `session_store._STATE_KEYS`；**漏登记即静默丢失**（`bridge_frame_descriptions`
  有实测教训）。

### 4.2 阶段 2 分叉

| 路线 | 主产物 | 是否再切 |
|---|---|---|
| base | `video-prompt.md`（三段式） | ≤10s 直接交付；>10s 再规划分段 |
| ref | 六段式整片词 ＋ 注入卡 | >15s 按镜头切点拆段，只重编号 Picture |
| director | **没有整片词**：直接段表＋逐段词＋导演包 | 按帧规划，一次打包 |

### 4.3 电影语言词表接线〔读码〕

三份真源、三个读取口、四张白名单（两两不许相交）：

| 键 | 真源 | 消费者 |
|---|---|---|
| `storyboard` | video | 分镜师 |
| `cinematographer` | video | 摄影指导 |
| `prompt_engineer` | video | 整片提示词工程师（角色） |
| `segment_writer` | video | **四条写段请求**：base v2 / base 回退 / ref v2 / ref 回退 / 导演台 |
| `frame_prompt_engineer` | image | 关键帧生图词工程师 |
| `image_prompt_engineer` | image | 资产图（人物/道具/场景三种共用） |
| `tailframe_writer` | tailframe | 导演台尾帧词（直调，无角色） |

落笔侧两个键共用同一个元组 `_WRITING_SIDE_SLICES`（九节全取，含「运镜怎么写」），并有测试钉两者相等。
这是按引用共享的**最大一份**提示词内容（另有 `h3_validator.EDGE_STABILITY_SENTENCE` 与帧变体锚定行
也是单一来源）——改真源一处，四个消费者同时变。

### 4.4 六条写段入口和它们拿到的事实〔读码〕

「写段」不是三条路径而是**六条**：base 有 v2 与回退，ref 有 v2、回退、机械拼装，director 一条。

| 入口 | 分镜切片 | 图 / 读图 | 用户修订 | 画面决策 | end_hook 语义 |
|---|---|---|---|---|---|
| base v2 `build_segment_v2_request` | `[Shot N]` 精确切片 | `_frame_anchor_note`（含 `_FRAME_CONSISTENCY_DISCIPLINE`，称「唯一事实源」） | 有 | 有 | **落定**（`_segment_end_state_block_for_request`） |
| base 回退 `rewrite_segment_prompt` | 机械单镜段 | 同上 | 有 | 有 | 无末态块 |
| ref v2 `build_ref_segment_v2_request` | 按 `shots_in_segment` / 窗口重叠 | 无帧锚，靠本段定义块子集 | **无通道** | **不接**（docstring 明写这是首尾帧链的通道） | 只作注记句 |
| ref 回退 `rewrite_ref_segment_prompt` | 同上 | 同上 | 无 | 无 | 只作注记句 |
| ref 机械 `ref_segments._mechanical_segment` | 重编号＋时间戳重基（不过模型） | — | — | — | 注记取 `start_state`/`end_hook` |
| director `build_segment_request` | **整张表**，靠措辞约束窗口（首帧词另用 `shot_excerpt_for_window`） | `_fl2v_start_block` 只用上一段 `end_hook`；无首帧读图 | **无** | **无** | **切点**（`END_HOOK_CUT_CLAUSE`） |

两条推论，改提示词前必须记住：
- **「落定」只在 base**；**「切点」只在 director**；**ref 两者皆无**（只有一句注记）。三套语义不要互相套用。
- 六条入口共用 `_direct_write`（看门狗）、`MAX_SEGMENT_ATTEMPTS`、词表 `segment_writer` 切片——
  **只有这三样是共享的**，其余全部各自实现。

## 5. 共享 · 拷贝 · 刻意分叉

这是本项目**所有「改一处漏一处」事故的根源**，也是读代码时最该先认清的一层。

| 对象 | 形态 | 位置 |
|---|---|---|
| 落笔侧词表（含运镜六条判据） | **按引用共享**：一个元组两键共用＋测试钉相等 | `film_language._WRITING_SIDE_SLICES` |
| 直调看门狗 / 重试预算 | 按引用共享 | `segment_prompts._direct_write`、`MAX_SEGMENT_ATTEMPTS` |
| 官方节常量与节头识别 | 按引用共享 | `h3_validator.BASE_SECTIONS` / `REF_SECTIONS` / `_find_sections` |
| edge-stability 句 | 单一可写来源 | `h3_validator.EDGE_STABILITY_SENTENCE` |
| 修订块 | 共享实现；**base 写段与两路规划期**都接；ref 写段与导演台写段不接 | `segment_prompts.render_revision_context` |
| 画面决策块 | 共享实现；**base 两条写段路径接**；ref 显式不接（`build_ref_segment_v2_request` 的 docstring 写明「修订/帧锚/画面决策是首尾帧链的注入通道」），导演台不接且无书面理由 | `segment_prompts._visual_decision_block_for_request` |
| 「机位速度按剧情选」纪律句 | **4 份硬拷贝，措辞已漂** | base v2 / base 回退 / ref ×2 在 `segment_prompts`；导演台在 `prompts/segment_writer_director.md` |
| 「时间窗外剧情禁区」块 | **3 份硬拷贝** | `build_segment_v2_request` / `build_ref_segment_v2_request` / `director.prompts._future_events_block` |
| 「禁止指代前文」纪律 | **3 份硬拷贝**（判据正则在 `_ANAPHORA_RE` 一处） | `_REF_SEGMENT_DISCIPLINES` / `segment_writer_director.md` / 校验器 |
| 写段指令全文 | **各自维护**（三套） | `_SEGMENT_V2_INSTRUCTION` / `_REF_SEGMENT_DISCIPLINES` / `segment_writer_director.md` |
| 写段校验器 | **刻意分叉**（判据不同，设计 §3.3 明写不许复用） | `validate_segment` / `validate_ref_segment` / `validate_director_segment` |
| 时间轴口径 | **刻意分叉** | base/ref 相对本段起点；导演台组装器换算成成片坐标 |

**结论**：共享的只有**词表**；纪律文本是靠拷贝外传的。于是维护方向永远跟着「当前在跑的路线」走，
另一条只能靠人记得。这正是 11 月两极分化的机制。

### 5.1 三个校验器各咬什么

| 校验器 | 组成 | 注意 |
|---|---|---|
| `segment_prompts.validate_segment` | 委托 `h3_validator.validate_base(variant="I2VA")` | 三节/序、对齐指令逐字、`[Shot]` 编号与时间戳、自创结构、末节拍余量、对白结构；`TIMESTAMPS_LOOK_ABSOLUTE` 只是 warning |
| `segment_prompts.validate_ref_segment` | 委托 `validate_ref` ＋六条 ref 段判据 | 除 `DETAILED_TOO_SHORT/LONG`、`RETENTION_NO_MARKER` 外都是 error；**`BODY_NOT_ENGLISH` 是阈值启发式却报 error** |
| `director.prompts.validate_director_segment` | 七条自判，**不整体调** `validate_base`（后者顺带查切点/说话人/edge-stability，整调会造假错） | **`FIRST_SHOT_DISCONNECTED`（二元组零重叠）是启发式却报 error** |

「启发式却报 error」这三处是有界重写的主要触发源：段词被反复重写时先看它们，而不是先怀疑模型。

## 6. 阅读陷阱（按踩过的次数排）

1. **「段词里有分镜没写的东西＝模型加戏」——错。**
   链路是 `分镜表 → 规划 summary/end_hook → 段词`。先 diff 分镜表原文：`d69f2cfd/GEN002` 的
   `segment-02.md` 里那些细节（掌根压堤面、金属插扣轻响、海右陆左）**逐条都在同会话
   `shot-table.md` 的 Shot 3/4/1 里**。真正自造的是两处机位。
2. **「拿两个 GEN 比两条路线」——非单变量。**
   每个 GEN 是独立阶段 1 产物：`d69f2cfd` 的 GEN001（base）与 GEN002（导演台）分镜表 4.5K vs 6.1K，
   动作链完全不同。比对路线必须同分镜表、同锚图、同采样，否则结论不成立。
3. **「导演台也有首尾帧，和 base 一样」——不是同一个东西。**
   base 的是**桥接帧**（剥上一段末帧，每段都吃一张真实画面）；导演台的是**帧槽**（start/end 图槽），
   跨段连续靠**段间引导**。导演台的引导段**没有首帧图**，且引导开时插件会丢弃该段首帧图。
4. **「给图清单＝包里挂的图」——不是。**
   给图清单是**执行期**要备的图（段表出站给人看）；包里只装开场首帧与参考素材，尾帧由用户在 UI 里逐段挂。
5. **「段内素材预算」vs「段内素材子集」——输入 vs 产出。**
   预算（`asset-budget.json`）在写段**之前**由规划定；子集（`assets-in-segment.json`）在写段**之后**按正文算子集。
   混用会指错文件。
6. **三个尺寸别混**：画布（生图尺寸）／成片画幅（声明的目标宽高）／视频输出（实测宽×高）。
   2026-11-04 验收出现过「声明 736×1280、实际 864×480」。
7. **三个帧数别混**：声明帧（`17k+5`）／导出帧（有引导段＝声明+12，恒 17 的倍数）／实际输出（还会被下一段相位对齐裁掉几帧）。
8. **模式差异在派生函数里，不在段类型名里**：`director/frames.give_images_for` 先按模式分派——
   t2v 零图槽、i2v 单段只能 opening、r2v 每段只给参考素材。照段类型名推首帧会把 r2v 写成有槽位。
9. **edge-stability 句不是官方要求**：2026-11-01（#117）定性为**本仓增补、来源不明**，但行为不变
   （仍要求每个镜头块以此句收尾）。
10. **改 base 写段不是改一处**：base 有 v2 与回退两条产出路径，外加分段规划这个第三消费者；
    改提示词必须三处同看。
11. **「测试全绿＝改对了」不成立**：本仓守卫只钉单条路径，**没有任何跨路线一致性守卫**
    （见 §7-G5）；没有变异用例的守卫不算守卫。
12. **`output/sessions/` 只在主树**（gitignore），工作树里没有真实产物；要对照实跑必须回主树读。
13. **行号会漂**：票面与文档一律写「模块.符号」，不写 `file.py:123`。
14. **文档权威序**：`CONTEXT.md` = 术语；`docs/adr` = 决策；代码 = 实现。三者冲突时先看 ADR 与代码，
    再决定改文档还是改码——`docs/design` 与 `docs/research` 是**当时快照**，不保证与现状一致
    （已核实的四处漂移见 §7.1）。
15. **「API 跑通 ≠ CLI 跑通」**：Headless API 有 `MINIMAX_FAKE_PIPELINE` 桩分支（`api.fake_pipeline`），
    CLI 没有；桩里通过的东西在真模型下未必成立。另：`api.jobs.JobRunner.reconcile` 只把 `running`
    收成 `interrupted`，**不自动续跑**。

## 7. 已知缺口（截至 2026-11-17，均未实现）

> 全量候选（A–G 七族，含本轮与延后）的**处置与延后理由**见索引票 #296；
> 本仓不落第二份清单——两面各存一份会各自漂。

**G1 导演台写段请求缺四块**（模式无关，四种模式共用同一条链路）：
整张分镜表原样塞入（应切片到本段窗口）、用户累积修订只在规划期注入、阶段 1 画面决策从未进入、
`end_hook` 是切点但缺「推进到、不越过」的纪律。位置：`director.prompts.build_segment_request`。
**注意分界线**：ref 写段也不要修订与画面决策，但那是**有书面理由**的（多参没有帧锚，那套是首尾帧链的
注入通道，见 `build_ref_segment_v2_request` 的 docstring）；导演台这一处**没有任何书面理由**——
两件事形态相同、性质不同，别一起「修」。

**G2 t2v 引导段没有【本段起点】**：`director.prompts._fl2v_start_block` 对非 fl2v/r2v 直接返回空串，
于是 t2v 的 `camera_same`/`ending` 段既无图、也无「上一段落定画面」，只靠整张分镜表。

**G3 开场首帧图从不读图**：全仓只有全片尾帧被读（`ui.wizard_director.prepare_film_end_description`
→ `director.film_end.get_film_end_description`）。i2v 全片唯一一张图、fl2v 的 opening、以及
`camera_cut` 的首帧图，写段时都没有画面事实——base 那边这块是 `_frame_anchor_note` 的「唯一事实源」。

## 9. 怎么验证「我读对了」

改任何与提示词相关的代码前后，跑这六条：

1. **词表到没到**：读 `film_language.VIDEO_SLICES` 与四份请求模板，确认切片含「运镜怎么写」「写作纪律」标题。
2. **块到没到**：在目标请求字符串里 grep 块标题常量（`REVISION_CONTEXT_HEADER`、`VISUAL_DECISION_HEADER`、
   `SEGMENT_END_STATE_HEADER`、`【本段起点】`、`【本段给图】`），别只看组装函数「会拼」。
3. **接线在不在**：用记录型桩模型跑一次 `write_director_segments` / `build_segment_v2_request` 的调用方，
   抓出站请求——组装函数会拼不等于调用方传了。
4. **给图对不对**：逐项跑 `director.frames.give_images_for(段类型, 模式)` 五种类型 × 四种模式。
5. **帧数对不对**：`declared_frames_for_export` 与 `land_exports` 的往返；有引导段导出恒 17 的倍数。
6. **加戏归因**：拿同一 GEN 的 `shot-table.md` → `plan.json` 的 summary/end_hook → `segment-NN.md` 三层对照，
   定位是分镜写的、规划加的、还是写段自造的。
