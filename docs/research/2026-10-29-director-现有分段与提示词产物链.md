## 1. 分段规划

### 1.1 `SegmentPlan` 契约（`segment_planner.py:30-98`）

字段（全部由 dataclass 定义，`:31-45`）：

- `index: int`、`start_s: int`、`end_s: int` —— **整数秒**，不是 float；
- `shots_in_segment: tuple[int, ...]`、`summary: str`；
- `end_hook: str` —— base 的语义是「下段首帧锚」，ref 的语义是「本段末态声明」（`:37-40` 注释写明这个分歧）；
- `start_state: str = ""` —— 只有 ref 用（起止状态声明进正文）；
- `assets_in_segment: dict | None` —— ref 的段内素材子集（issue #75），**只有非 None 才写盘**（`:63-65`）。

`duration_s` 是 `end_s - start_s` 的 int 属性（`:47-49`）；`to_dict` 省略 None 键（`:51-65`）；`from_dict` 对旧档缺键**宽容**（`end_hook`/`start_state` 读空串，`:86-92`），但 `assets_in_segment` 形态坏了会抛 `ValueError`（`:95-97`）。

> **对 #102 的直接含义**：这个数据结构**装不下**帧真源。`start_s/end_s` 是整秒、`duration_s` 是整数减法、下游 `_coverage_problem` 按秒判覆盖（`final_film.py:79-99`）。导演台要 `start_frame/end_frame/declared_frames/export_frames/segment_type/giving_list`，应新写一个 dataclass（例如 `DirectorSegmentPlan`），**不要**给 `SegmentPlan` 加帧字段——它被 base/ref 两处规划、两处校验、成片覆盖判据同时读，加字段就等于把「同一契约两处口径」再开一次（本仓已咬过两次：记忆条目 `one-validator-two-totals`）。

### 1.2 `parse_segment_plan` 的两档验收（`segment_planner.py:218-284`）

- 时长上限**分路线**：`limit = MAX_SEG_S(15) if mode == "ref" else BASE_MAX_SEG_S(10)`（`:236`，常量定义 `:22-24`，依据 ADR 0012 写在 `:15-21`）；
- 硬约束：整数边界（`int()` 已保证）、`MIN_SEG_S(4) ≤ duration ≤ limit`、首段从 0 起、段间无缝（`:252-258`）、末段 `end_s >= total_s`（允许略超，`:279-281`）；
- `end_hook` **两条路线都必填**（`:264-267`，issue #95）；`start_state` 仅 ref 必填（`:268-269`）；
- 只有 ref 检查「内部边界落在镜头切点」（`:282-283` → `_boundaries_on_cuts` `:287-297`；超长镜头的镜内切是唯一例外，`:294`）；
- 结构不对返回 `None`（内容病），**调用失败**则抛 `RuntimeError`（`:349-352`）。

`shot_cuts` 由调用方给：ref 侧从 `_shot_blocks` 的块首秒现推（`ref_segments.py:1332`），base 侧根本不传（`wizard.py:4511-4516`）。

### 1.3 规划指令文件

| 文件 | 给谁 | 选法 |
|---|---|---|
| `src/minimax_h3_prompt/prompts/segment_planner.md` | base | `_load_instruction("base")`，`:196` |
| `src/minimax_h3_prompt/prompts/segment_planner_ref.md` | ref | `mode == "ref"` 时选它，`:196` |

两份是**故意分开**的（`:193-195` 注释：锚定语义不同，「塞一个文件里改一处漏半处」）。base 版硬约束 4-10s、不要求切点（`prompts/segment_planner.md:18-20`）；ref 版 4-15s、边界落在切点、`start_state` 英文（`prompts/segment_planner_ref.md:12-18,41-43`）。

> 规划师**不接**电影语言词表切片（`film_language.py:77-79` 明列「不进白名单」，理由：段尾钩子是锚帧语义校验的对照物）。#102 若也想让导演台规划师读词表，那是**改既有裁定**，不是顺手接线。

### 1.4 `plan_segments` 与调用点（`segment_planner.py:305-352`）

签名：`plan_segments(shot_table, total_s, llm, *, frame_context="", revision_context="", mode="base", shot_cuts=None) -> list[SegmentPlan] | None`。

- 请求 = 指令文件 + 总时长 + 可选「关键帧实际画面」块（`FRAME_CONTEXT_HEADER` `:27`，拼装 `:332-335`）+ 可选修订块 + 分镜表（`:337-343`）；
- 走 `run_direct_call(llm, request, role=SEGMENT_PLANNER_ROLE)`（`:346-352`）：首字节心跳、卡住重试、token 记账与角色调用同源（ADR 0019）。角色名常量 `SEGMENT_PLANNER_ROLE = "role_segment_planner"`（`:302`）——**新路线必须给新角色名**，否则成本表分不清钱花在哪。

调用点（生产只有两处）：

- **base**：`ui/wizard.py:4510-4516`（`step_scope("正在分段规划")` 包住，`_drain_stdin()` 紧跟 `:4520`）；
- **ref**：`ref_segments.py:1331-1340`（`prepare_ref_segmentation` 内，异常 → `planning_failure` 文案 + 回退机械打包，`:1335-1340`）。

### 1.5 规划失败的机械回退

- base：`split_shots_from_prompt` 按 `[Shot N]` 与 `At MM:SS.mmm` 反推（`segment_prompts.py:278-315`），`len<2` 就整段直出并返回 False（`wizard.py:4529-4535`）；
- ref：`pack_shots_into_segments`（`segment_planner.py:143-190`，碎窗/超长镜/末窗三条规则写死）＋ `_derive_plan` 从窗内首末句派生 `start_state/end_hook`（`ref_segments.py:383-397`）。

> 导演台的机械回退等价物是「按 17k 网格均分」，#102 需要一个确定性打包函数，形状可照 `pack_shots_into_segments`（纯函数、输入输出都是元组，好测）。

### 1.6 `plan.json` 形态（回答「数组还是 dict」）

**两条路线都是 JSON 数组**，只是排版不同：

- ref：`_write_plan_file` 手拼 `"[" + ",\n ".join(...) + "]"`（`ref_segments.py:911-920`），读回 `read_plan_file` → `json.loads` → `[SegmentPlan.from_dict(x) ...]`（`:923-933`）；
- base：`json.dumps([p.to_dict() ...], ensure_ascii=False, indent=2)`（`wizard.py:4834-4836`；机械补写同形 `:4400-4402`）。

落点同为 `<生成目录>/segments/plan.json`。`tools/ledger.read_plan_segment_count` 只取 `len(data)`（`tools/ledger.py:271-280`），所以导演台的帧版 plan.json 只要仍是数组，这个口不会炸。

## 2. 提示词产出

### 2.1 base 写段（`segment_prompts.py`）——**「六节外壳」在 base 不成立**

先纠正一个容易带进 #103 的误读：base 分段产物的外壳是**对齐指令行 + 三节**，不是六节。

- 首行恒为 I2VA 锚定行：`SEGMENT_ANCHOR_VARIANT = "I2VA"`、`I2VA_ANCHOR_LINE = ALIGN_TEMPLATES["I2VA"]`（`:334-335`，理由 `:327-333`：每段只喂一张图、逐段执行时由桥接链取代、不得按 `brief.variant` 套模板）；
- 三节：`integrated_multimodal_description` / `overall_soundscape` / `non_diegetic_music`（`h3_validator.py:69-73`）；
- 每个 `[Shot N]` 块必须以官方 edge-stability 句收尾（模板 `:573-576`，常量 `h3_validator.py:56-59`）。

两条产出路径**共用同一份纪律核心**，但请求模板不同：

| 路径 | 触发 | 请求组装 | 角色 |
|---|---|---|---|
| 规划式（v2） | `plans` 非空 | `_SEGMENT_V2_INSTRUCTION`（`:546-593`）+ `build_segment_v2_request`（`:758-813`） | `role_segment_writer`（`:45`） |
| 回退式 | 规划失败/文件缺失 | `_REWRITE_INSTRUCTION`（`:469-489`）+ 内联拼装（`rewrite_segment_prompt` `:492-539`） | `role_segment_rewriter`（`:46`） |

两者共用：`_WRITING_WORDLIST`（`:467`，只取一次、两个模板插同一个常量）、`_revision_block_for_request`、`_visual_decision_block_for_request`、`_frame_anchor_note`。**「两条路径同改同测」是本仓反复吃过的教训**（`:460-466` 注释、记忆条目 `h3-segment-two-paths`）。

`build_segment_v2_request` 的注入顺序（等于优先级叙述）：编号/时间窗/`shots_in_segment` → 剧情概述 → **末态声明**（`_segment_end_state_block_for_request` `:735-755`）→ 帧锚（`_frame_anchor_note`）→ 修订块 → 时间窗外剧情禁区（`:786-790`）→ 镜头原文（`:773-779`）→ 画面决策块（`:812`，刻意排最后，理由 `:807-811`）。

产出校验：`validate_segment`（`:820-840`）= `validate_base(variant=SEGMENT_ANCHOR_VARIANT)` + 一条「时间戳疑似绝对片时」warning（`:849-862`）。重写预算 `MAX_SEGMENT_ATTEMPTS = 2`（`:817`），耗尽仍不合格**交回原文**而不是 None（`:873-880`）。

### 2.2 ref 写段——真正的六节外壳 + 注记

六节：`subject_definitions` / `summary` / `retention_analysis` / `detailed_description` / `overall_soundscape` / `non_diegetic_music`（`h3_validator.py:61-68`）。

- 组装器 `assemble_ref_segment(...)`（`segment_prompts.py:1037-1064`）：定义块**由代码原样拼入**、不让 LLM 重写；`detailed_description` 顶部插入 `annotations`。
- 注记三句是 canonical 常量：`_REF_TIMELINE_NOTE`（`:923-926`）+ `_REF_START_STATE_PREFIX` / `_REF_END_STATE_PREFIX`（`:927-928`），渲染入口 `render_ref_segment_annotations`（`:959-971`）。**产出、请求提示、校验判据三处同取这一个函数**（`:951-956`、`validate_ref_segment` `:1106-1108`），这是本仓「同一契约不许两处口径」的正例。
- 归一化 `normalize_ref_segment_output`（`:1321-1354`）：剥掉 LLM 自写的注记行（切点由 `split_ref_segment_detailed` `:974-988` 判定，形态从模板**派生** `:991-999`），定义块换成本段作用域原文，再重拼。
- 校验 `validate_ref_segment`（`:1067-1153`）在 `validate_ref` 之上加五条 error：注记缺失、起止状态缺失、定义不全、留存分析悬空标签、指代前文（`_ANAPHORA_RE` `:933-943`）；另加「锚定行混入即作废」（`REF_SEGMENT_ALIGN_BANNED` `:1096-1103`）。
- 机械地板 `_mechanical_segment`（`ref_segments.py:478-493`）：`rebase_ref_shot_blocks` 把绝对片时重基成段内相对（`segment_prompts.py:1421-1435`）。

写段两条路径同样共用纪律块 `_REF_SEGMENT_DISCIPLINES`（`:1160-1196`）：v2 用 `build_ref_segment_v2_request`（`:1223-1264`），回退用 `rewrite_ref_segment_prompt`（`:1267-1306`）。角色名 `role_ref_segment_writer` / `role_ref_segment_rewriter`（`:46-47`），改写轮另有 `role_ref_segment_reviser`（`ref_segments.py:1198`）。

### 2.3 三个注入块分别是什么

| 名字 | 位置 | 读者 | 作用 |
|---|---|---|---|
| `render_revision_context(state)` | `segment_prompts.py:362-385` | **写段**（经 state）、**规划**（经显式入参） | 累积用户修订 + 优先序声明；只取 `pending_revisions`（已落地的设定级修订不再重复） |
| `frame_anchor_context(state)` | `:612-618` | **规划层** | 首/尾帧读图结果，一段纯文本 |
| `_frame_anchor_note(is_first, is_last, state, segment_index)` | `:657-697` | **写段层** | 段 1=用户提交帧、中间段=桥接帧（按 0-based 段号取 `bridge_frame_descriptions`）、末段=尾帧；附双向一致性纪律 `_FRAME_CONSISTENCY_DISCIPLINE`（`:625-634`） |

注意 `_frame_anchor_note` 的段号是**权威**：传了 `segment_index` 就由它派生 `is_first`，不许调用方给自相矛盾的组合（`:676-680`）。优先级常量只有一个：`PRIORITY_TIERS`（`:354`），三个块都引它、不另写同义句。

> 导演台没有桥接帧，这三个块里只有「修订」有直接对应物；`_frame_anchor_note` 的语义要换成「段间引导（无图）／首帧图／尾帧参考图」三态，**不要照抄文本**。

### 2.5 校验器的路线分叉（#103 的隐藏雷）

`validate_prompt(text, mode, ...)`：`if mode == "ref": validate_ref else validate_base`（`h3_validator.py:595-599`）。同理 `output/assembler.assemble_and_repair` 用 `REF_SECTIONS if mode == "ref" else BASE_SECTIONS`（`output/assembler.py:23`）。

也就是说 **`mode="director"` 落进这两处会被当成 base 校验**。今天不会发生（导演台在 `run_wizard` 就短路了，`wizard.py:514-520`），但 #103 一旦把导演台接进阶段 2 或共用组装路径，它会**静默按三节验收或强行补齐三节**。必须显式早退或加分支，不能靠「反正不走那条路」。

## 3. 阶段 1/2 与产物目录

### 3.1 阶段函数返回

- `run_stage1(...) -> tuple[state, model, agents]`（`graph/pipeline.py:259-318`）；导演台模式随图下发：`"director_mode": brief.director_mode`（`:289-291`），且**故意不在持久化白名单**（`session_store.py:87-90`）。
- `run_stage2(...) -> tuple[state, 最终提示词]`（`pipeline.py:356`）；组装后经 `assemble_and_repair` 修形（`:412`、`:452`、`:458`），带断点 `stage2_checkpoint`。

### 3.2 「(job, report) 二元组」的真身

spec 说的「多参准备口」= `prepare_ref_segments(...) -> tuple[RefSegmentJob, str]`（`ref_segments.py:526-537`，内部 `_build_ref_job` `:496-523`）。**job 只定案边界、一段都不写**（`RefSegmentJob` `:158-196`），正文由 `job.write_segment(n)` 在陪跑轮到该段时才写（`:252-276`）；报告由 `format_ref_segment_report` 出（`:556-587`）。批式入口 `deliver_ref_segments` 返回 `(RefSegmentResult, str)`（`:540-553`），两者同形（`RefSegmentResult` `:115-144`）。

> #102 的「准备口」照这个形状做即可：`prepare_director_segments(...) -> (DirectorJob, report)`，`DirectorJob` 暴露 `plans / segment_paths / total_s / write_segment(n)` 这些同名只读属性，收尾与账本代码就不用按类型分叉（原因写在 `:166-171`）。

## 4. 账本

### 4.1 两本账，同形不同路

| | base | ref |
|---|---|---|
| 文件 | `segments/shot-ledger.jsonl`（`shot_ledger.py:28`） | `segments/segment-ledger.jsonl`（`ref_segments.py:708`） |

| 取数 | 全部行 | **必须传 `event`**（`read_segment_ledger` 的 `event` 是必填参数，`:847-873`） |
| 另一本 | `segments/gate-log.jsonl`（锚帧人裁，`wizard.py:3342-3355`） | 无 |
| 轮转 | `rotate_shot_progress` 挪账 + `progress.json`（`shot_ledger.py:175-200`） | `rotate_segment_ledger` 只挪账（`ref_segments.py:1009-1030`） |

### 4.2 通过行长什么样

base（`shot_ledger.py:61-70`）：

```json
{"segment": 2, "start_s": 4, "end_s": 9, "video": "D:\\...\\seg-02.mp4", "sha256": "…", "at": "2026-10-…Z"}
```

ref（`ref_segments.py:757-767`）：

```json
{"event": "output", "segment": 2, "start_s": 4, "end_s": 9, "video": "D:\\...", "sha256": "…", "verdict": "pass", "at": "…"}
```

另外两类 ref 行：`encounter` = 语义层每次遭遇（`verdict/outcome/attempt/first_frame/last_frame`，`:794-803`）；`rewrite` = 改写轮次（`round/feedback/prompt_before/prompt_after`，`:827-835`）。

**判据**：「行在＝这段过了」建立在**行写全了**之上——base 的 `passed_shot_rows` 会拒收缺 `video/sha256/at` 或相对路径的行（`shot_ledger.py:119-131`），ref 的 `read_ref_handoff_progress` 另核 `verdict == "pass"`、段号越界、跳号（`ref_segments.py:1066-1088`）。

> spec #100 的账本口径（「沿用既有段产出账，只写 `output` 行（另加 `rewrite`），不写 `encounter`」）**正好是 ref 那本的形状**；直接复用 `log_segment_output` / `log_segment_rewrite_round` / `passed_segment_rows` / `read_segment_ledger` 即可，不要新建第三本账。

### 4.3 缓存路径（目前只在文档里）

段缓存帧路径 `output/minimax_seg_cache/<缓存名>_<节点id>/seg_XXXX.frames.mkv`（`CONTEXT.md:390`；`docs/adr/0024` 只讲帧数）。**代码里 grep 不到 `minimax_seg_cache` / `mmxpack` / `timeline.json`**——这是 #105 起才实现的东西，本笔记引用它只是术语对齐。

### 5.1 `H3_TIER_FRAMES` 与校验入口（`tools/preflight.py`）

### 5.2 `frame_auditor` / `frame_sanity` / `frame_match` 各做什么

| 模块 | 干什么 | 关键入口 |
|---|---|---|
| `tools/frame_auditor.py` | **读图**：调视觉模型描述首/尾帧实际画面，产出 `FrameAudit` 供锚定 | `required_frames` `:26-28`、`audit_frame_images` `:58-64` |

### 7.3 具体的坑（每条都有现场）

1. **30 秒精确落位的算术陷阱**。ADR 给的样例是「段1 声明 108（无引导，导出 108）、段2–5 各声明 141（导出 153），合计 720」（ADR `:37`）。注意 **141 = 17×8+5**（落在 align 网格上，+12 后 153 = 17×9），而 **108 既不是 17k 也不是 17k+5**。也就是说：网格约束只对有引导段成立，**无引导段的声明帧不受网格约束**。若 #102 顺手给所有段都套网格，720 一定凑不出来（107 + 153×4 = 719）——AC1 会被自己的校验器判红。另外「无引导段的 align（17k+5）如何与其声明帧 108 协调」ADR 没写，属**待实测**（spec 已有「待实测」一节）。
2. **别给 `SegmentPlan` 加帧字段**（§1.1）。它是 base/ref 共用契约，`final_film._coverage_problem`（`:79-99`）与 `validate_shot_progress` 都按整秒判。
3. **`mode == "ref"` 的二元分叉会静默把 director 当 base**：`segment_planner.py:196/236/268/282`、`output/assembler.py:23`、`h3_validator.py:597`、`agents/__init__.py:193`、`graph/nodes.py:80/315/1023`、`graph/pipeline.py:217/243`。**凡新增一条路线，都要么显式早退、要么加第三支**；靠「新路线不会走到这里」是最坏形态（本仓「规则在、接线不在」已犯九次）。特别是 `nodes.py:315` 的 `if not brief.is_ref: return {}`——r2v/rv2v 需要资产图提示词，这条会把它们静默跳过。
4. **`run_wizard` 的导演台短路点**（`wizard.py:514-520`）是 #102/#103 唯一可接的入口，**必须早于 `_phase2_collect_and_finish`**（注释已写明理由）。接入后要新增会话状态（仿 `STATUS_SEGMENTED_RUNNING` / `STATUS_REF_SEGMENTS_RUNNING`，`session_store.py:40-44`）——**不能复用老状态值**，理由写在 `:35-39`（复用值会让导演台会话被老路线的续接分支接走）。
5. **追加式账不随目录覆盖**：同一 GEN 复用目录时产物会被整份覆盖、账不会；新一次交付开头必须 `rotate_segment_ledger`（`ref_segments.py:1009-1030`，现场 `wizard.py:2899-2902`）。导演台同样会复用 GEN，别忘这一步。
6. **段号/时长口径只有一份**：ref 那边把「全片时长」固定在 `RefSegmentResult.total_s`（必填、不给默认，`ref_segments.py:121-126`），因为规划器允许末段略超 total（`segment_planner.py:279-281`）。导演台是帧真源，等价字段应是 `total_frames`（＝总时长×24），**不要**从 `plans[-1].end_frame` 反推。
7. **两种写段路径要同改同测**（规划式 + 回退式）。本仓为此掉过两次档（`segment_prompts.py:460-466` 注释；`h3-segment-two-paths` 记忆）。导演台若也有规划失败回退，纪律块必须是同一个常量。
8. **守卫要从常量派生**：注记形态 `_timeline_note_shape`（`:991-999`）就是正例——字面重抄一份，模板一改守卫就永不为红（`guard-shape-must-derive-from-constants` 记忆）。
9. **`_drain_stdin()`**：长阻塞调用之后必须清行缓冲，否则之后所有问答错位（`wizard.py:4517-4520`）。新的长步骤（规划、打包、写段）都适用。
10. **零变化护栏**：#102/#103 的提交必须让 base/ref 的全量测试零变化。现存护栏：`tests/test_base_prompt_bytes.py`（base 系统提示词逐字节不变）、`tests/test_official_references.py` + `tests/test_role_prompts.py`（官方原文唯一来源）、`tests/test_director_route.py`（路线判据严格小写、`director_mode` 随图下发且不进持久化白名单）。新增判据不得改 `is_ref_mode` 语义（spec #100「回归护栏」）。
11. **成本账**：新角色名要单独取（`SEGMENT_PLANNER_ROLE` 的写法，`segment_planner.py:300-302`），并且记住直调路径的开流式必须同时开 usage 上报（`stream_usage_required-when-streaming` 记忆：指标看着在、数是空的，不报错）。
12. **`plan.json` 路径冲突面**：`tools/ledger.read_plan_segment_count` 只读 `len()`（`:271-280`），导演台若沿用 `<生成目录>/segments/plan.json` 且仍是数组，不会炸；但若改成 dict（如 `{"total_frames":…, "segments":[…]}`），这个口会静默返回 `None`。**要么保持数组，要么同步改读取口**——别留两种形态。
