1. **机械回退路径从不写 `segments/plan.json`**（`wizard.py:3958-4071` 全段无 plan 写入），

   `_verify_last_frame`）——#97 的"不重问段路径"不能只靠"循环跳过"实现。

### A2 调用链

自动（向导）：

```
_run_ref_segment_handoff(...) -> True            # wizard.py:2432
  -> _finish_ref_handoff(result, dir, brief, state, finished)   # wizard.py:2401
     -> _assemble_ref_final_film -> assemble_final_film(...)    # wizard.py:2382
     -> print(format_final_film(film))
     -> if finished: save_session(status=STATUS_COMPLETED)      # wizard.py:2409
```

首跑：`_phase2_ref_finish` → `_finish_ref_handoff`（`wizard.py:2853`）。
续跑：`_resume_ref_handoff` → `_finish_ref_handoff`（`wizard.py:3840`）。
**两处共用同一个收尾函数**，这是 #92「拼接只放在收尾处」在多参侧已经成立的形态，
base 侧要照抄这个形状（`_run_long_form` 是 base 的对应点，见 §B4）。

手动：`main.py:499` 分派 → `_run_ref_concat`（`main.py:345`）→ 同一个
`assemble_final_film`；`--replace` 在内存里改 `rows[N]`（`main.py:393-395`），
并当面说破"未经本系统验收"。

### A3 不变量与坑

- **「未通过即不拼」住在 `assemble_final_film` 里**（`ref_segments.py:1161`），不在调用方的
  `if` 里。这是本仓"规则在、接线不在"反复吃过亏的地方，base 侧不许改成调用方判断。
- 段序取 `plans`（`ref_segments.py:1172`），**不取 rows 的插入顺序**。
- 覆盖判据是「`plans[-1].end_s >= total_s`」（`ref_segments.py:1129`），不是"各段之和＝总时长"——
  规划器允许末段留余量（`segment_planner.py:266`）。
- SHA 核对是 `if recorded and sha256_file(video) != recorded`（`ref_segments.py:1179-1185`）：
  **账上没记 sha 的行会静默放行**。base 侧若要"必须对得上"，得自己收紧。
- 段数=1 退化为 `shutil.copy2`（`ref_segments.py:1189-1194`）。
- 实测时长只做**只报短**告警（`ref_segments.py:1204`），容差 `len(sources) * (1/24)`。
- `merge_videos` 的 `find_ffmpeg()` 在 `try` **之外**（`seam_audit.py:168` vs `:174`），
  所以 ffmpeg 缺失时 `RuntimeError` 会穿过 `assemble_final_film` 冒到顶层——
  与 spec「ffmpeg 定位失败要转成拼接失败」**当前不符**（见 §F-2）。
- `merge_videos` 在输出目录留 `concat_list.txt` 并在 `finally` 删除（`seam_audit.py:165,182`）；
  有用例钉着（`tests/test_seam_audit.py:134`）。
- `_FINAL_FILM_FRAME_S` 写死 1/24，而 spec 要求 fps 取实测元数据（见 §F-8）。

### B3 末段视频的关键事实（已核实）

- **第 1..N-1 段**：视频在 `_acquire_bridge_frame` 里收集。
  - v2 在**本段末尾**调（`wizard.py:4296-4308`，`judged_video_segment=position+1`，
    `anchor_segment=position+2`），条件 `position + 1 < total`。
  - 回退在**下一段开头**调（`wizard.py:3986-3998`，`judged_video_segment=position`，
    `anchor_segment=position+1`）。
- **末段（第 N 段）**：只在有尾帧（`FL2VA` / `L2VA`）时，才由 `_verify_last_frame`
  索要（`wizard.py:3672` 提问、`:3677` 剥 `-end` 帧）。**I2VA / T2VA 时
  `promised is None`，`wizard.py:3666-3667` 直接 `return True`——从不索要末段视频。**
- 后果（对 #94/#96 是结构性的）：I2VA/T2VA 下系统手上没有第 N 段视频的路径，
  段产出账的 `output` 行凑不满 `1..N`，`assemble_final_film` 会判"第 N 段尚未通过"。
  若要在两条变体上都出成片，必须**改"末段也要交回视频"**（或另定"末段不参与拼接"
  的语义），这是票面没写的决策点，见 §F-4。
- **视频路径目前不外流**：`_acquire_bridge_frame` 与 `_verify_last_frame` 都只返回
  `bool`。视频路径只在函数内的局部变量 `video_raw` 里，落盘记录只有
  `gate-log` 的 `bridge_frame_path`（帧图，不是视频）。#94 要记账就必须改签名
  （返回路径 / 接受一个回调），见 §F-5。

### B4 收尾点在哪（#96/#97 的落点）

`_run_long_form`（`wizard.py:3719`）是 base 唯一的收尾：

```python
save_session(dir, brief, state, status=STATUS_SEGMENTED_RUNNING)   # :3732
finished = _run_segmented_flow(...)                                 # :3733
if not finished: print("[续接] ..."); return                        # :3734-3737
save_session(dir, brief, state, status=STATUS_COMPLETED)            # :3738
```

- 规划式与机械回退式**都**在这一个函数下面（`_run_segmented_flow` 内部分叉），
  所以"拼接只放收尾处"在 base 恰好有一个天然落点：`:3734` 与 `:3738` 之间。
- 但 #97 要"拼接失败不标完成、重进直接续拼"，这里有个现成的陷阱：
  **当 `done == total` 时，两条 flow 的 `for` 循环都直接跳过，却仍然无条件调用
  `_verify_last_frame`**（v2 `:4326`、回退 `:4064`）。FL2VA/L2VA 下这就是
  "再问一次末段视频路径"，与 #97 AC 直接冲突。续拼入口需要在这两处之前加
  "全段已过、只差成片"的短路。
- base 现在的收尾话术就是要被替换掉的那句：
  v2 `wizard.py:4331`、回退 `:4070` ——「✓ 全部 N 段已人工确认完成。可在剪辑工具中按顺序拼接 segments/ 下的各段输出。」
