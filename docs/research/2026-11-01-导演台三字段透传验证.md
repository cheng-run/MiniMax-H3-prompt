## 0. 结论（先说能行动的那句）

**能只在提示词层改，不需要插件层或节点层配合。**

三条支撑：

1. ComfyUI 的 MiniMax H3 节点把 `prompt` 字符串**整段原样**交给 `clip.tokenize`，
   中间没有任何按字段名切分、按句数截断、按 token 截断或加正文前缀的代码
   （`comfy_extras/nodes_minimax_h3.py:156`、`:360`）。
2. 分词器把整段当**一段裸文本**（无 chat 模板、无权重解析、`max_length=99999999`），
   字段名只是普通子词（`comfy/text_encoders/minimax.py:197`、`qwen3vl.py:151`、
   `comfy/sd1_clip.py:491,585-588`，逐条见判据表）。
3. **r2v 的六节格式和它走的是同一条代码路径**：`subject_definitions:` … `non_diegetic_music:`
   这种「段头当头」的文本本仓已经在产出并落盘
   （`output/sessions/…-e49b3dae/GEN001/director/segment-01.md:1,21,24,35,45,48`），
   而插件对 r2v 与非 r2v 的送法完全一致（`nodes/conditioning.py:141-171` 都是
   `prompt=prompt` → 官方 `execute` → `clip.tokenize`）。三字段只是节数更少、同一形态。
   **注意边界**：那份 r2v 会话没有 `pack/` 目录，所以这只能证明「本仓产出六节形态」，
   不能证明「六节文本已实跑出视频」——见 §2 末尾与 §4。

但「只改提示词层」指的是**我们这边的写法 + 我们自己的校验器和模板**，不是「只改一句提示词」：
本仓的导演台校验器现在**主动拒绝**非 r2v 段出现三节段头
（`src/minimax_h3_prompt/director/prompts.py:302-310`），模板也明写「产出单段正文」
（`src/minimax_h3_prompt/prompts/segment_writer_director.md:32-35,37-42,44-50`）。
这两处不改，改了写法也会被判红。

## 3. 三个问题的直接回答

### 问题 1：节点是否原样透传？

**是。** 唯一非透传的动作是节点在正文**前面**插入参考素材标签（`<Picture i>: ` / `<Audio j>: ` / `<Video k>: ` / `<%.1f seconds>`）与视觉块；正文本身逐字节进入 Qwen 分词器。无按字段名切分、无按句数截断、无 token 截断、无 system 前缀。
超长时是 `raise ValueError`（`minimax.py:160-162`），不是静默截断。

### 问题 2：三字段名是否被当结构 / 会不会污染？

**不被当结构，也不会与节点拼的文本冲突。** ComfyUI 与 Director 插件对这三个词零感知，字段名就是普通正文。
「模型会不会当画面内容读」**未证实**（禁止采样）；文献侧依据是官方 `base-en.txt:20-40` 本身就把字段名写进正文。

真正会造成「字段名位置不对」的三个来源都在**我们自己这边**：

1. `reinforce_*` 的前置标签（`plan.py:603-624` / `:1029-1036`）——正文里没有 `<Picture`/`<Video` 时把标签顶到最前；
2. 公共词拼接（`plan.py:202-212`）——已被本仓 `pack.py:288-304` 的 `commonEnabled === false` 守卫封死；
3. 提示词增强（`prompt_enhance_runtime.py:88-90`）——开启时整段被 LLM 改写，三字段不复存在。

### 问题 3：能否只在提示词层做？

**能，插件与节点一行都不用改。** 但「提示词层」在本仓包含三件事，必须一起动：

| 要改的 | 位置 | 不改的后果 |
|---|---|---|
| 写段模板 | `src/minimax_h3_prompt/prompts/segment_writer_director.md:32-35,37-42,44-50` | 模型继续只写单段 |
| 导演台校验器 | `src/minimax_h3_prompt/director/prompts.py:302-310` | 新写法被判 `DIRECTOR_SECTION_PRESENT` error，走重写循环直到预算耗尽 |
| 设计口径留痕 | `docs/design/2026-10-29-导演台路线实现设计.md:124`（或新 ADR） | 「音频并入正文」的旧决策与代码矛盾，后来人按旧的改回去 |

改动量最小的可行形态（照 r2v 的既有做法）：

```
integrated_multimodal_description:
Segment N of M, covering A.AAAs-B.BBBs of the full C.CCCs video.
[Shot 1] …
overall_soundscape:
…
non_diegetic_music:
N/A
```

即：**时间轴注记挪进 `integrated_multimodal_description` 段内**（r2v 的注记就落在 `detailed_description` 内，`segment-01.md:35-36`），
`DIRECTOR_TIMELINE_MISSING`（`prompts.py:327-332`）仍按「正文包含注记」判，不必改判据。

三个待定项（属于设计选择，不是阻塞项）：

1. **要不要 `reinforce_*` 前置标签**：三字段文本通常会在正文里写 `<Picture N>`（i2v/fl2v 的锚定句会提），但若只写三字段不带标签，插件会前置标签串。要么在正文里显式带标签，要么接受「标签在前」。
2. **i2v/fl2v 的官方 instruction 行**：`base-en.txt:22-40` 要求 instruction 是**第一行**，而 ComfyUI 会先拼 `<Picture 1>: <vision block>`（`nodes_minimax_h3.py:147-157`）。这两者已在官方 fl2va 呈现里共存（`comfy/text_encoders/minimax.py:6-13` 的 docstring 描述的就是 `"<Picture 1>: " <vision> … <prompt>`），所以不冲突；但要不要写 instruction 行是独立决策，`prompts.py:320-325` 现在把它判 `DIRECTOR_ALIGN_LINE` error。
3. **提示词增强**：若保留该开关，三字段会被改写掉；要么默认关闭、要么给增强模板加「保留三字段外壳」的约束。
