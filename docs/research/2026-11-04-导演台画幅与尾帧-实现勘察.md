## 产线入口与调用链

- 导演台路线入口：`ui/wizard.py:764` `_run_director_flow`。阶段 1 之后由
  `ui/wizard.py:572` 分派进来。
- 开场首帧/全片尾帧收集：`ui/wizard.py:702` `_collect_director_opening_still`，
  落盘由 `_store_director_still`（`ui/wizard.py:670`）负责：
  - 首帧 → `director/assets/01/start.<ext>`
  - 全片尾帧 → `director/assets/film-end.<ext>`（`segment=None`，不在任何段目录）
- 段规划：`_run_director_flow` 调 `director/planning.py:259` `plan_director_segments`，
  请求在函数体里拼（`frame_block` / `revision_block` / `shot_table`）。
- 写段：`_run_director_flow` 调 `director/prompts.py:856` `write_director_segments`
  → `build_segment_request`（`director/prompts.py:455`）。
- 逐段陪跑：`ui/wizard.py:1386` `_run_director_segment_handoff`。贴回视频的问句是
  `ui/wizard.py:1227` `_prompt_segment_video`（只数帧，不知道段号与锚图）；判定
  `judge_video_evidence` 通过后、`ledger.log_director_output` 落账前是**回贴画幅核对**
  的插入点。
- 续接：`ui/wizard.py` `_resume_director_handoff` 也走同一个 `_run_director_segment_handoff`，
  所以回贴核对只接一处即可覆盖续跑。

## 测试与守卫的既有做法

- 流程问答：`tests/conftest.py` 的 `fake_prompt` 必须按**问题文本**匹配作答；恒返回
  空串会撞重问（本仓多次实测）。新增预检确认问句要给既有驱动点补答案。
- 「知识到了模型眼前」：用**记录型桩模型**抓出站 system/user 消息，断言描述/规则
  在其中；不要猜图结构（本仓既有做法，见 `tests/test_director_prompts.py`、
  `tests/test_segment_writer_watchdog.py`）。
- 回贴路径的接线用例：打桩 `_prompt_segment_video` 返回 `video` 动作 + 宽高不符的
  元信息，断言段账没长、打印里有期望／实际。
- 变异检验：新守卫要往 `scripts/mutation_check.py` 的 `MUTATIONS` 补一条，并在
  `scripts/check.sh mutate` 下确实变红；没有变异检验的守卫不算守卫。
- `CONTEXT.md` 词条守卫：`tests/test_context_glossary.py`（四条不变式）。词条形态照
  既有 `**画布（canvas）**:` 写；流程总览里「画布只问一次（成片画幅）」在第 19 行。
- ADR 引用写法：本仓 `ADR NNNN`，外部 `ADR-NNNN`；本 spec 不要求新 ADR（#161 才要）。

## 已知坑（本仓反复咬过的）

1. 给流程加新问答会带走既有用例（`fake_prompt`、位置语义、直接调流程函数的用例）。
2. 同一契约不许两处口径：画幅判定只写一份纯函数，预检与回贴共用；容差按比例相对差
   （默认 5%），不按像素。真实样本：1920×1088 vs 864×480 ≈ 2% 通过；
   1920×1088 vs 480×864 ≈ 218% 失败。
3. 规划器契约是「末段可略超 total」——不要用「各段之和 = 总时长」这类另一处口径去
   核对画幅。
4. 提示词文件被 docs 按行号引用：**只追加到列表末尾**，不插中间。
5. 改代码前先开分支；提交只圈定本票路径，不用 `git add -A`；工作树提交永不 push。
