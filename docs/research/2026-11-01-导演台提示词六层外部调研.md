## L1 剧情 / 叙事结构

### 官方
MiniMax H3 官方指南**没有任何体裁或节奏条款**。全篇唯一可落地的叙事判据：

> A cut should introduce new information about the subject, space, state, viewpoint, or time. If only the distance or a slight angle needs to change, prefer camera motion.
> — `VIDEO_PROMPT_WRITING_GUIDE_base_en.md` §4.2

### 可落条目
- 每段必须转向：段尾状态与段首状态在某个价值上相反（McKee）。
- 全片只讲一个角色的一个改变，每段为它推进一格。
- 品牌/产品第一次出现在全片前 1/3；末段给 CTA。
- 强度曲线必须有回落：强开场 → 主动降速 → 再爬升 → 峰值。
- 一镜一个信息点，读完即切。

### 注意
- **没有任何权威的「第几秒该发生什么」表**；所有秒级数字都是经验值。
- 「每镜信息点数」没有测量研究。

## L2 视频提示词与遵从度

### 官方结构与写法（H3）

三字段：
- `integrated_multimodal_description:`（内含 `[Shot N] At MM:SS.mmm`）
- `overall_soundscape:`（1–4 句，单段，无时间戳）
- `non_diegetic_music:`（1–3 句）

路径写法（官方 §3）：
- **FL2VA**：first-frame state → observable intermediate changes → progressively narrowing differences → last-frame state
- **I2VA**：first-frame anchor → action onset → continuous development → result or reaction
- **L2VA**：plausible preceding state → explicit action and transition path → gradual convergence in the final shot → last-frame landing

其他官方要点：
- 每个细节都必须对应「看得见或听得见」的东西（§4.1）。
- 风格与初始构图写在 `[Shot 1]` 开头。
- 幅度/速度只有有意义时才写；medium amplitude / normal speed 默认省略（§4.3）。
- 音频三层不可合并；对白/歌词/画面文字保留原文；画外音后要写「嘴唇不动」。
- **H3 不要写负面清单**（ComfyUI 官方：`cfg=1`，无负分支）。
- H3 无公开字符/token 上限；「2000 字符」是 Hailuo 2.3/02 旧 API 的限制。
- 模型卡：「H3-Context-IR is critical to the quality of the final output」——该组件不随开源发布，本地 ComfyUI 等于自行承担这层职责。

出处：
- HF `MiniMaxAI/MiniMax-H3` 的 `docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md`（与 GitHub skill 版逐字节相同）
- `docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide`

### 遵从度：为什么会被忽略
- 同段多条指令竞争；删装饰形容词，关键主体/动作/镜头前置（Seedance 排查页）。
- 长而复杂可能更差（RAPO，CVPR 2025）。
- 位置偏置（Lost in the Middle，TACL 2024）——LLM 结论，视频侧未证实。
- 相机是全局最弱维度（ETVA，ICCV 2025：最高 0.474）；物理 0.600。
- 一镜一动作一运镜；4–6s 段最多 2 拍（Sora 官方）。

### 未证实
- 「H3 文本编码器把长提示词压成固定 latent、后半句静默丢弃」——无来源。
- 「提示词越长越好」——官方导向长描述，但 DetailMaster 实测遵从度随长度下降。
- 「否定句会被当正向词读」——官方只说「没有负向字段，改成描述想要的场景」，没这么说。

## L3 运镜

### 动机判据（教材）
- 一切运动都要有动机；推/移入有天然动机（人眼要凑近看），拉出是「非自然运动」，必须另有理由（Bowen & Thompson, *Grammar of the Shot*, Ch.6）。
- 无动机的运动会让观众出戏（Blain Brown, *Cinematography*）——**注意：此句来自检索快照，原页未打开，等级降为「未逐字核实」**。
- 静＝交代地理；摇＝随进展增益或揭示更多（Mascelli, *The Five C's*，OCR 文本）。
- 空间推进序列：远景建立 → 中景引入人物 → 特写强调（Mascelli）。

### 写法（官方 H3）
- 运镜表达三要素：motion type / amplitude / speed；medium 与 normal 默认省略（`base-en.txt` §4.3）。
- 白名单 12 类（Push In / Pull Out / Tracking / Pan / Tilt / Truck / Pedestal / Arc / Zoom / Static / POV / Shake）。
- **终点构图句**（官方 FL2VA 例文）：`… and settles into the pose, spacing, and composition established by Picture 2 at the end of the shot.`
  - 该句在**上游官方原文件 line 203 与仓内 line 209 都存在**（行号差 6 来自本地增补），是真官方原文。

### 社区补充
- 运镜词单独不足以控制机位；3D 预演/参考视频更可靠（X 多条）。
- 同速参照物（「与人物前进同速拉远」）与背景地标是有效补丁（Reddit 实测）。
- 否定式运镜无效，改写成「静态机位 + 画面里正在发生什么」。
- dolly zoom / crane / handheld 在 Veo 官方是合法词，**H3 不是**。

### 未证实
- `large amplitude` 与画质/闪动的关系没有实测。
- 「两米五秒可以、三十米不行」来自第三方教学站，无一手来源。

## L4 尾帧图词（图生图编辑）

### 官方编辑原则（Qwen）
出处：`github.com/QwenLM/Qwen-Image-2.1/blob/main/prompt_rewrite/prompts/system_prompt_edit.txt`

- 只改用户点名的属性，并推到明确无误；其余保持输入保真。
- 保留句：**按类型/位置/作用**点名，不描述外观；优先一条毯式句。
- 身份：来自参考图时**指向那张图**，不要用文字描述五官。
- 写成指令：以操作开头，不写成品描述。
- 未解算的程度词必须消解（「前方几步」不合格）。
- `viewpoint/canvas transform` 属于「改这张图」——约束，不是重造。
- 输出：单段、无换行、不写分辨率/比例；用肯定式表述。

### 其他模型
- **FLUX**：点名目标 → 说清改成什么 → 列清要保留的细节（**要列全主要元素**，与 Qwen 相反）。
- **Google/Nano Banana**：`change only X, keep everything else exactly the same`；语义负向（用正向描述替代「no X」）；迭代漂移就重开会话。
- **OpenAI**：`change only X` + 列保留项；要求像素级一致时用 composite，不靠提示词。
- **Seedream**：`Reference Target` + `Generated Scene Description`；避免模糊代词。

### 关键文献
- arXiv 2610.39179（2026-10-29）：端点图保留源图布局 → 下游全帧条件化把它变成「末帧必须回到源位置」的硬要求，称为 **spatial over-specification**；表现为运动被压 / 背景反向运动 / 硬切。
  - **边界**：论文的修法在**条件化层**（Partial），不是删提示词就能解决。
- ICCV 2025 多轮编辑：只用上一轮结果会导致漂移；双条件（原始图 + 当前图）可锚回。

### 社区
- `IMAGE EDIT, NOT A REGENERATION` / `STRICT IMAGE MASTER` / `ONLY identity source`。
- Qwen 中文原生命令执行更好；`add/replace/remove` + 「其余不变」有效。
- 别在提示词里提不想改的东西（与 BFL 相反，按模型分档）。

### 未证实
- 「写地标距离/地面线能治原地踏步」没有官方出处，且与 arXiv 2610 的机制可能冲突。
- 「删掉背景保留句就能解决接缝跳变」是推断，未经实验。

## L5 关键帧图词

### 官方
- **没有任何厂商公开「如何画一张用作视频首帧的图」的规范**；官方只讲「首帧是什么/怎么用」。
- Runway：输入图定义构图、主体、光线与风格；i2v 提示词应只写运动。
- MiniMax API：`first_frame_image` 与 `prompt` 并列；官方示例只写动作。
- Veo：先用图像模型分别生成起始帧与结束帧，再喂 first-and-last-frame。

### Qwen 官方 t2i 改写提示词（192 行）
出处：`github.com/QwenLM/Qwen-Image-2.1/blob/main/prompt_rewrite/prompts/system_prompt_t2i.txt`

八步：
1. 拆「已定/未定」；
2. 定画幅（比例只写进 `wh_ratio`）；
3. 开场句：`The image is a ⟨vertical/wide/…⟩ ⟨style⟩ ⟨medium⟩ of ⟨subject⟩, ⟨background and palette⟩.`；
4. 走帧：位置短语 8–14 个，约 1/3 句子以位置开头；
5. 覆盖四角、边缘、中心；
6. 画面文字：直双引号、逐条、不可读要写「blurred」；
7. 光线单独成句；
8. 整帧收尾句，只写一句。
- 长度：约 20 句 / 400–500 词；英文正文；观察者语态；不写质量套话。

### 模型档差异
- **Z-Image**：官方说「works best with long and detailed prompts」；在线 demo 的 512 token 是**截断长度**，本地可设 1024；无负向通路；官方 PE 模板 `pe.py`。
- **FLUX**：结构优先于长度；10–30 / 30–80 / 80–300+ 三档；无负向字段。
- **MOSS**：英文；官方负向标签 `nsfw, worst quality, bad anatomy, watermark, jpeg artifact`；CFG 3.0。
- **SDXL**：官方无写法指南；权重语法是生态层。

### 社区（首帧给视频用）
- 留运动空间、姿态在动作中途、三层景深、肢体与身体分离、首尾帧同画幅——**全部只有社区来源，无官方背书**。

## L6 资产图词

### 数量
- H3 单请求参考图 ≤9，混合素材 ≤12；API 前 5 张免费（`platform.minimax.io/docs/pricing/overview`）。
- 收益区 3–5；6–9 是上限不是目标（MACRO / MultiBanana 外推，非 H3 实测）。
- 每类：主角 3 张起步 5 张封顶；配角 1–2；道具 1–2；场景 1（空镜）。

### 视图
- 工业标准 five-point turnaround；AI 侧压成 3–5 张。
- 一张图一个视角；拼板只当规格图，不挂参考槽（Nodaro「Feed Panels, not Sheet」；turnaroundsheet「Keep one face per image」）。
- **B站 5 组对照**（社区一手实测，n=5）：小图里有人脸会抢走参考；动态人物用「正/侧脸特写 + 无头全身」，口播用「超大脸正/背 + 全身」；一图人脸 ≤2。

### 透明底
- Qwen-Image 2.1 原生 RGBA，有固定句式；Z-Image 文档未提；MOSS 靠社区 LoRA。
- **透明底是产出端选择，不是参考端默认**；参考图用无缝中性底更稳。

### 去冗余
- 一张图必须回答一个别的问题；同角度/光照/妆造的第二张不算证据；三张干净胜过十张混杂；一图一职。
