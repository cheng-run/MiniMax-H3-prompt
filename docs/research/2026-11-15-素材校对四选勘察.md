## 一、现状链路（出事的那条）

1. 交图决议：`api/jobs.py:1119` `elif target.kind == step_machine.ACTION_ASSET_IMAGE`
   —— 收 `asset_id` 时把行置 `registered`、写 `proofread_asset_id`（`ASSET_PROOFREAD_KEY`，
   定义在 `api/jobs.py` 顶部的台账键常量区）。
2. 校对作业：`api/jobs.py:3169 _execute_asset_proofread`
   - `describe_image` → `parse_reading` → `compare_descriptions`（`asset_proofread.py:158`）
   - `report.is_clean()`（`asset_proofread.py:141`，**当前把 omissions 也算进「不干净」**）
   - 不干净 → `asset_loop.rewrite_asset_prompt`（`asset_loop.py:291`）**覆盖写回**
     `assets/picture-NN.md` ← **本次要整体删除的路径**
3. 校对收尾：`api/jobs.py:3351 _finish_asset_proofread` —— `_settle_asset(ledger, number, passed)`
   决定 `passed`/`pending` 与下一步（下一件 / 补交口 / 阶段 2）。
4. 桩分支：`api/jobs.py:3237 _execute_asset_proofread_fake` +
   `api/fake_pipeline.py:217 asset_proofread_verdict` / `:235 rewrite_asset_prompt_text`。
   **桩与真身必须同形**：桩只换「谁写/谁判」，台账转移与产物落盘不走第二条路。
5. 前端卡：`frontend/src/features/sessions/AssetImageCard.vue`（整卡）、
   `AssetsTab.vue`（分区与每行）、`SessionDetailView.vue` 的 pending kind 判据。
   改卡的界面语义时同步 `frontend/src/features/sessions/progress.ts` 的 `pendingActionHint`。

## 三、契约与决议

- 决议值闭合表：`workbench_store.py:800 _DECISIONS`（校验）+ `step_machine.py` 的
  `DECISION_*` 常量（真源）。新决议值要改**两处**，且事件类型仍是
  `workbench_store.py:778 EVENT_TYPES` 的**十种闭合集合**（不新增）。
- 待办载荷键表：`workbench_store.py` 的 `_ACTION_ITEM_PAYLOAD_KEYS` /
  `_ACTION_ITEM_ASSET_KEYS`（事件重放要能补回快照）；新字段必须同时进键表与校验。
- DTO：`RefOut`（`workbench_store.py:1225`）、`ActionItemOut`（`:1297`）。
- 契约链：FastAPI → `scripts/export_openapi.py` → `contracts/openapi.json` →
  `frontend/scripts/generate-api.mjs` → `frontend/src/api/generated.ts`。
- 端点是既有的 `POST /sessions/{id}/action-items/{item_id}/resolve`
  （`api/routes/sessions.py:738`）——只加决议值，不新增端点。
  恢复动作按 spec 也不新增端点以外的入口；它是第五个决议值。

## 四、生图档位（#292）

- 档位事实源：台账/state 条目的 `image_model`（`image_routing.ENTRY_KEY`），
  读口 `image_routing.model_of(entry)`；`generation.asset_prompt_for` →
  `AssetPromptVariant.model_family`（`generation.py:1039` 附近）。
- **显示名唯一映射**：`image_config.IMAGE_MODEL_LABELS`（`:71`，`qwen/moss/z_image`）；
  取显示名走 `image_config.image_model_label()`。前端**不许**再写一份名字表——
  后端随 DTO 下发显示名（或下发键 + 由同一份映射在服务端渲染），二者取其一。
- 读图模型名：调用点 `describe_image` 处取视觉客户端模型名（`model_factory` /
  `tools.reference_auditor`），写进结构化校对结论的 `vision_model`。
