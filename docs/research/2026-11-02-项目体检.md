## 结论摘要

1. **代码底子不差**：1,880 个用例全绿（77.19s）、超时/重试/预算设计完整、测试有 autouse 网络守卫、无硬编码密钥、`subprocess` 无 `shell=True`。
2. **主要风险不是算法，是「可验证性」与「可导航性」**：7 模块导入结、5,613 行上帝模块、同一正则 4 份副本、427 个 `ValueError`、状态契约分散在四处、无 CI、无需求追溯。
3. **全绿不能证明行为对**：#141（17k+5 落位会把合规的 4s 段压到 3.0s）、#142（ComfyUI 导入后「引用上段」被翻成 true）、#139（资产图纪律块未真正生效）都是全量绿着漏过去的。缺的是跨系统契约测试，不是断言数量。
4. **死代码与死参数是功能残缺的物证**：6 个顶层定义、273 行代码全仓 0 引用；16 个函数有未使用形参。

## 3. 结构体检（已验证）

### 3.1 一个 7 模块的导入结

AST 找到 5 条环路径，核心是 7 个模块互相依赖：

```
asset_ledger ↔ brief_parser ↔ generation ↔ graph.state
      ↕              ↕
workflow_config    injection_card ↔ ref_capacity
```

其中 **top-level 导入边**（不是函数内 lazy import）就有：

- `asset_ledger` → `brief_parser`
- `generation` → `brief_parser`、`graph.state`、`workflow_config`
- `injection_card` → `asset_ledger`、`generation`、`ref_capacity`、`workflow_config`
- `ref_capacity` → `asset_ledger`
- `workflow_config` → `asset_ledger`
- `graph.state` → `brief_parser`

**影响**：

- 初始化顺序脆弱；新增一个顶层 import 就可能炸；
- 层逆向：配置层（`workflow_config`）依赖领域层（`asset_ledger`）；领域层（`generation`）依赖图层（`graph.state`）；
- 理解一个契约要跨 4–7 个文件，AI 只能抽样读。

### 3.3 重复判据（同一语义多处口径）

同一正则字符串出现在多个模块：

| 正则/常量 | 副本数 | 位置 |
|---|---:|---|
| `^[0-9a-f]{64}$`（SHA256） | **4** | `asset_ledger.py`、`generation.py`、`project_models.py`、`task_package.py` |
| `At\s+(\d{2}):(\d{2})\.(\d{3})` | **4** | `director/firstframe.py`、`director/prompts.py`、`segment_prompts.py`、`tools/h3_validator.py` |
| `\[Shot\s+(\d+)\]` | **3** | `segment_prompts.py`、`segment_refs.py`、`tools/h3_validator.py` |
| `<Picture\s+(\d+)>` | **3** | `director/pack.py`、`segment_refs.py`、`tools/h3_validator.py` |
| `<Subject\s+(\d+)>` | **2** | `segment_refs.py`、`tools/h3_validator.py` |

**已发现一处同名不同义**：

- `segment_prompts.py:82`：`^At\s+(\d{2}):(\d{2})\.(\d{3}),?\s*`
- `tools/h3_validator.py:24`：`^\s*At\s+\d{2}:\d{2}\.\d{3}`

两者都叫 `_BARE_TIMESTAMP_LINE`，但前者不允前导空白、捕获三组；后者允许前导空白、不捕获。**不是当前 bug，是下一次「改一处漏一处」的现成入口。**

另有两组同名常量内容相同（`_WRITING_WORDLIST`、`_AT_TIME_RE`），属于重复但不漂移；仍应合并来源。

## 4. 正确性与契约（已验证 / 部分验证）

### 4.1 错误类型单一

生产代码里的 `raise` 分布：

| 异常类型 | 次数 |
|---|---:|
| `ValueError` | **427** |
| `RuntimeError` | 19 |
| `FileNotFoundError` | 15 |
| `KeyError` | 3 |
| 其他 | 个位数 |

**影响**：调用方无法区分「用户输入错」「模型输出坏」「配置错」「外部服务错」，只能解析错误文案。直接后果是重试/回退/人判的边界都变粗。

### 4.2 契约不可机读

- **162 处 `Any` 引用**；
- **79 处 `state.get(key, 默认值)`**（近似）——缺键不报错；
- 状态契约分散在四处：`graph/state.py` 的 `TypedDict`、`ASSET_KIND_FIELDS` 常量、`session_store._STATE_KEYS` 白名单、各模块字面量 `state["..."]`；
- LLM 的 JSON 输出没有 JSON Schema / pydantic，全靠手写字段检查。

实测状态键探针：`frame_prompt_issues`、`bridge_frame_descriptions`、`frame_round` 被读写却不在 `PipelineState`。**核实后不是活 bug**（它们不进 LangGraph 图，或在 session 白名单里），但它证明：**光看 schema 或 grep，都拼不出完整的状态契约。**

### 4.3 静默降级（少数几处，但都在关键路径）

| 位置 | 行为 | 后果 |
|---|---|---|
| `session_store.py:381-382` | `schema_version` 不匹配 → `return None` | 旧会话从续接列表**静默消失**，用户以为没存过 |
| `director/cache.py:71 / :92 / :126` | 任意异常 → `""` | 缓存名/节点 id 解析失败变成空串，定位落到别的目录；有 `_require_safe_key` 兜底，但错误原因丢了 |
| `observability.py:57-60` | 订阅者异常 → `pass` | 进度/渲染坏了，主流程照跑，事后无记录 |

其余 30 多个 `except Exception` 多数是打印警告后降级，属有意设计；问题不在吞，而在**没有结构化失败记录**（见 §4.5）。

### 4.4 配置

- `config.py:252` 在 **import 时**构造 `Config()`，读 `agent.yaml` + `.env`。副作用在导入期；YAML 写坏会让任何 import `config` 的模块一起失败。
- **未知键静默忽略**：`agent.yaml` 里把 `provider` 拼成 `provder`，会回落到环境探测，不报错。
- 视觉档 `config.py:151-158` 的 `provider` 实际是**装饰性**的：客户端恒为 `ChatOpenAI`，默认 model/base_url/key 恒取 DashScope。写 `vision.provider: anthropic` 不会换协议，只会让错误文案说错。
- 平台耦合：`library_config.py:28` 默认 `D:\素材库`；`config.py:89` 默认 `D:/Comfyui/ComfyUI/output`；`run_wizard` 要求 TTY。

### 4.5 可观测性

- **617 处 `print`**，没有结构化运行日志（无 `run.jsonl`、无 trace/run id、无错误码）。
- 成本、耗时、失败原因都靠人看屏幕；出事后无法从盘上复盘一次运行。

### 4.6 并发与外部调用（风险较低）

- `graph/nodes.py:1245-1247` `merged.update(f.result())`：并行组按完成顺序覆盖同名键。实测各节点只写自己的键、且**没有原地改 state**，所以当前不是 bug；是潜在契约风险。
- `subprocess` 3 处，均为列表参数、无 `shell=True`（`tools/seam_audit.py:184 / :201 / :275`）。
- 密钥扫描未发现硬编码 key；`tests/conftest.py:103` 有 autouse 网络守卫。这两项是做得好的。

## 5. 测试体检

**已验证**：1,880 通过、5 跳过、77 秒、退出 0。

**盲区**：

1. **没有外部契约测试**：导演包字段与插件导入行为（#142 就是导入把 `continuityFromPrev` 翻成 true）、网关流式/usage、ffmpeg 命令、ComfyUI 工作流槽位，都没有对着「对方真实契约」的测试。
2. **没有跨路线端到端**：base / ref / director 三条路线各写各的测试，没有「同一功能三路线都覆盖」的矩阵。
3. **没有配置优先级测试**：env > yaml > 默认的整条链、未知键、拼写错误，没有覆盖。
4. **没有 schema 迁移测试**：旧 `session-state.json` 读回、版本不匹配的行为，没有用例。
5. **测试到模块的分布不均**（代理指标，不是覆盖率）：`output/renderer.py`、`task_package.py` 在测试里 0 引用；`director/cascade.py`、`companion.py`、`delivery.py`、`firstframe.py` 各只有 1 个文件提及。

这解释了为什么 **#141、#142、#139** 都是「全量绿着漏过去」——测试钉的是各自模块的声明，不是跨系统的行为。
