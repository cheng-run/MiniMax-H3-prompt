一句话：**向导是状态机，路线是状态机里的分叉；管线图本身不分叉**（ADR 0020），
路线差异全部落在「节点早退 / 产物出口 / 阶段 2 编排」三处。导演台目前只在入口与
退出点接了线，中间（准备口、陪跑、收尾）全是待接缝。

## 1. `ui/wizard.py`：流程、菜单、问答与测试桩

### 1.1 入口与状态机

- `run_wizard(config: Config) -> int`（`wizard.py:469`）。先要求交互终端
  （`:471-472`），脚本场景走 `--brief` 快路径。
- 恢复入口 `_offer_resume`（`:532`）：`find_awaiting_sessions` → `_confirm` → 编号菜单
  （回车=1）。**这是测试输入表最容易被吃掉的上游菜单**（见 §7.3）。
- 恢复会话时把成本表接回活账并立刻从 state 摘掉（`:480-484`），口径见 ADR 0005。
- 状态路由顺序（`run_wizard` 内，顺序本身是契约）：
  1. `STATUS_STAGE1_RUNNING` → `_resume_stage1`（`:491-495`）
  2. `STATUS_SEGMENTED_RUNNING` → `_resume_segmented`（`:498-499`）
  3. `STATUS_REF_SEGMENTS_RUNNING` → `_resume_ref_handoff`（`:502-503`）
  4. `STATUS_AWAITING_FRAMES` 且未展示过帧提示词 → `_resume_awaiting_frames`（`:507-513`）
  5. **导演台出口**（`:517-520`）：`session.brief.is_director` → 打一行说明后 `return 0`。
     注释明确：必须早于 base 分支，否则第三条路线会被静默塞进首尾帧链阶段 2。
  6. ref → `_phase2_ref_finish`（`:523-524`）；base → `_phase2_collect_and_finish`（`:525`）。
- **接缝**：新增 `director_running` 之类状态后，必须（a）加进
  `find_awaiting_sessions` 的 resumable 元组（`session_store.py:357-358`），
  （b）在 `run_wizard` 的导演台出口**之前**加一条 `_resume_director_*` 分支。
  只做 (b) 不做 (a)，中断的导演台会话不会被列为可续接；只做 (a) 不做 (b)，
  会被当成 `awaiting_frames` 走 `_resume_awaiting_frames`。

### 1.2 方式菜单与导演台模式

- `_choose_generation_mode() -> str`（`:256-283`）：五项，返回
  `I2VA/L2VA/FL2VA/REF2VA/DIRECTOR`；回车默认 3=`FL2VA`；编号→值映射在 `:282`。
  导演台是第 5 项（`:276`）。
- `_choose_director_mode() -> str`（`:299-315`）：七项取自
  `brief_parser.DIRECTOR_MODES`（`brief_parser.py:149`），**没有回车默认**，
  空/坏输入重问；菜单文案 `_DIRECTOR_MODE_LABELS`（`:288-296`）由测试钉住与常量同键
  （`tests/test_director_route.py`）。
- 导演台路线的 `variant` 取 `T2VA` 占位（`_phase1_new` `:711-713` 与注释）：
  导演台模式与帧变体是两套口径，带 `FL2VA` 进图会让 `FRAME_VARIANTS` 判据把会话读成首尾帧。
- 通用菜单收口 `_menu_pick(title, count) -> int`（`:335-346`）：返回 1..count+1，
  坏输入重问；画布选择 `_choose_canvas`（`:349`）与 `_choose_canvases`（`:318`）用它。
  测试里通常直接桩掉 `_choose_canvases`（如 `test_director_route.py:262`）。

### 1.3 阶段 1 / 阶段 2 边界

- `_phase1_new(config) -> SessionState | None`（`:679-765`）：
  1. `token_meter.reset()`——成本账的**唯一清零点**（`:683`，issue #52）；
  2. 主题 → 澄清（`_ask_clarifications` `:637`）→ 时长 → 风格 → 方式 → 导演台模式 →
     画布 → 构造 `Brief`（`:711-722`）；
  3. `_session_dir(config, topic)`（`:723`）定目录；
  4. `run_stage1`（`:736-740`），`on_step_done=_progress_saver` 逐节点落盘；
  5. `save_session(..., STATUS_AWAITING_FRAMES)`（`:745`）；
  6. `_skips_base_frame_loop(brief)` 为真（多参或导演台）→ 直接 `load_session` 返回
     （`:747-757`）；否则进 base 的人机修改循环 `_user_revision_loop`（`:761-763`）。
- `_skips_base_frame_loop(brief) -> bool`（`:459-466`）：`brief.is_ref or brief.is_director`，
  三处入口共用（新跑、阶段 1 续接、等交回续接）。**加第三条路线时它已经接好了**。
- base 阶段 2：`_phase2_collect_and_finish(config, session, *, show_frame_prompts=True)`
  （`:3037-3188`）：收帧路径 → 变体降级 → 帧图入库 + 读图 → `save_session` →
  `run_stage2(..., checkpoint_dir=generation_dir)`（`:3129-3130`）→
  `duration > 10` 标 `SEGMENTED_RUNNING` 并进 `_run_long_form`（`:3134-3181`）。
- ref 阶段 2：`_phase2_ref_finish(config, session) -> int`（`:2844-2923`）：
  素材循环 `_asset_loop` → 挂账 `_collect_extra_media` → 注入卡 `_deliver_injection_card`
  → 落盘入参 → `run_stage2` → 标 `REF_SEGMENTS_RUNNING` → `rotate_segment_ledger`
  （`:2899`）→ 单段/多段交付 → `_run_ref_segment_handoff` → `_finish_ref_handoff`。

### 1.4 分段循环与用户修订循环

- base 分段：`_run_segmented_flow(brief, session, prompt, summary=None, state=None) -> bool`
  （`:4437-4693`）。
  - 先读进度 `_segment_progress`（`:4289`）与缓存段表 `_cached_plans`（`:4734`）；
  - 有规划：`_run_segmented_flow_v2(session, plans, state, llm, summary=None, *,
    plans_from_cache=False, progress=None) -> bool`（`:4764-5004`），后台预取下一段；
  - 规划失败：按 `[Shot N]` 机械拆分回退（`:4528-4693`）；
  - 每段：写段文件 → `_gate_segment_text`（`:3230`）交付校验 → 终端展示 →
    用户回车「已在 ComfyUI 生成好」→ `_acquire_bridge_frame`（`:3586`）剥尾帧 + 可证层
    闸门 + 读图 → 落账 `append_shot_output` → `_save_after_segment_pass`（`:3401`）；
  - 末段：`_verify_last_frame`（`:3819`）核收尾并索要视频；
  - 全部通过后补写机械段表（`:4690-4691`）。
- ref 逐段：`_run_ref_segment_handoff(result, generation_dir, *, passed=None) -> bool`
  （`:2501-2644`）：轮到哪段才写哪段 → 出词 → 交回视频 → **可证层**
  `_gate_segment_handoff`（`:3259`）硬阻断 → **语义层**剥首/末帧读图
  `_capture_ref_segment_frames`（`:2647`）+ `_judge_ref_segment_semantics`（`:2690`）
  → 五档出路 `_choose_ref_segment_outcome`（`:3474`）→ 落 `log_segment_output`。
- 用户修订循环是**阶段 1/2 内**的另一条：`_user_revision_loop`（`:1079`），
  设定级重跑 `_rerun_setting_layer`（`:995`）、画面级重出等。导演台目前被
  `_skips_base_frame_loop` 挡在门外；后续若需要「改词」，应从段级账/导演台 UI 侧走，
  不要把导演台塞回这条以 `fl2va_prompt_bundle` 为锚的循环。

### 1.5 问答函数与测试桩形态

- 三个底层问答口：
  - `_prompt(text) -> str`（`:129-132`）：先 `_drain_stdin()` 再 `input().strip()`；
  - `_confirm(text, default=True) -> bool`（`:243-253`）：回车按默认，坏输入重问；
  - `_menu_pick`（`:335`）。
- 测试统一用 `monkeypatch.setattr(wizard, "_prompt", fake_prompt)` +
  `_confirm` + `_drain_stdin` + `wizard.sys.stdin`：
  - `tests/test_cost_accounting.py:65-86`（`_silence` / `_fake_inputs`）；
  - `tests/test_director_route.py:176-184`、`:241-243`；
  - `tests/test_wizard_resume_points.py:53-86`（喂完输入＝Ctrl-C）。
- 桩法有三种，按要测的层次选：
  1. 桩 `_prompt` 喂**输入表**（跑真实 `_phase1_new` / `run_wizard`）；
  2. 桩 `run_stage1` / `run_stage2` 返回假 state，跳过 LLM（`test_director_route.py:246-251`）；
  3. 桩图本身：`pipeline.build_pipeline_graph` 返回记录型 `FakeGraph`
     （`test_cost_accounting.py:112-121`、`test_director_route.py:154-164`）。
- **输入表顺序**：`_phase1_new` 的问答顺序是
  主题 → （澄清，可能 0 轮）→ 时长 → 风格 → 方式 → 导演台模式 → 画布。
  在中间插一道新题会让后面每个输入整体错位；在末尾补一项则可能被
  `_offer_resume` 的确认/序号菜单吃掉（issue #57 实测：补一个 `""` 被上游队列菜单吃掉，
  67 条全绿但 6 个文件 2.25s→249s，因为真发了 LLM 请求）。
  **正确做法**：在 `fake_prompt` 里按提示文本只对那道新题作答，不动输入表尾部。
  改完必须看耗时（CPU 时间远低于墙钟＝真发了网络请求，见 §7.4）。
- `run_wizard` 需要 `sys.stdin.isatty()`（`wizard.py:471`），所有走 `run_wizard` 的用例
  都要 `_silence`（桩 `wizard.sys.stdin`）。

## 2. `graph/pipeline.py` + `graph/state.py` + `graph/nodes.py`

### 2.1 图只有一张，路线靠节点早退与产物出口

- `build_pipeline_graph(model, brief, config, *, stage=0, chain=None, refs=None)`
  （`pipeline.py:101-137`）：线性 DAG，`StateGraph(PipelineState)`（`:129`），
  按 `chain` 逐节点 `add_node` 并串边（`:130-136`）。**没有按 mode 复制图**（ADR 0020）。
- 链常量：
  - `_STAGE1_CHAIN`（`:61-74`）：`producer → director → creative_rt → screenwriter →
    parallel_designers → art_director → parallel_image_prompts → storyboard →
    parallel_decisions → parallel_visual → fl2va_frame_prompts → parallel_sound`；
  - `_STAGE2_CHAIN`（`:75-78`）：`prompt_engineer → finalize`；
  - `_PARALLEL_GROUPS`（`:89-94`）与由它现推的 `_FOLDED_NODES`（`:97-99`）。
- 组合节点解析 `_combined_node`（`:140-157`）：并行组从 `_PARALLEL_GROUPS` 现推；
  链位名写错会在构建时取不到实现，不会静默少跑。
- 路线差异的真实落点（现状，全部是**早退**）：
  | 节点 | 守卫 | 导演台后果 |
  |---|---|---|
  | 资产图提示词三个节点 | `if not brief.is_ref: return {}`（`nodes.py:315`） | `r2v`/`rv2v`/`mixed` 需要资产图提示词，当前**一个都不产出**且不报错 |
  | 关键帧提示词节点 | `if variant not in FRAME_VARIANTS: return {}`（`nodes.py:667`） | `i2v`/`fl2v` 需要首/尾帧提示词，导演台 `variant=T2VA` → 静默不产出 |
  | 身份一致性圆桌 | `if brief.mode != "ref": {"identity_lock": ""}`（`nodes.py:1119`） | 导演台被当成 base，`identity_lock` 恒空 |
  | 参考一致性节点 | `if brief.mode != "ref": {"subject_defs": ""}`（`nodes.py:896`） | 同上，`subject_defs` 恒空 |
- **注意**：`mode != "ref"` 在第三条路线出现后不再等于「base」——它现在同时覆盖
  `base` 与 `director`。这两处是最容易「静默把导演台当 base」的地方（#103 必须处理）。
- 角色可见的 brief 块 `_brief_block`（`nodes.py:54-66`）：写 `模式=brief.mode`，
  `变体` 只在 `mode == "base"` 时给，**没有 `director_mode`**——角色 agent 目前不知道
  用户选了哪个导演台模式（#103 的提示词方言必须把模式送进请求）。
- 下游组装/校验对未知 mode 的处理（#103 的坑）：
  - `assemble_and_repair(prompt, mode, variant)`（`output/assembler.py:20-23`）：
    `mode == "ref"` 取 `REF_SECTIONS`，否则取 `BASE_SECTIONS`——导演台会被当 base 组装；
  - `validate_prompt(text, mode, ...)`（`tools/h3_validator.py:595-599`）：`mode == "ref"`
    才走 `validate_ref`，否则 `validate_base`；导演台会被 base 校验器判。
  目前导演台不走阶段 2，所以尚未爆；#104/#108 若把导演台接到 stage 2 或复用这两个口，
  **必须先加导演台分支**，否则是「规则在、接线不在」。

### 2.2 `PipelineState` 声明与 LangGraph 搬运纪律

- `PipelineState(TypedDict, total=False)`（`state.py:34-98`）。**LangGraph 只搬运 schema
  里声明过的键**，未声明的键传得进图、到节点手上就没了（静默；`state.py:39-41` 与
  `:84-93` 的注释，issue #28 实测）。
- 已声明且与导演台相关的键：
  - `mode`（`:37`）、`director_mode`（`:42`，issue #101 新增）；
  - 前期产物：`production_plan / director_brief / creative_lock / script /
    character_design / background_design / prop_design / art_design`（`:47-54`）；
  - 资产三键 `character_image_prompts / prop_image_prompts / scene_image_prompts`
    （`:57-59`，键名从 `ASSET_KIND_FIELDS` 派生，`ASSET_PROMPT_KEYS` `:30-31`）；
  - `identity_lock / shot_table / shot_review_lock / visual_design / subject_defs`
    （`:60-71`）、`sound_design / music`（`:74-75`）、`final_prompt / qa_*`（`:78-82`）；
  - `user_revisions / setting_revision`（`:91-92`）、`asset_proofreads`（`:98`）。
- `run_stage1` 的初始 state 显式塞 `director_mode`（`pipeline.py:285-297`，`:289-291`
  的注释说明「由 brief 现取，不在白名单存第二份」）。
- **接缝**：#102 的段表若要在图节点间传递，必须先在 `PipelineState` 声明；
  更稳的做法是**段表只落盘**（`segments/plan.json`），图外计算、图外消费，
  避免把「帧为真源」的导演台契约塞进 base/ref 共用的 state 契约。

## 3. `session_store.py`：目录、白名单、过滤、续跑

### 3.1 会话目录结构

- 会话文件 `session-state.json`（`session_store.py:24`，schema `wizard_session.v1` `:25`）。
- 目录命名：`_session_dir(config, topic)`（`wizard.py:778-815`）→
  `<sessions_root>/<topic_slug>/GEN00N`；`_topic_slug`（`:768-775`）是「可读前缀 + 8 位哈希」。
- 续接规则：最新 GEN 的 `status != completed` → 复用；`completed` / 无会话 / 损坏 → 新 GEN
  （`:796-814`）。**只按「不是 completed」判**，所以新增未完成态自动获得续接语义——
  前提是确有代码在写那个态（`segmented_running` 曾长期只存在于 docstring，issue #17）。
- 复用 GEN 的副作用（issue #58）：新一轮交付会整份覆盖 `plan.json` / 段文件，但
  **追加式账不会**；所以新交付开头必须轮转（base `rotate_shot_progress`，
  `wizard.py:3176`；ref `rotate_segment_ledger`，`wizard.py:2899`）。
- 常见落盘物（写入点）：`frames/`（`_store_frame` `wizard.py:5007`）、
  `segments/`（plan/段文件/账/gate-log）、`video-prompt.md`（`wizard.py:3141`、`:2890`）、
  `injection-card.md`、`stage2-checkpoint.json`（`stage2_checkpoint.py:11`）、
  `summary-zh.json`、`final.mp4`（`wizard.py:4113`）、`ledger.json`、`audit/`。

### 3.2 `_STATE_KEYS` 白名单

- `_STATE_KEYS`（`session_store.py:67-91`）：state 允许持久化的键。关键点：
  - 资产三键从 `ASSET_PROMPT_KEYS` 展开（`:72`），不重抄；
  - `frame_images`（`:78`，issue #51）；
  - `bridge_frame_descriptions`（`:83`，issue #94 复审：不在白名单＝续跑时桥接链断掉且不报错）；
  - `user_revisions / frame_round / asset_proofreads / asset_loop / resume_answers /
    asset_proofread_progress`（`:85-86`）；
  - **故意不在**：`director_mode`（`:87-91`）——路线级选择只住 `brief` 一份；
    `frame_revision_baseline` 与 `setting_revision` 是「某一轮的入参」不持久化（`:62-66`）。
- **接缝**：导演台的「节点 id / 缓存名 / 引导模式」（spec #100「会话开头问一次并落会话状态」）
  要么进 `Brief`（推荐：与 `director_mode` 同族，路线级数据，需同时加到
  `_brief_to_dict` / `_brief_from_dict`），要么进 `_STATE_KEYS`。
  **不能两处都放**（同一契约两处口径）。落 `Brief` 还要求向导是唯一写入者
  （brief 文件入口已拒绝 director，`brief_parser.py:452-455`）。

### 3.3 `_route_filtered_state` 与 brief 序列化

- `_route_filtered_state(raw_state, brief)`（`session_store.py:100-126`）：
  **只按 `Brief.mode` 过滤**——`brief.is_ref` 原样保留，否则弹掉 `ASSET_PROMPT_KEYS`。
  它有明确纪律：这是路线过滤不是容错；字段损坏仍大声报错。
- **导演台风险（高优先级）**：#103 若让 `r2v`/`rv2v` 产出资产图提示词，续跑读回时
  它们会被当成「非多参残留」**静默丢掉**。修法不是加 `or brief.is_director`（那会让

  归档最终包 + 摘要值；读最终包比对补 `rewrite` 行；失败不标完成（照
  `_assemble_film_and_complete` 的「成功才 completed」`wizard.py:4134`）。

  `_run_segmented_flow_v2:4908-4912` 的「没有产出就 continue」。

### 8.4 「base/ref 零变化」护栏怎么守

1. **判据单源**：任何新分叉只从 `is_ref_mode` / `is_director_mode` / 新的能力判据派生；
   禁止在调用点写 `mode == "director"` 字面量（除入口/出口各一处）。
2. **改共享守卫要成对跑**：动 `nodes.py` 的早退、`_route_filtered_state`、`_STATE_KEYS`、
   `_skips_base_frame_loop` 时，先跑 base/ref 全量，再跑新增导演台用例；
   两边都绿才算数。
3. **产物出口分叉而非图拓扑分叉**（ADR 0020）：新节点只加在导演台自己的准备/陪跑模块，
   不改 `_STAGE1_CHAIN` / `_STAGE2_CHAIN` 的顺序（截断重跑与续跑都按这两个清单索引）。
4. **持久化白名单不抄字面**：新键从常量派生（`ASSET_PROMPT_KEYS` 先例）。
5. **测试隔离**：导演台用例单独文件（如 `tests/test_director_*.py`）；
   不改既有 base/ref 用例的输入表尾部。
6. **全量 + 耗时**：每张票合并后主树跑全量；若某文件耗时异常上升，先查是不是真发了网络。

### 8.5 通用坑清单（按严重度）

1. **`mode != "ref"` 已经不再等于 base**（`nodes.py:896`、`:1119`）：导演台会被静默当 base，
   `identity_lock`/`subject_defs` 恒空。这是「规则在、接线不在」的高危形态。
2. **`_route_filtered_state` 会丢导演台资产图提示词**（`session_store.py:120-126`）：
   续跑读回即丢，且不报错。
3. **`assemble_and_repair` / `validate_prompt` 只认 ref 与 base**（`assembler.py:20-23`、
   `h3_validator.py:595-599`）：导演台若走这两个口，拿到的是 base 的段结构与判据。
4. **LangGraph 丢未声明键**（`state.py:39-41`）：段表若想经 state 传给节点，必须声明；
   否则「返回值里读得到 ≠ 节点读得到」。
5. **新状态漏加 `find_awaiting_sessions`**（`session_store.py:357`）：会话不被列出，
   用户只能重开新 GEN，段账永远读不到（#17/#58 同形）。
6. **复用 GEN 不轮转追加账**：新一次交付读到上一次的通过行（#58 实测）。
7. **`_session_dir` 只看 `!= completed`**（`wizard.py:808`）：状态名写错/没写＝永远新 GEN。
8. **`--brief` 的 director 报错是 traceback**（`brief_parser.py:452`）：用户体验问题，
   不是接线问题；若要开快路径，另设入口，别动 `--mode` 的 base 语义。
9. **`_brief_block` 缺 `director_mode`**（`nodes.py:54-66`）：#103 的方言必须把模式送进请求，
   否则所有模式拿到的都是同一份 base 口径。
10. **导演台不需要 `ref-concat` 的出路文案**（`final_film.py:210-219`）：成片由导演台合并，
    给 `--replace` 指引是误导。
