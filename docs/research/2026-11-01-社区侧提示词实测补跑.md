# 社区侧提示词实测补跑（2026-11-01）

> 平台：Reddit / X / 小红书 / B站。只读，未发帖。
> 目的：补第一轮六层调研缺失的社区证据；每条标依据等级与样本限制。

## 一、方法与限制（先说清）

- **Reddit**：`opencli reddit search` 全程 403（WAF）；改用 `site:reddit.com` 搜索 + `reddit read` 读原帖。34 次读取，0 次硬失败，2 条部分失败。**日期多为推算**（正文明确日期只有 2 条）；赞数是读取时快照。
- **X**：`opencli twitter search` 正常；点赞/浏览为检索时快照。
- **小红书**：封装 `search` 命令坏（`search_input_not_available`），走浏览器通道（`opencli browser`）；高赞笔记正文多为 tag、干货在图里，**未采信**。
- **B站**：`bilibili search` 正常；`subtitle` 可取 ai-zh 自动字幕（有错字）；部分视频本身无字幕。

## 二、按层的证据

### L1 剧情 / 长片分段

- H3 单次生成**连贯上限约 20–25 秒**；超过后开始「循环头几镜」，多镜头更早崩。Reddit 多帖同向（47 / 257 赞）。
- 长片主流做法是**运动上下文/潜变量接力**，不是一次生成。
- 分镜表要「一个视觉信息点一个镜号」；不许合并概括（小红书转述）。
- 社区口径：「一条视频一个主动作 + 一种主运镜」「提示词 60 词以内：一个主体、一个动作、一个有名字的运镜」。
- **等级**：社区一手实测 + 经验；无官方依据。

### L2 视频词与遵从度

- H3 本地量化档确实漏执行，能点名漏项（叫声、物件变形、开场动作）。X 实测（325 赞）。
- H3 Max 实测：JSON/分区提示词更稳；质量取决于首尾帧；动作越多越差；广角吃力。X（6.9 万浏览）。
- 多镜防换脸：每个镜头开头原样粘贴同一段人物描述。X（实测自述）。
- **提示词遵从度可能与分辨率相关**：352/416p 结构遵循好于 768p（Reddit 单帖，10 赞，未复现）。
- **否定式约束在三处独立失效**（Wan/Kling/H3）：写「不要动」会被忽略或反噬。
- 多主体：2 个角色稳，3 个以上串脸（Sora/Kling 证据；**H3 无专门实测**）。
- **等级**：社区一手实测（多为单帖 n=1）；分辨率与多主体两条需验证。

### L3 运镜

- 运镜词**单独不足以控制机位**；从业者用 3D 预演/参考视频当运镜真源（X 多条）。
- 有效补丁：结构化三要素（Motion Type + Amplitude + Speed）＋「同速参照物」＋ 背景地标（Reddit 实测，OP 回「did the trick」）。
- 只写运镜名词不够，要写「镜头逻辑」（B站 104 种运镜逐条实测，17 万播放）。
- 否定式运镜无效；改写成「静态机位 + 画面里正在发生什么」。
- **等级**：社区一手实测 + 经验；「词不能保证落点」是多来源同向。

### L4 尾帧 / 图生图编辑

- **角色声明写法**：`This is an IMAGE EDIT, NOT A REGENERATION`；`Use the uploaded image as the STRICT IMAGE MASTER`；`ONLY identity source`（X 多条 prompt 原文）。
- Qwen 编辑：`add / replace / remove` + 「其余一切保持不变」有效（Reddit 462 赞，被质疑为 ChatGPT 产物）；**中文原生命令执行更好**（Reddit 343 赞，实测）。
- Qwen 2.1 Edit 会「贴脸」不是融合；有人给参数（steps 40 / CFG 3 / res_multistep）。
- Kontext：`Change [X], keep [Y], don't touch [Z]`；迭代编辑会累积画质劣化。
- 「别在提示词里提你不想改的东西」与「列全保留项」冲突——**按模型分档**。
- 尾帧可靠做法：**从首帧派生尾帧**，不分别生成两张再赌一致。
- **无直接证据**：尾帧提示词「强制写 A→B 位移」（我们的 #114 补丁）没有社区对照，既无佐证也无反证。

### L5 关键帧

- 首帧质量决定 i2v 上限；官方要求先把图定为 first frame 锁透视。
- 关键帧要**干净电影帧**，不要文字密集故事板（X 1012 赞）。
- **按状态节点切帧**：起势→动作→反应→转折→定格，每节点前后两格；每格只写身体状态、视线、一个微表情；共用描述只写一次（小红书实测，第一版失败）。
- 末格不许「缓缓转身」这类收不回来的动作。

### L6 资产图

- **B站 5 组对照实跑**（2 万播放，同 seed、同提示词、只换资产图布局；作者自认不严谨，n=5）：
  - 001 全身 + 大脸 → 模型优先用全身姿态，大脸等于没输入；
  - 002 两张全身 → 用全身照里的脸；
  - 003 超大脸正/背 + 全身 → 首帧最清晰，但转身时回去用全身脸；
  - 004 一张图四张脸 → 「少数服从多数」；
  - 005 **正/侧脸特写 + 无头全身** → 转身前后一致性最好。
  - 作者结论**分场景**：动态人物用 005 式；口播/数字人用 003 式。
- **一张图人脸 ≤2**；小图（全身）里不留脸。
- 张数：主角 3–5、配角 1–2、道具 1–2、场景 1；3–5 是收益区。
- 参考图用视频原生分辨率、白底可防背景渗入、`ref_image_size` 设 max、脸单独裁大图。
- **Ref2VA 不是严格首帧**：Reddit 实测约 80% 把 `<Picture 1>` 当尾帧；小红书一句话弱印证（1 赞）。

## 四、工具坑（供后续复用）

- 小红书：直开 `/explore/<id>` 404；必须用带 `xsec_token` 与 `xsec_source=pc_search` 的完整签名 URL；搜索页 `window.__INITIAL_STATE__.search.feeds` 是 Vue ref，取 `._value`。
- 小红书搜索结果混有非笔记卡片，用 `{title, href}` 成对取。
- B站：`subtitle` / `summary` 逐视频，有的视频本身没有；`summary` 偶发 -504，重试常变 `EMPTY_RESULT`。
- Reddit：`read` 不返回 `created_utc`，日期需另补。
