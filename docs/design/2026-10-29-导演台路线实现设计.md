## 1. 总原则

1. **只加产物出口，不动老路线**。`base` / `ref` 两条路线的行为、产物、账本一字不变；现有全量基线 `1502 passed / 1 failed / 5 skipped`（失败为 `test_loadout_manifest_real_assets` 的环境性用例）。任何让老路线测试变红的改动都是错的。
2. **严格失败优先于静默回落**。插件自己会在缺缓存时静默硬切、`mixed` 段类型为空时回落 `t2v`；项目侧必须用**事前校验**把这些路堵死，而不是等它静默降级。
3. **一个契约只住一处**：帧换算只在 `director/frames.py`；包字段只在 `director/pack.py`；段类型判定只在 `director/frames.py`；提示词方言只在 `director/prompts.py`。其它模块从这些口取，不重抄字面。
4. **测试不跑 ComfyUI**（spec Testing Decisions）。包/缓存/账本全部用临时目录与 fixture 断言；插件侧契约用**镜像校验**（把插件源码的判据抄成项目侧断言，并在注释里写明对应插件 file:line 与版本敏感点）。
5. 代码注释一律中文，写「为什么」（票号 / ADR / 插件行号 / 实测现场），不复述代码。

## 3. 数据契约

### 3.1 帧数学（`director/frames.py`，票 #102）

- `FPS = 24`。
- 插件对齐函数是 `17k+5`（`ComfyUI_MiniMaxH3_Director/director/frame_align.py:8`），只向上取整。
- **有引导段**（`guided=True`）：导出帧恒为 17 的倍数；`declared_frames = export_frames - 12`（ADR 0024）。反解：给定目标导出帧 E，声明帧取 `E - 12`。
- **无引导段**（`guided=False`）：`export_frames == declared_frames`。
- **声明帧一律落在 `17k+5` 上**（ADR 0025，2026-10-29 用户裁定）：后端与 UI 都按 `durationSec` 吸附到该网格；包内 `durationSec` 必须与声明帧自洽（107 帧↔4.0s、141 帧↔5.8s），不省略。
- 总帧判据：`Σ export_frames` 取**与 `round(total_s*24)` 最接近的合法落位**。n 段总量恒 ≡ `5×无引导段数 (mod 17)`，且**取决于段表里有几段无引导**：30 秒五段在 1 段无引导时最近 **719**（差 1），含切镜段（2 段无引导）时最近 **724**（差 4），3 段时 **712**。出站清单写明「目标 / 实际 / 差几帧」（ADR 0025）。
- 规划器的确定性层必须**枚举**合法落位再取最近，不能「先均分再四舍五入」——那会落到不可达的余数上。
- 段类型的英文 slug（代码用）+ 中文显示（出站用）**一处映射**：

| slug | 中文 | 引导 | 给图清单（执行期） |
|---|---|---|---|
| `opening` | 开场 | 关 | 按模式：`t2v` 无；`i2v` 首帧；`fl2v` 首帧（尾帧可选）；`r2v` 参考素材（首帧可选） |
| `continue` | 续接 | 开 | 无（只靠段间引导） |
| `camera_same` | 运镜·同场景 | 开 | 尾帧（终点画面） |
| `camera_cut` | 运镜·切镜 | 关 | 首帧 + 尾帧 |
| `ending` | 收尾定格 | 开 | 尾帧（终点画面） |

- 判定规则（spec「段类型与给图规则」）：**起点是上一段终点 → 引导开、只给尾帧；起点在别处 → 给首帧、关引导。** 段类型由规划 LLM 判定，项目侧只做**合法性校验与派生**（`guided` / `give_images` 从类型派生，不接受 LLM 直接给）。
- 尾帧（终点画面）不是打包时存在的图：它由 #107 的尾帧变换提示词产出，用户在导演台 UI 里逐段挂。`give_images` 是**出站清单**，不是打包清单。

### 3.2 `plan.json`（`director/planning.py`，票 #102）

路径为 **`GENxxx/director/plan.json`**，导演台用**自己的形态**（不碰 `SegmentPlan` / `ref_segments._write_plan_file`）。**刻意不写 `segments/plan.json`**：共享读取口 `tools/ledger.read_plan_segment_count` 只认 JSON **数组**（`src/minimax_h3_prompt/tools/ledger.py:271-280`），同一路径放第二种形态会让它在导演台会话上**静默返回 None**；把新形态放到路线自己的目录，两个读取口互不污染。

```json
{
  "route": "director",
  "mode": "r2v",
  "fps": 24,
  "total_frames": 719,
  "segments": [
    {
      "index": 1,
      "type": "opening",
      "guided": false,
      "start_frame": 0,
      "end_frame": 107,
      "declared_frames": 107,
      "export_frames": 107,
      "start_s": 0.0,
      "end_s": 4.458,
      "summary": "…",
      "end_hook": "…",
      "give_images": ["first"]
    },
    {
      "index": 2,
      "type": "continue",
      "guided": true,
      "start_frame": 107,
      "end_frame": 260,
      "declared_frames": 141,
      "export_frames": 153,
      "start_s": 4.458,
      "end_s": 10.833,
      "summary": "…",
      "end_hook": "…",
      "give_images": []
    }
  ]
}
```

- 秒 (`start_s` / `end_s`) 是**派生值**，不参与校验；`start_frame`/`end_frame` 是累计**导出帧**（成片坐标，Σ = `total_frames`）。
- **两套坐标（易混，写包时必须换）**：`plan.json` 与可证层用**成片坐标**（导出帧累加）；导演台的 `timeline.totalFrames` 与 `segments[].start/length/frameCount` 用**声明坐标**（声明帧累加，`gen_timeline.py:102-123`）。二者差 `12×有引导段数`——插件文案本身就说「保完整成片会略长于时间轴」。包构建时 `timeline.totalFrames = Σ declared`、`segments[].start = 累计 declared`，而我们的 `total_frames`（Σ export）是**成片长度**，不是时间线的显示长度。**出站清单必须同时写两个数**（30 秒例：时间线 671 帧 / 成片预计 719 帧），否则用户会以为导演台里显示 28 秒是错的。
- 规划器输出（LLM）只提供分段边界建议、段类型、`summary`、`end_hook`；确定性层负责吸附网格、反解声明帧、把总帧落到**目标附近最近的可达值**。
- 目标不可达（不能精确等于 `round(total_s×24)`）时**取最近可达值并写出站说明**，不静默截断/超时（票 #102 AC4，ADR 0025）。不做「先均分再吸附」的近似——会落到不可达余数上。
- 读回严格：未知段类型、非法帧数、`Σ export != total_frames`（读回的表本身必须自洽）都抛 `ValueError`（续跑不能拿错表）。
- **目标帧不落盘**：`total_frames` 存实际落位值（719/724…），目标只出现在规划那一刻的出站说明里。续跑读回的表不需要复述「差几帧」；#104 的打包清单报告的是「时间线总帧（Σ 声明）vs 成片预计帧（Σ 导出）」，不依赖目标值。

### 3.3 提示词方言（`director/prompts.py`，票 #103 / #107）

六节常量已存在：`tools/h3_validator.REF_SECTIONS = [subject_definitions, summary, retention_analysis, detailed_description, overall_soundscape, non_diegetic_music]`；`BASE_SECTIONS = [integrated_multimodal_description, overall_soundscape, non_diegetic_music]`。

- `r2v`：**保留 REF 的六节外壳**（唯一含音频段的模式），`detailed_description` 改成**时序写法**，去掉 `start_state`（它不属于导演台的输出契约），主体引用 `<Picture N>`。可复用 `ref_segments.parse_ref_prompt / build_ref_prompt` 的往返能力，但**不得**复用 `validate_ref` 里与多参段序/时间轴相关的假错判据（另写导演台校验口径）。
- `t2v` / `i2v` / `fl2v`：按各自模板；**音频描述并入正文**（不单列 `overall_soundscape` / `non_diegetic_music`，与导演台自由提示词一致）。
- 时间轴注记：保留绝对位置，按 `start_frame / 24` 重算，写入段提示词；不得沿用「相对本段起点」的旧口径（`CONTEXT.md` 细粒度时间戳是 base/ref 的口径，导演台用绝对帧）。
- 模板落点：`src/minimax_h3_prompt/prompts/segment_writer_director.md`（一个文件内按模式分节，加载口按模式取节；**不要各模式各建一份会漂的指令文件**）。测试逐模式断言：该有的段头在、不该有的段头不在、时间轴注记等于帧换算结果。
- **校验器不能默认把 director 当 base**：`h3_validator.validate_prompt` 与 `output/assembler.assemble_and_repair` 都是 `mode == "ref"` 的二元分叉（`h3_validator.py:595-599`、`output/assembler.py:23`），`director` 会落进 base 分支被按三节验收或强行补齐三节。导演台走自己的校验/组装口，或在这两处显式分叉；**不许**靠「反正不走那条路」。
- **模式必须送进写段请求**：`graph/nodes.py` 的 `_brief_block` 目前不含 `director_mode`（`nodes.py:54-66`），方言分派拿不到用户选过的模式；#103 要把模式按既有形态送进请求，否则所有模式拿到同一份口径。
- 尾帧变换提示词（#107）：三部分——**变换指令 / 保留项声明 / 锁死清单**；只在 `camera_same`、`camera_cut`、`ending` 触发（`opening`/`continue` 不产）。输入是**上一段缓存末帧**（#105 的缓存读取口），产出后跑确定性检查（`tools/image_prompt_discipline` 的口径：只写看得见的事实、正向陈述）。

### 3.4 导演包（`director/pack.py`，票 #104）

插件侧已核实的格式（`ComfyUI_MiniMaxH3_Director/director/pack.py`）：

- 包是 `.mmxpack.zip`，布局：`pack.json`、`timeline.json`、`shared_params/shared_params.json`、`asset_groups/<NN>/group.json` + 媒体、`source_video/`（v2v）、`extra/`。
- 包内路径必须匹配 `^[A-Za-z0-9_./]+$`（`pack.py:35`）；媒体文件名 `Picture1–9`、`Video1–3`、`Audio1–3`、`start.*`、`end.*`（`pack.py:37-41`）。
- `pack.json`：`format="minimax-h3-director-pack"`、`formatVersion=1`、`taskType`、`widgets{steps,sampler,scheduler,cfg,shift_video,shift_audio,seed,task_type}`、`output`（`pack.py:589-599`）。
- `shared_params/shared_params.json`：`commonEnabled`、`commonCollapsed`、`prompt`、`refs`、`refAudios`、`refVideos`，可选 `t2vCommon`（`pack.py:600-614`）。
- `timeline.json` = 节点时间线数据本体（v4）：`version=4`、`editMode`、`totalFrames`、`frameRate`、`width`、`height`、`refMaxSize`、`output{mode,longEdge,width,height,maxExportFrames,exportMode,audioMode,refImageSize,continuity*}`、`videoClips[]`、`video{}`、`global{taskType,prompt,refs,...}`、`segments[{id,start,length,prompt,taskType,refs,referenceVideo,continuityFromPrev,startImage,endImage,genImage,...}]`（`director_common.py:167-219`、`pack.py:417-433`）。**`totalFrames` 与 `segments[].start/length` 用声明坐标**（Σ declared），见 §3.2 的「两套坐标」。
- 时间线/段结构：`timelineMode` 必须显式写（生成类 `prompt_batch`；`fl2v` 模式写 `fl2v`；`v2v`/`rv2v` 写 `video`），否则插件按任务类型猜、`v2v` 猜错会走成生成类。`pack.json.widgets.task_type` 与 `timeline.global.taskType` 必须一致（前者优先）。**段边界按 `frameCount` 顺序累加，`start` 被忽略**（`gen_timeline.py:102-123`）——数组顺序即时间顺序，`start` 只作展示用。
- 段级字段：`length` / `frameCount`、`start`、`durationSec`、`taskType`、`refs`、`refImageSize`、`continuityFromPrev`、`startImage` / `endImage`（mixed 的 fl2v 段用首尾帧字段，`gen_timeline.py:177-193`）。生成类段必须写 `durationSec` 且与声明帧自洽（ADR 0025）；`fl2v` 另要写 `shots` 与 `segments` 两处。
- 连续性键：`output.continuityEnabled`、`output.continuityOverlapFrames`（默认 22）、`output.continuityMode`、`output.continuityKeepTail`（默认 true）；段级 `continuityFromPrev`（默认 true，段 0 永不生效）（`director/segment_continuity.py:130-228`）。

八条装配约束（违反即 `ValueError`，**不得**先写包后校验）：

1. 包内路径一律 ASCII（同一个正则从插件常量派生，不重抄）。
2. `commonEnabled=false`（公共参考关闭；否则参考编号顺延，与段内子集对不上）。
3. 画布宽高 `% 32 == 0`。
4. `refImageSize` 只允许 `match` / `max`；段级优先于全局。
5. 每段参考图 ≤ 9（`Picture1–9`）。
6. `mixed` 下的 `fl2v` 段用 `startImage`/`endImage`，**不是** `refs` 数组。
7. `output` 必含：`continuityEnabled=true`、`continuityOverlapFrames=22`、`continuityKeepTail=true`、`exportMode="all"`、`continuityMode`（配置项，默认官方基线 `guide`）。
8. `mixed` 段内只允许 `t2v` / `i2v` / `fl2v` / `r2v`；其它值（含空）报错——插件自己会把空值静默回落 `t2v`（`gen_timeline.py:159-166`），这条正是要抢在它前面。

包输出路径：`GENxxx/director/pack/`（解包目录）+ `GENxxx/director/initial.mmxpack.zip`。中文语义名只留在提示词与账本；包内媒体名用 ASCII（`Picture1.png` 等）。

#### 3.4.1 素材来源与槽号口径（2026-10-29 用户裁定，覆盖 handoff 的未决问题 1）

| 模式 | 来源 | 缺了怎么办 |
|---|---|---|
| `r2v` | **复用素材台账**：`asset_ledger.load_asset_ledger` + `resolve_asset_path` 取已登记正本；**每段挂全量**（登记图 ≤ `ref_capacity.MAX_PICTURES`=9） | 台账未登记正本 → 拒绝打包并点名 |
| `i2v` / `fl2v` 开场 | 按段目录 `GENxxx/director/assets/NN/start.png`（`fl2v` 可选 `end.png`） | **拒绝打包**并点名段号（`i2v` 漏给首图会静默变文生视频） |
| 运镜段 / 收尾段的终点画面 | **不进包**：#107 出尾帧变换提示词，用户在导演台 UI 里逐段挂 | — |

**为什么 r2v 每段挂全量、而不是 `segment_refs` 的段内子集**：#103 已写好的段提示词里 `<Picture N>` 用的是**全局登记号**；插件把 `refs[].index` 直接当槽号（`plan.py:1073-1074`、`lib/ref_images.py:44-46`），段内槽号是**局部**的。挂全量时全局号＝局部槽号（**从 0 连续**），段词一字不用改；改走子集就必须在打包时重编 `<Picture N>`，那等于第二条改写口径，且会与用户手里的段词不一致。容量上限已经是 9（`ref_capacity.MAX_PICTURES`），全量与官方上限重合，不存在放不下。

缺口登记：`r2v` 若要放宽到子集，属二期另票；本票不实现子集路径，也不留「超 9 张自动改子集」的静默降级。

**准备口形状**（spec Testing Decisions 缝 2）：仿多参 `prepare_ref_segments` / `deliver_ref_segments`，导演台提供 `prepare_director_pack(...) -> (DirectorPackJob, str)` 二元组：job 是可断点续做的打包任务（plan、段提示词、素材路径、输出目录），report 是出站文本（缺哪些图、八条约束逐条结论、包路径）。纯函数 + 临时目录可测，不跑 ComfyUI。

### 3.5 段缓存（`director/cache.py`，票 #105）

- 目录：`<ComfyUI output>/minimax_seg_cache/<cache_name>_<node_id>/`；名字为空时只有 `<node_id>`（`segment_cache.py:180-196`）。`cache_name` 按插件规则归一（非法字符替换）。
- 帧文件：`seg_XXXX.frames.mkv`（0-based，`segment_cache.py:461-465`），FFV1 无损；`meta.json` 只记输入指纹，**不是**产出凭据。
- **编码口径（2026-10-29 勘察确认）**：插件控件 `cache_frames_codec` 默认 `raw` → 缓存帧是 `seg_XXXX.pt`（torch uint8）；切成 `ffv1` 才是 `.mkv`。本项目环境**没有 torch**（`.venv` 只有 cv2 / imageio_ffmpeg），无法读 `.pt`。
  - 本路线只支持 `ffv1` 的 `.mkv` 缓存；遇到 `.pt` **明确报错**并给出处置：「把导演台的 `cache_frames_codec` 切成 ffv1 后重跑该段」——不许静默当 0 帧或跳过。
  - `handoff.json` 里的 `export_frames` 只是插件自报的计划值，**不能**代替数帧（相位对齐会实裁几帧）。
- 数帧：`cv2.VideoCapture` 的 `CAP_PROP_FRAME_COUNT` 对 FFV1 mkv 可用（本机实测 30/30），但为防容器元数据不可靠，读到 ≤0 时逐帧解码计数（`frame_match.read_frames_gray` 口径）。文件缺失/读不出 → 明确报错，不当作 0。
- 删除：删 `seg_XXXX.frames.mkv` 及其 `av.pt`/`audio.pt`/`handoff.json`/`meta.json` 同段副产物；不删整个缓存目录（其它段可能仍在用）。删除前 `resolve()` 并校验仍在缓存根内（路径来自用户配置，防越界）。
- 根目录从配置读：`config/director` 的 `comfy_output_root`，环境变量 `H3_COMFY_OUTPUT_ROOT` 覆盖；默认 `D:/Comfyui/ComfyUI/output`。**不写死在模块里**。

### 3.6 段产出账（`director/ledger.py`，票 #105 / #106 / #108）

沿用 `segments/segment-ledger.jsonl`（`ref_segments.segment_ledger_path`），导演台只写两类行：

- `event=output`（一段通过可证层）：
  `{"event":"output","segment":N,"start_frame":..,"end_frame":..,"declared_frames":..,"export_frames":..,"actual_frames":..,"cache":"<绝对路径>","sha256":"…","at":"…"}`
- `event=rewrite`（#108 从最终包补记的 UI 改词）：字段与 `ref_segments.log_segment_rewrite_round` 同形（`segment`、`round`、`feedback`、`prompt_before`、`prompt_after`、`at`）。

不写 `encounter`（语义验收在导演台 UI 完成）。作废下游通过行用 `event=invalidate` 行（追加式，不改写旧行）：`{"event":"invalidate","segment":N,"reason":"…","at":"…"}`。`passed` 判定＝按段号取**最后一条** `output`/`invalidate` 行，是 `output` 才算通过。

### 3.7 可证层判定（`director/companion.py`，票 #105）

- 有引导段：`actual_frames <= export_frames` 且 `export_frames - actual_frames <= 5`（容差 `DIRECTOR_FRAME_TOLERANCE = 5`，写成模块常量，测试做变异检验：改成 0 必须变红）。插件会因下一段相位对齐裁掉上一段尾部几帧，所以不能判「等于」。
- 无引导段：`actual_frames == declared_frames`。
- 勾错段/该跑未跑：缓存里段号对不上（比如用户勾了第 4 段但缓存文件的段号是 3）→ 直接报红（`SEGMENT_MISMATCH`），不静默通过。
- 通过后写 `output` 行，含缓存路径与实际帧数。
- **只跑某一段的 UI 前提**：插件对「选中段」一律重采样，全片模式并不会因缓存命中而跳过（`exportMode="all"` 只影响导出，不影响采样）。陪跑出站必须写明「在导演台里用 `runSelection` 只勾第 N 段」；否则用户一点运行就是整条时间线重跑。

### 3.8 级联（`director/cascade.py`，票 #106）

- 改第 N 段：作废第 N+1.. 的通过行（append `invalidate`）、删除第 N+1.. 的段缓存；第 1..N-1 不动。
- 两条路径：**重跑（不改词）** 不重打包，删第 N 段及之后的缓存并重跑；**改词** 在导演台 UI 里改该段提示词、删缓存重跑，回告项目记账（`rewrite` 行或 `invalidate` + 后续 `output`）。
- 「缓存指纹不含父段身份」（插件侧重放原因）是必须删下游缓存的硬理由，注释写明。

### 3.9 交付（`director/delivery.py`，票 #108）

- 全段通过后引导用户在导演台合并成片，记录 `final.mp4` 路径（存 `GENxxx/director/final-film.json`：路径、`total_frames`、段数、时间）。
- 最终包归档：`GENxxx/director/final.mmxpack.zip` + `final.sha256`（校验值现算，不另收参数）。
- 比对：读最终包 `timeline.json` 的 `segments[].prompt`，以 `segments[].id` 为 join 键，与初始包/账本逐段比对；`fl2v` 另比 `shots[].prompt`。`group.json` 只在 `timeline.json` 该段词为空时才被插件采用，不作比对源。不同则 append `rewrite` 行（`prompt_before` 取初始包、`prompt_after` 取最终包，`feedback` 写「导演台 UI 内修改」）。**不比对帧数**：最终包的 `frameCount` 可能被 UI 归一化改过，不代表用户手改。
- 最终包缺失/损坏/段数不一致 → `ValueError`，不静默跳过。

### 3.10 源视频与 mixed（`director/source.py` / `director/mixed.py`，票 #109 / #110）

- v2v/rv2v：段边界**取自源视频时间轴**，不由叙事规划决定；编辑型方言 = 改动项（Modifications）+ 保留项声明（Preservations）；`rv2v` 强制保留项声明、屏幕左右视角、禁括号。走同一套 pack / companion，不新增平行流程。跳过某段（源片段缺失）→ 明确报错。
- mixed：每段 `taskType` 合法值只有 `t2v/i2v/fl2v/r2v`；段类型（叙事类型）与任务模式是两套坐标，逐段判定引导与给图清单并展示；`fl2v` 段用 `startImage`/`endImage`。

## 7. 已知边界与待实测

- ~~`exportMode="all"` 下全部命中缓存时插件是否真的不再采样~~：**已源码确认不成立**——选中的段无条件重采样（`executor_core.py:1691-1724`），全片模式只影响导出与未选中段的填充。陪跑必须用 `runSelection` 只勾当前段。

- 切镜段关闭引导后接缝有 1 帧重复（插件不裁）：接受并记账，不在项目侧重编码。
- 插件缺上一段缓存时静默硬切：项目侧靠可证层帧形态反向发现，无法事前保证。
- 段缓存指纹不含父段身份：级联必须删下游缓存，不能只作废账行。
- `PACK_VERSION` 现在是 1；镜像校验要注释标明「依插件版本」，插件升级时重核。
