## 1. 给图契约：四条分支 + 一个谓词

唯一判据是 `director/frames.give_images_for(segment_type, mode)`（`frames.py:194`）。
任何「这一段要不要图、要哪张」的出口都从它派生，不在调用点写段类型名。

| 段类型 | fl2v 给图 | r2v | 说明 |
|---|---|---|---|
| `opening` | 首帧 | 参考素材 | 全片开场；关引导 |
| `continue` | **无** | 参考素材 | 起点正好是上一段终点，靠段间引导连上 |
| `camera_same` | 尾帧 | 参考素材 | 起点是上一段终点，有运镜，落到指定终点画面 |
| `camera_cut` | 首帧＋尾帧 | 参考素材 | 起点在别处，硬切新场景，关引导 |
| `ending` | 尾帧 | 参考素材 | 收尾定格 |

- **r2v 每一段只给参考素材**（`frames.py:212-215`）：首/尾帧是 fl2v 的槽位，r2v 没有；
  段类型只决定起点与是否引导，不决定给图。张数由段内素材表决定（≤ `MAX_PICTURES`＝9）。
- **可选图**走 `optional_images_for(..., single_segment=, film_end=)`（`frames.py:247`）：
  只有 **fl2v 开场**的尾帧可选，且仅在**单段**片子且盘上真有 `film-end` 时成立；
  多段开场的全片尾帧属于最后一段，不在本段。
- **首帧槽谓词** `needs_first_frame_image(segment_type, mode)`（`frames.py:236`）＝
  `IMAGE_FIRST in give_images_for(...)`。首帧词生产（`ui/wizard.py:1089`）与切镜简报
  共用它：fl2v 的 `camera_cut` 为真，r2v 全部为假。照类型名写 `camera_cut` 会让 r2v
  产出一份没有槽位可挂的首帧词、简报还会让用户去挂一张不存在的图。

## 2. 写段：给图分支 +【本段起点】

`prompts/segment_writer_director.md` 的 fl2v 小节按请求里的 `【本段给图】` 走
**四条分支**：首＋尾 / 仅首 / 仅尾 / 无图。段类型只决定给哪几张图，**不能替代请求里的
事实施**——`continue` 段不会被写成「从一张不存在的首帧开始」。

`【本段起点】` 事实块由 `director/prompts.py:428` 的 `_fl2v_start_block` 组装（仅 fl2v）：

| 段 | 起点块 |
|---|---|
| `opening` | 全片开场：本段第一帧就是全片第一帧，没有上一段可承接 |
| `camera_cut` | 切镜：第一帧来自**本段首帧图**，是**硬切**的新场景，**不承接**上一段的画面、构图与人物位置 |
| `continue` / `camera_same` / `ending` | 上一段落定画面（`previous.end_hook`），本段第一拍从这里接着写、本段没有首帧图 |

起点块与【本段给图】都进同一个请求（`build_segment_request`，`prompts.py:455` 起）；
r2v 不产起点块（它的起点由参考素材与请求开头的模式说明决定）。

## 3. 尾帧变换词：参考图按段型分流

`director/tailframe.py:226` 的 `build_tailframe_request` 与 `ui/wizard.py:1088` 起的取图分支：

- **引导段**（`continue`/`camera_same`/`ending`；实际触发尾帧词的是后两种）：参考图优先
  **上一段终点图**（段账里的 `end_image`），账里没有才回退上一段视频末帧。
- **切镜段**（`camera_cut`）：参考图＝**本段首帧**。轮到它时向导先问首帧路径——**必填**，
  空输入讲清后果后重问，`q` 干净停下（`_HandoffStopped`，返回码与贴视频的停下一致）；
  不再「回车＝没有、改用上一段终点图兜底」——切镜段的起点恰恰不在这里。
- 请求里显式写**本次按哪一档出词**（`_model_line`，`tailframe.py:204` 起）与
  **本段是硬切段还是引导段**（`_segment_kind_line`）：不说，模型会按角色提示词里举过的
  另一档写法出词、把切镜段写成同景软过渡。终端打印档名。
- **`ending` 的全片尾帧优先**（`ui/wizard.py:1049` 起）：盘上有 `director/assets/film-end.*`
  就直接用它、**不产尾帧词**、不花那次模型调用；盘上的旧词明确打一句「不采用」。

### 3.1 静态分支与位移词表

`is_static_segment`（`tailframe.py:443`）判「视频词里读不出运镜」且「`end_hook` 是姿态/
状态变化」；命中时请求改问**可见状态变化 + 一个具名关系**，校验器不再要求 A→B 位移。
段词缺失按**在动**处理（宁可要求位移，不静默降级）。

位移闸 `_DISPLACEMENT_TO`（`tailframe.py:401`）收「具名地标 + 可见关系」，并接受
`blocked by` / 「被…挡住」——那是 L4-07 允许的合法措辞，旧闸把它判死会触发无谓重写。

## 4. 图像模型：统一键位、三档工作流与画布

键位统一为 **`z_image`**（`image_config.IMAGE_MODEL_KEYS`，`image_config.py:56`）；
旧 `zimage` 只在**读入**时归一（`canonical_image_model`，`:64`），覆盖配置、brief 画布键
与旧 bundle。新写一律 `z_image`。

`generation.IMAGE_PROFILE_DEFAULTS`（`generation.py:86-89`）：

| 键 | 工作流 | 节点 | 默认画布 | 纪律文件 |
|---|---|---|---|---|
| `z_image` | `zimage_t2i_v1` | 10 | 640×1280 | `z_image.md` / `z_image_edit.md` |
| `qwen` | `Qwen-image2.1+空间折叠流之万法编辑` | 605 | 1920×1088 | `qwen.md` / `qwen_edit.md` |
| `moss` | `【WorkFisher】全能生图王 _ 适配所有类型` | 29 | 1920×1088 | `moss.md` / `moss_edit.md` |

接线口径：

- **资产请求的【画布】只列当前模型那一行**（`graph/nodes.py:603` 的 `_canvas_block`）；
  三档各自的工作流与画布不同，把别的档也摆出来会让模型挑错行安排构图。
- **产物/终端/注入卡同一档**：`generation.image_prompt_variants`（`generation.py:1024`）
  从条目的 `image_model` 取该条自己的 profile/节点/画布；旧条目没有这个字段时按
  Z-Image 读（那时只有这一档）。
- 关键帧请求同样只列本档【画布】（`_frame_canvas_line`，`nodes.py:650`），与资产图共用
  同一个渲染函数——两份渲染是「同一契约两处口径」的温床。

## 5. 语言按出图档，不再跟随对白语言

图像提示词请求**不再**带 `语言=brief.language`（旧实现把默认 `Chinese` 传给生图模型，
模型把它读成「正文用中文」，压过 Qwen/MOSS 的英文纪律）。口径：

| 用途 | Qwen | Z-Image | MOSS |
|---|---|---|---|
| 关键帧文生图（`<档>.md`） | 英文长文 | 中文短句 | 英文 |
| 尾帧图生图（`<档>_edit.md`） | 中文（指令语言） | 中文短句 | 英文 |

- 关键帧角色提示词的三处正文语言条款改成「按【出图模型】／【生图纪律】块」，
  保留旧 `:135`（现 `:136`）的按档规则。
- 共用生图真源 `film-language-image.md` 的中文假设改成按档语言；首尾帧自检那条标明
  单帧段不适用。
- `qwen.md` 的走帧顺序、`moss.md` 的文字条数与长度限定在**资产图**；关键帧按角色提示词
  的八步骨架，不被资产纪律压掉。
- 检查器「Z-Image 五类」钉在 `Z_IMAGE_MODEL` 常量（`image_config.py:93`），不钉「默认档」
  ——用户把默认档换成 Qwen 时，那五类判据不能跟着搬过去。

## 6. 人物参考板：一张综合板

（2026-11-03，spec #144 F 段）

- 主要人物默认 **1 张综合板**：3 全身（正面／侧面／背面）＋3 脸（正面／左 3/4／右 3/4）
  ＋3 表情（平静／微笑／认真）。删掉色卡、固定要点、细节矩阵、皮肤／发丝／手部特写。
- 配角默认 1 张、允许 2 张；道具 1–2 张；场景每个地点 1 张。
- **板数照设计端的母版清单、板内视图去冗余**：清单列了几张就出几项，写词端不得自行
  增删整张板；去冗余只删同一张板里角度／妆造重复的视图。
- 三张母版方案（身份 3 视图／表情 4 栏／服装 1 张）只存记忆
  `character-board-three-master-backup`，**不接代码**。

## 7. r2v：规划口径与 Subject / Picture

- 规划请求的 r2v mode scope（`director/planning.py:284` 起）明写：「本模式每段都只给
  参考素材（≤9 张），没有首帧/尾帧槽；段类型只决定起点与是否引导」。
- 规划师的给图表标注为 **fl2v 口径**（`segment_planner_director.md:21`、`:29`）：
  r2v 以请求开头的模式说明为准。
- `reference_consistency` 的定义句改为「中文素材，下游转英文」——它不是最终提示词，
  不会逐字进入（`reference_consistency.md:21`）。
- 写段指称：可复用的可见内容（人物／场景／道具／风格）用 `<Subject N>`；只有「这张图
  本身是某一帧／独立图」时才用 `<Picture N>`（`segment_writer_director.md:24`）。
- 母版张数与板内去冗余有优先级（见 §6）；配角在设计与写词两端都是 1–2。

## 8. 按需词 provenance：sidecar

`firstframe-NN.md` / `tailframe-NN.md` 各自有同名 `.meta.json`（`director/frame_meta.py`）：

| 字段 | firstframe | tailframe |
|---|---|---|
| `kind` / `segment` / `model` | ✓ | ✓ |
| `segment_prompt_sha256` | ✓ | ✓ |
| `start_image_sha256` | `null`（文生图，没有起点图） | ✓（本段起点图） |
| `composition` / `lighting` / `negative_prompt` | ✓ | —（尾帧的三段式文档里带锁死清单） |

`composition` / `lighting` / `negative_prompt` 与 provenance **不进可复制正文**
（`frame_meta.py` 的模块说明）。续跑时向导比对 sidecar 的 `model` 与当前
`config/image.yaml` 的 `frame:`：不一致先警告、再问「重写…？」，**默认 N**——旧词可能
已经拿去生过图，重写会让挂上去的那张图与文件里的词错开。旧产物没有 sidecar 时不凭空报警。

## 9. 切镜首帧词

`director/firstframe.py:79 build_firstframe_request` 补齐八项设计上下文（分场剧本、人物/
道具/背景设计、美术统筹、镜头评审锁定、画面细化、身份一致性锁定、语言）；`end_hook`
在请求里标成「本段终点，不要画成首帧」。角色提示词的「段首帧」变体
（`frame_prompt_engineer.md:21`）规定：只出 `first`、不是整片 0.00s、不与尾帧共享
`scene_anchor`。

## 11. 未验证项

1. **实机模型与 ComfyUI 端到端仍未跑**：三档工作流的节点号与画布来自用户给定值，未在
   ComfyUI 里逐个导入验证；插件执行分支（`ref_images.py` 的 9 图上限、段间引导清空
   `first_frame`）只按调研与既有实跑记录引用。
2. **写段指令的四条分支在真实模型上按哪一条落笔**：请求侧事实已齐（【本段给图】与
   【本段起点】），但「模型是否照请求而不是照段类型名写」需要一次带记录桩的实跑。
3. **静态 `ending` 是否在真实静态画面上撞校验**：此前样本都是运动镜头；静态分支的
   判据（无运镜 + 状态变化）只在合成用例上跑过。
4. **Qwen/MOSS 关键帧的实际出图质量**：语言与纪律已按档接线，但生成质量未做 A/B。
