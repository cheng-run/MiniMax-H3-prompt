# 用户修订累积与分层重跑（首帧环节的意见不再丢失）

日期：2026-09-25　状态：待评审（尚未开票，issue 由 `/to-tickets` 生成）

## Problem Statement

用户在阶段 1 展示首帧生图提示词后提出修改意见，**第二轮意见会顶掉第一轮**：实测同一主题连提两次意见，第二轮产物含「中国古代秋日庭院」「几片秋日枫叶落在青石与水缸边，院中或墙侧有红枫与树影」，第三轮产物里**秋日 / 枫叶 / 红枫 一个都没有**——改动整体消失，用户必须把说过的话重说一遍。

更严重的是**这个环节的意见在结构上无处落地**。阶段 1 的人物设计、背景、道具、美术统筹、分镜、镜头评审、身份锁定、画面细化**全部在首帧提示词节点之前定稿**，而重出只跑首帧提示词一个节点。用户提「汉服太朴素了，可以参考现代的汉服，颜值高」——这是**人物设计级**的要求——但它在架构上没有任何落点，最终只有首帧图变好看了。用户的原话是：「那我在生图提示词提的意见不就是一个形式主义吗」。

而在**长视频（本项目的主用途）**上更彻底：分段写段请求与分段规划**都拿不到用户意见**（写段请求收了一个从未被引用的 brief 参数，分段规划函数根本没有这个参数），意见**进不了任何一段**。

## Solution

用户侧的形态：

- 提意见时**指明这条属于哪一层**：只改画面 / 人物设定 / 美术场景道具 / 剧情分镜。系统据此决定动不动后面的设定，并重跑对应的下游。
- 意见**按轮累积**；随时能看到清单（带编号），能**删掉任意一条**（不只是最后一条——被后来意见覆盖的旧意见也常需要撤）。
- 选「只改画面」时的代价与今天完全一样（只重出首帧提示词）；选设定级才会重跑下游，且**重跑前先告知将替换哪些已经看过的产物**，用户确认才跑。
- 已落地的设定级意见在清单里标为**已落地**，不会每一轮又被当成新要求重复叠加。
- **长视频的每一段**都带上累积的修订；首帧图仍然是最高事实源（图 > 修订 > 分镜表）。
- 起步时可先回答几个**澄清问题**把模糊需求钉具体，**可一键跳过**，轮数上限可配置。
- 每轮重出留**台账**，事后能看出哪一轮带了什么、是否用了上一版作基线。
- 崩溃/重启续接后意见还在；「整个流程重来」会清空意见并**明确告知**。

## User Stories

1. 作为提意见的用户，我想让每条意见都被记住，这样第二次提意见时第一次的改动不会消失。
2. 作为提意见的用户，我想在提意见时指明这条属于哪一层（只改画面／人物设定／美术场景道具／剧情分镜），这样系统知道该动哪一步。
3. 作为提意见的用户，我想看到当前累积的意见清单（带编号），这样我知道自己说过什么。
4. 作为提意见的用户，我想删掉清单里**任意一条**（不只是最后一条），这样被后来意见覆盖的旧意见不会一直挂在那里。
5. 作为提意见的用户，我想在选「只改画面」时只重出首帧提示词，这样代价最小、不必等重跑。
6. 作为提意见的用户，我想在选「人物设定」时系统改人物设计并重跑其下游，这样「汉服改成现代审美」真的体现在整条视频里而不只是首帧。
7. 作为提意见的用户，我想在重跑前被告知「将重跑哪几步、哪些已看过的产物会被替换」，这样我能决定值不值得。
8. 作为提意见的用户，我想让已落地的设定级意见标为「已落地」，这样它不会每轮又被当成新要求重复叠加。
9. 作为提意见的用户，我想让画面级意见在下一轮重出时仍被带进上下文，这样它不会因为我又提了别的而消失。
10. 作为提意见的用户，我想让新一轮重出以**上一轮产出的提示词为基线**，这样我没提过的部分不会无端漂移。
11. 作为提意见的用户，我想让我的意见在冲突时**优先于**上一版基线。
12. 作为长视频作者，我想让我提过的修订出现在**每一段的写段请求**里，这样逐段执行时不会丢掉开场就定下的要求。
13. 作为长视频作者，我想让**分段规划**也看到我的修订，这样段边界与每段剧情概述不会与我的要求矛盾。
14. 作为长视频作者，我想让首帧图仍是最高事实源（图 > 修订 > 分镜表），这样成片不会与我自己提交的图自相矛盾。
15. 作为长视频作者，我想在写段前把「累积修订」与「首帧读图结果」**并排看一次**，这样图与修订冲突时我能自己发现。
16. 作为用户，我想在起步时被问几个澄清问题把模糊需求钉具体，这样后面少返工。
17. 作为用户，我想**一键跳过**这些澄清问题，这样主题已经想清楚时不被审问。
18. 作为用户，我想让澄清轮数上限可配置（默认 3），这样问多少由我定。
19. 作为用户，我想在续接（崩溃/重启后重跑）时我的意见还在，这样我不用重说一遍。
20. 作为用户，我想在**续接路径上也能提修改意见**（今天这条路径根本没有这个循环）。
21. 作为用户，我想在选「整个流程重来」时**被告知累积意见会被清空**，这样我不会误以为意见是全局财产。
22. 作为用户，我想每轮重出留下台账（轮次、本轮意见、累积全量、该轮产物、是否用了基线），这样事后能看出哪一轮生效了什么。
23. 作为用户，我想屏幕上标明「第 N 轮 · 累积 M 条」，这样我知道自己在第几轮。
24. 作为用户，我想在最终交付时看到「本片累积的修订」供核对。
25. 作为提意见的用户，我想在提了设定级意见但**没有重出图**时，不被系统静默地按图覆盖掉我的要求而毫不知情。
26. 作为维护者，我想让每一个新增字段与新增入参都有**确定的读者**，这样不会再出现「写了没人读」的死接线。
27. 作为维护者，我想让主题字段恢复成只装主题，这样地点守卫与常识判官不会被意见文本污染。
28. 作为维护者，我想让「人的意见累积」「机器的质检问题替换」这两套语义各自有名字，这样不会有后人把其中一边改成另一边的语义。

## Implementation Decisions

**1. 新增累积真源，与主题字段分家**

`state["user_revisions"]`：按轮累积的修订清单，每条含 `{round, layer, text, applied}`，`layer` 取四档之一。它是**唯一**的意见真源，并必须进入会话持久化白名单（否则崩一次即丢——本仓库这一族缺陷已有专测）。

`brief.plot` 恢复为**纯主题**，意见不再经它传递。理由：`plot` 同时喂给主题地点守卫（**按子串**提取地点硬约束）与生图常识判官（「不得新增主题中不存在的主体、地点或道具」的判据），把散文意见塞进去等于让意见文字随机改写两条闸门的判据；且有否定句反噬——用户说「不要森林，改到庭院」会让守卫**反而开始要求**正文出现「森林」。

**2. 层次＝重跑起点，四层一一对应阶段 1 链上的节点**

| 层次 | 回灌产物 | 重跑起点 | 连带重跑 |
|---|---|---|---|
| ①只改画面 | （不回灌） | 首帧提示词节点 | 无 |
| ②人物设定 | 人物设计 | 设计节点组 | 美术统筹 → 分镜 → 镜头评审‖身份评审 → 摄影‖参考一致 → 首帧提示词 |
| ③美术/场景/道具 | 背景设计／道具设计 | 设计节点组 | 同上 |
| ④剧情/分镜 | 剧本／分镜表 | 编剧 或 分镜 | 相应下游直到首帧提示词 |

层次直接等于重跑起点，**不另造一套映射**（否则「重跑哪一段」要再判一次）。重跑**复用既有的 `run_stage1(resume_from_node=...)` 截断链机制**（续接路径已在用），不新建机器。①与今天的行为等价，是代价最短的路径。

**3. 首帧重出的修订基线**

首帧节点以**上一轮的完整 frame bundle**（首/尾帧、scene_anchor、continuity_constraints）为修订基线，而不是只喂正文文本——scene_anchor 与 continuity_constraints 正是那几条 mismatch 闸门校验的字段，只喂正文会让基线在被校验的字段上失锚。

基线经**独立的 opt-in 状态键**传入；阶段 1 的自动质检循环**不设**该键，于是它的「替换」语义逐字不变。

**4. 两条重出循环的语义分叉，各自命名**

- **用户修订**：人提出的，**按轮累积**，说了就不忘，可回收（按编号删）。
- **质检问题**：系统自动判出的 error，**每轮重算**，问题消失即失效（替换）。

自动质检循环保持替换语义不改：它每轮对**当前产物**重新审一遍，问题消失就该消失；而人提的意见是一次性说出口的断言，不该被后来的一轮静默作废。两者语义不同，正是它们该有两个名字的理由。

**5. 分段侧：修断链，并把死参数删掉而不是给它找用途**

- **写段请求**：累积修订**从 state 读**（该请求本来就在读 state 取关键帧锚定），同时**删掉那个从未被引用的 `brief` 参数**。
- **分段规划**：该函数**不依赖 state**，沿用关键帧上下文 `frame_context` 的既有模式，新增一个显式的修订块入参。
- 修订块的措辞需声明优先序：**首帧读图结果 > 用户修订 > 分镜表**。

**6. 注入优先序与冲突处理**

图优先的理由沿用既有教条：图是用户提交的**产物**，分镜表是**计划**，成片必须与图连续。但「提了修订却没重出图」这种冲突**不做自动判定**（语义对比不可证），改为**在写段前把「累积修订」与「首帧读图结果」并排展示一次**，由人自行发现。

**7. 每轮台账**

新增追加式 jsonl 台账，一行一轮：`round` / `layer` / `feedback_this_round` / `active_revisions`（**当轮活动清单的全量快照**）/ `bundle`（该轮产物）/ `base_used`（是否用了上一版作基线）。

`active_revisions` 取**快照**而非增量，于是「某条意见在第 N 轮被撤掉」这件事仍可 diff 出来，撤销本身不必单开一列。`base_used` 是日后判定「累积到底生效没有」的分组变量，缺它无法把「上了基线」与「没上基线」的轮次分开看。

**8. 已落地标记与重复注入**

设定级修订重跑**成功后**标 `applied`；此后不再作为注记注入（否则会与已经改好的设定产物叠加，越滚越重）。重跑失败或用户中断时**不标**。

**9. 重跑前的确认门**

重跑会**替换用户已经看过的产物**（分镜表、画面细化、首帧提示词都被重写），且 LLM 生成**不可复现同一版本**——这是不可逆动作，故先展示「将重跑 N 个节点、下列产物会被替换」，确认后再跑。

**10. 前置澄清**

在起步处提问，**总是问**（不做「主题模糊才问」那种不可证判据），但**一句话即可跳过**；轮数上限进配置（与既有 QA 轮数上限并列），默认 3。

**11. 续接与重来**

续接路径补上**同一个**修改循环（今天它只展示提示词、不提供修改入口）。「整个流程重来」**清空** `user_revisions`，且提问文案必须**明说会清空**。

**12. 术语（写入 `CONTEXT.md`）**

- **用户修订（user revision）**：用户在阶段 1 后提出的修改要求，**按轮累积**，分为**画面级修订**与**设定级修订**两档；画面级只改首帧画面，设定级回灌对应产物并重跑下游。
- **质检问题（frame_prompt_issues）**：系统自动判出的 error 级问题，**每轮重算、随当前状态失效**。
- _Avoid_：把两者当成同一件事（会诱导把其中一边改成另一边的语义）。

**13. 防死接线的验收口径**

每个新增字段/入参，必须有一条断言它在**产出物里可见**的测试（请求文本、落盘状态、或展示块）。本次排查出的五处根因里有两处是「写了没人读」形态，该口径针对它。

## Testing Decisions

**好测试的定义**：只断言**外部行为**——注入给 agent 的请求文本、落盘的产物、用户可见的证据块；不断言内部函数调用顺序或私有结构。

**缝一（主缝，既有）：阶段 1 的修改循环。** 脚本化交互输入 + 假 agent（记录收到的消息文本），断言只落在外部产物：会话状态文件里的修订清单、台账 jsonl、屏幕证据块。这条缝一次覆盖累积／按编号删／层次标注／已落地标记／轮次展示／重跑确认门／续接循环／重来清空，以及「首帧节点到底吃到了什么」。先例：锚帧语义闸门那套（脚本化 `_prompt`/`_confirm` + 日志读回助手 + `capsys`）。

**缝二（既有，纯函数）：分段两处请求文本。** 这两个函数的**返回字符串就是它们的契约**，也正是缺陷发生处（死参数即在此）。断言修订块与优先序声明真的出现在请求里。先例：桥接帧锚点测试（纯函数 + 真实产物裁剪 fixture）、分段规划测试。

**缝三（既有）：阶段 1 链截断。** 断言设定级修订确实从正确的节点起跑到链尾。先例：阶段 1 续接测试。

**白名单往返**：新增累积真源必须能被 save/load 往返。先例：会话存储白名单测试——该族缺陷已有专测，直接扩展它。

**回归**：全量回归不得低于当前基线（动手前跑一次确认具体数字，基线易变）。

**缝的数量**：三个，**全部已存在，零新增**。

## Out of Scope

- **不做自动化**（项目既有裁定：质量未达标前不做自动化）。
- 不改自动质检循环的替换语义。
- 不做「按主题自动裁决互相矛盾的意见」（需要不可证的语义判断）。
- 不做「修订与首帧图」的自动冲突判定（同上）；只并排展示交人判。
- 不改「首帧图是最高事实源」的地位。
- 不新增测试缝。
- 不碰采样步数、闪动量尺、LoRA 版本等无关议题。
- 不重写阶段 2 的正文组装与分段写段模板本身（只增加一个修订块入参）。

## Further Notes

**根因五处（均有可复现证据）**

1. 意见只进 `plot`，无独立通道，且污染主题校验。
2. 重出只跑首帧一个节点，设计层全在它之前定稿 → 设定级意见无落点。
3. 长视频分段：写段请求的死参数 + 分段规划函数缺该入参 → 意见进不了任何一段。
4. 意见不累积：第 N 轮用**循环外**的原始 brief 重建，前 N−1 条整体丢弃。
5. `frame_feedback` 字段**写了从没人读**，且不在持久化白名单。

**建议的落地分片**

- **第一片**（本身就是完整修复，可立刻用于下一个 GEN）：修订真源与字段分家（决策 1）／层次四档（决策 2 的枚举）／按编号删与清单展示／累积注入首帧节点与分段两处（决策 5）／基线（决策 3）／台账（决策 7）／续接与重来（决策 11）／白名单（决策 1）。
- **第二片**（体验升级，风险独立）：设定级重跑与确认门（决策 2 的重跑、决策 8、决策 9）／前置澄清（决策 10）／已落地标记的注入抑制。

**配套文档**：`docs/adr/0005-*.md` 记录「人的意见累积、机器的质检问题替换」这一语义分叉（难逆转／无上下文会困惑／有真实备选，三条均满足）；`CONTEXT.md` 补决策 12 的两个词条。
