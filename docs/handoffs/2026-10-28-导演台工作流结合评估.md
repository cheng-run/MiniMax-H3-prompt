## 四、导演台的真实优势（用户问过的）

**唯一结构性优势：音轨跟着视频一起在 latent 层连续。**

`nodes/h3_continuity/core.py:230 append_tail` 把 `NestedTensor((video, audio))` 两个流按各自 token 重叠合并；默认 22 帧（0.917s）隐藏上下文，采样后被丢弃。

本项目对照：
- 每段音频独立生成，[`segment_prompts.py:484`](../../src/minimax_h3_prompt/segment_prompts.py#L484) 明写 soundscape **为本段重写**
- 成片用 ffmpeg concat **硬接**，[`tools/seam_audit.py:177-179`](../../src/minimax_h3_prompt/tools/seam_audit.py#L177-L179)，`-c copy` 或 `-c:a aac`
- **项目侧对音频接缝零校验**：`preflight.py` 只查帧数/尺寸；`final_film.py` 只查「各段有没有音轨」

**已实测的量化证据**（成片 `output/sessions/一个二次元游戏的CG动画-adc4c797/GEN001/final.mp4`，5 段，源自 `segments/segment-ledger.jsonl` 的 `event=output` 行）：

| 段 | 时长(s) | 整段 RMS |
|---|---|---|
| 1 | 4.448 | 0.00810 |
| 2 | 6.560 | 0.06805 |
| 3 | 6.560 | 0.03843 |
| 4 | 6.560 | **0.00065** |
| 5 | 8.000 | 0.01393 |

段间 RMS 极差约 **105 倍**（段 4 近乎静音 0.00065 vs 段 2 的 0.06805）。这说明各段音频是**独立生成**的，响度彼此无关，拼起来在接缝处会有突跳——这正是「音画不连续」在数据上的样子。注意：这只证明「响度不连续」，尚未量「接缝处的瞬时跳变」（单期短时能量差分），后者更贴近听感。复现命令见本文件第七节环境说明。

**注意口径**：RMS 差异本身不构成「接缝必然难听」的证明——响度变化也可以来自剧情（安静场景 vs 动作场景）。要证它对听感有害，需量**接缝两侧各 100–200ms 的瞬时能量跳变**，与段内自然起伏作对照。本会话被打断在此处，下一步做这个对照。

其余优势属便利性：只解码新增段、可从任意普通视频续、重掷锁 parent 不静默推进、`Join clips` 自带 H3 转场、显存友好。

它**换不来**的：整片规划、`end_hook`、时间轴对齐、校验器、闸门、段产出账、换中间段（checkpoint 依赖整条父链）。

## 五、为什么「复制提示词进导演台」不够（用户最新提问，已答复）

导演台有**两种模式**，只有一种能吃项目提示词：

- **新建模式**（`duration: 4`）→ ✅ 原样可用，帧数也对得上
- **连续性模式**（用户那份工作流配的就是这个）→ ❌ 三处互斥

**（1）它会改写提示词结构**。按 `compose_ref_fields`（`core.py:127-154`）实际重放，`detailed_description` 变成：

```
This is a continuation window. Its opening 0.917 seconds are hidden overlapping
context from the end of the preceding shot. Weld to that tail at the seam...
The following 4.958 seconds are the new visible continuation.

Continue the same uninterrupted shot. Preserve the subjects identity...

Segment 1 of 5, covering 0s-4s of the full 30s video. This segment begins with...
```

原文里的 `Segment 1 of 5` 与 `30s video` **原样保留但不成立**——连续性模式里既没有「第 1 段」也没有「30 秒总长」。

**（2）时间戳整体错位**。项目规定时间戳相对本段起点（`CONTEXT.md` **细粒度时间戳**节）。实测 `output/sessions/一个抖音女网红的旅游vlog-b6e2ab21/GEN001/segments/shot-01.md` 节拍为 `00:00.000 / 00:01.500 / 00:02.500 …` 至 6.5s。连续性窗口结构是：

```
[0.000 – 0.917)  隐藏重叠（丢弃，不进成片）
[0.917 – 5.875)  新增可见段
```

→ `At 00:00.000` 那拍落在**会被丢弃的重叠区**；后续所有拍点前移 0.917 秒。

**（3）段边界不再由项目决定**。项目 `plan.json` 写死 `0-4 / 4-10 / 10-16 / 16-22 / 22-30`，每段带 `end_hook`；导演台连续性只认「接下来发生什么」，只保证**接得顺**，不保证**接在对的地方**。

**（4）买不到音画连续那一条**——那是 `append_tail` 在采样层做的，与提示词内容无关。

补充事实：项目多参/首尾帧的段规划**每段恰好一个 Shot**（`plan.json: shots=[1]` 逐段递增），所以「单段单镜头」这条与导演台不冲突；真冲突的只有绝对时间定位与段序声明。

- 跑 ComfyUI 侧代码必须用打包解释器，且要把 ComfyUI 根目录塞进 `sys.path`：
  ```bash
  cd /d/Comfyui/ComfyUI && /d/Comfyui/python_embeded/python.exe -c "
  import sys; sys.path.insert(0,'D:/Comfyui/ComfyUI')
  sys.path.insert(0,'D:/Comfyui/ComfyUI/custom_nodes/ComfyUI-DaSiWa-Nodes')
  sys.stdout.reconfigure(encoding='utf-8')  # 不设会出 GBK 乱码
  "
  ```
  系统 `python` 没有 torch/comfy，直接 `import` 会 `ModuleNotFoundError`。
- 查询节点当前契约（ComfyUI 正在运行，端口 8188）：
  `curl -s http://127.0.0.1:8188/object_info/MiniMaxH3Director`
- `rg` 全盘扫 `D:\` 会超时（>20s）。改用逐目录 `grep -rl` 循环，或用 Grep 工具限定到 `custom_nodes` 子路径。
- 段规划文件形态**不统一**：多参的 `GEN001/segments/plan.json` 是 **JSON 数组**（不是带 `segments` 键的 dict）；另有路线的是 dict。读之前先判类型。
- `ComfyUI-DaSiWa-Nodes` 的 `nodes/` 是**命名空间包**（无 `__init__.py`），以 `sys.path` 方式 import 会报 `'nodes' is not a package`；直接读源码复刻逻辑更快。
