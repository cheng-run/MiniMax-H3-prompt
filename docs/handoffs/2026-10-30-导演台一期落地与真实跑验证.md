已验过的只有「包能被插件导入」——用插件自己的 `extract_pack_zip` + `import_extracted_pack` 跑过 i2v 与 r2v 两条，`missing: []`、媒体落 `input/minimax_director_packs/<id>/` 且路径被改写。其余全是源码推导 + `tmp_path` 模拟。按顺序核这四项：

### 1. 段缓存目录名与实际帧数（#105）
- **看**：`D:/Comfyui/ComfyUI/output/minimax_seg_cache/<缓存名>_<节点id>/` 是否真的长这样（本机此前**没有**这个目录，从没跑过真实段）。
- **判据代码**：`director/cache.py` 的 `resolve_cache_key` / `cache_dir` / `actual_frames`；容差 `director/companion.py` 的 `DIRECTOR_FRAME_TOLERANCE`。
- **最可能出问题**：缓存名归一（`normalize_cache_name` 与插件逐字符镜像过，但你输入的缓存名里若有特殊字符要核）；`CAP_PROP_FRAME_COUNT` 在真实 FFV1 mkv 上的读数。

### 2. `cache_frames_codec` 必须切 ffv1（#105 硬前提）
- 插件默认 `raw` → 磁盘是 `seg_XXXX.pt`，本项目**没有 torch**，读不了。
- 现在的行为：陪跑会打「把 cache_frames_codec 切成 ffv1 后重跑该段」并继续重问（这一条是复审后修的——修之前用户只会看到「这一段还没跑」）。
- **要核**：切成 ffv1 后该段确实写出 `seg_XXXX.frames.mkv`，且陪跑数出的帧数与判据相符。

### 3. 相位对齐会不会裁尾（ADR 0025 的核心假设）
- 设计推导：声明帧都在 `17k+5` 网格上 → 有引导段 gap 恒 0、无引导段（也在网格上）恒 0，即**一帧都不裁**。
- 若真实运行出现「实际比计划少几帧」，看 `director/companion.py` 的 `judge_segment`：`≤5` 帧判告警放行、超出判红。**实测值要回写**（容差 5 是拍的，`config/agent.yaml` 的 `director.frame_tolerance` 是旋钮）。

### 4. 最终包比对（#108）
- **看**：导演台导出的最终包里 `timeline.json` → `segments[].id` 是否与初始包一致（UI 若重建段会换 id）。
- **判据代码**：`director/delivery.py` 的 `compare_prompts` / `_prompt_by_id`（join 键＝id，重复 id 报错）。
- 若 id 集合对不上，会**明确报错**（不会静默记错行）——那时要看是 UI 行为还是我们打包时 id 取法要改。
