# 官方规范 references（给人读的官方原文）

这两份是 MiniMax 官方 H3 提示词规范的**逐字原文**，vendor 进仓库供人查阅与核对：

- `base-en.txt` —— base 模式（T2VA / I2VA / FL2VA / L2VA）的字段、结构与句法；
- `ref-en.txt` —— ref 模式（参考图 / 视频 / 音频）的六段式结构与 retention 标记。

## 定位（ADR 0008）

**它们是给人读的参考与对照物，不是运行时的输入。** 流水线一条请求都不会读这两份文件——
加载链上没有模板引擎、也没有解析链（官方原文是散文，靠位置去解析既脆又会让 `h3_validator`
的 import 期崩给全程序看）。**格式问题一律以这里为唯一依据**，但那是**对人**说的：
读它、照着它核对产出。

要逐字符照抄的官方原文，在**代码里**的唯一可写来源是 `tools/h3_validator.py` 的常量
（「唯一」指的是**出站文本的来源**：正样本 fixture 与各条用例里内联的同句是**样本**、
CONTEXT / ADR / playbook 里的是引文，它们不是来源）：

| 常量 | 内容 | 谁用 |
|---|---|---|
| `EDGE_STABILITY_SENTENCE` | 镜头块收尾句 | 校验器、两条写段模板（插值）、角色提示词（由加载处注入） |
| `ALIGN_TEMPLATES` | 帧变体首行对齐指令（I2VA / FL2VA / L2VA） | 同上 |
| `BASE_SECTIONS` / `REF_SECTIONS` / `RETENTION_MARKERS` | 字段名与 retention 标记 | 校验器 |

`tests/test_official_references.py` 读这两份文件，把每个常量**逐字钉回**官方原文，并反向钉住
「被判自创结构的标记在官方原文里确实找不到」。于是：

- 改常量而不同步官方文件 → 报红；
- **重新 vendor 官方文件**而不同步常量 → 报红（这是有意的：官方措辞一变，进模型请求的文本
  就跟着变，值得一次人工确认，而不是悄悄跟着漂）。

## 维护

**不要改这两份文件的正文**——它们是官方原文，改了就失去核对价值。上游更新时整份替换，
再按守卫测试的报红逐条核对常量。
